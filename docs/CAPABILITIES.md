# What works where (v1 capability matrix)

PLATFORM-003: known gaps are documented here and explained in the app wherever you run into them. When a command is
unavailable for a location, FileCat's status line says why (for example, "Items can be pasted only into a file-system folder").

## Platforms

| Platform | Tier | Notes |
|---|---|---|
| Windows 11 x64 (serviced releases) | **A: release-blocking.** Correctness, UX, performance, accessibility, and packaging are tested. | Native copy, move, and delete (CopyFile2/MoveFileEx); verified Recycle Bin with restore; junctions; Mark-of-the-Web; SMB shares with sign-in; extension icons; terminals |
| Linux x64 (Ubuntu 24.04 or later; X11, or XWayland under Wayland) | **B: preview packages.** `.tar.gz` (with a script that adds the menu entry), `.deb`, and AppImage, each built and started in CI; Core, Remote, and headless UI tests run on Ubuntu, including a real desktop keyring. Tier A waits for the TV-10 and TV-13 checks on real desktops. | Portable copy, move, and delete; the trash on each item's own drive (freedesktop.org), with Undo; permissions, owner, and group columns, and permission editing; downloads keep their origin (`user.xdg.origin.url`); saved passwords in the desktop keyring (GNOME Keyring, KWallet, KeePassXC); terminals from `$TERMINAL`, then the common ones. Not available: programs' own icons and Shell thumbnails, Registry, phones and cameras (MTP), administrator retry |
| macOS 13 or later on Apple silicon | **B: preview app.** A zipped `FileCat.app`, built and started in CI; ad-hoc signed, not notarized, so the first start needs right-click → **Open** | ⌘ works as Ctrl, and ⌘Q quits; `~/.Trash` and volumes' own trash (FileCat's Undo restores; Finder's Put Back does not know FileCat's deletions); downloads are quarantined for Gatekeeper; permissions as on Linux, plus Hidden in Finder; saved passwords in the login keychain; Terminal. Not available: as on Linux |

## Known gaps in v1 (planned later)

| Gap | Where it is explained | Planned |
|---|---|---|
| Registry browsing and typed value editing | Local Registry panels with explicit 32/64-bit views (switchable in place), raw inspection, bounded search, guarded jobs on marked items with Undo, `.reg` backups before key deletion, scoped `.reg` import/export (F5 to a folder offers it), binary save/load of value data, HKCR/HKCC writable-location route, change notifications, read-only key ACL inspection, and administrator retry. Import is non-atomic; `.reg` omits ACLs and the view; links are followed only on request | P4a |
| Elevated operations (per-plan broker) | Installed builds: "Retry as administrator" for items that failed with access denied (Registry changes, delete, copy, move within a drive, rename, create folder, attributes). One UAC approval per plan; the helper shows the exact steps, refuses links, and exits. Portable ZIP: none | P4a; TV-15 VM checks pending. FileCat never runs elevated by itself and warns when started elevated |
| Permissions and ownership (Linux, macOS) | Permissions, Owner, and Group columns (in the default Details and Full profiles). Change attributes and times… edits owner, group, and others × read, write, and execute, the set-ID and sticky bits, or an octal mode; only what you change is applied. With **Also apply to everything inside**, each folder changes after its contents, and execute reaches only files that are already executable (chmod's `X`). Links are never changed, nor what they point to. Copies keep permissions, except set-ID bits, and are never readable by more people than the source while they are written. Changing an item's owner or group is not supported (it needs administrator rights) | P9 |
| Recovering deleted files | Disk images, drives, and whole disks with NTFS, FAT12/16/32, or exFAT, including partitions that were deleted or whose table was erased, and volumes whose first sector is damaged (read from their backup boot sector): states come from the file system's own evidence, never a percentage. FAT forgets a deleted file's pieces, so a fragmented FAT file is "Partly lost" from where FileCat can no longer know; exFAT and NTFS usually keep them. Windows also erases half of a deleted FAT32 file's starting position: FileCat restores it from the neighboring items, folders' own entries, and the data's file-type signature, and marks the rest "Uncertain" (F5 then says the copy may not be the file). NTFS-compressed files are decompressed unit by unit (a unit whose space was reused is lost as a whole); EFS-encrypted files are listed by name only; alternate data streams are not recovered. Drives are scanned while in use, so the list is a snapshot, and new writes can overwrite what it shows; the system drive is the worst case (image it from another computer). Portable FileCat for Windows scans drives only when run as administrator; on Linux, asking for a drive needs UDisks2 (root or the disk group can read without it). ext4 and APFS are not supported | P10 (ADR-08) |
| Hex editing | Dedicated fixed-length editor for local files on Windows, Linux, and macOS (File menu, or F6 in the viewer; on Linux and macOS other programs are not locked out while it saves, and it says so): typing in hex and text columns, find, paste, bounded undo/redo, protected baseline, journaled in-place save with in-editor or later guarded recovery, sparse-aware Save As, and patch export/apply. Existing-target saves are non-atomic; network files and links are refused | P4b; TV-04 external fixtures pending |
| Bulk rename | Ctrl+M on files and folders on disk: name and extension masks (counters, character ranges, folder, date, and time), text or regular-expression replace, letter case, a live preview that blocks invalid and colliding names, editing the new names in your editor, swaps and chains, and Undo. Operations finishes a rename interrupted by a crash. Archive members rename one at a time (F2) | Post-v1 slice (OPS-007) |
| Creating links | File → Create link…: symbolic links (need Developer Mode or administrator rights on Windows; FileCat checks first and suggests a junction or hard link), junctions to local folders (Windows), and hard links to files on the same drive. FAT and exFAT drives support none of them. Undo removes links that still point where they were made | Post-v1 slice |
| Checksum manifests | `.sha256`, `.sha512`, `.sha1`, `.md5`, `.sfv`, and `SHA256SUMS`-style files (GNU, BSD-tagged, and SFV lines): File → Verify checksum manifest…, or Calculate checksums… on a manifest. Only files in and below the manifest's folder are verified; MD5, SHA-1, and CRC-32 matches show integrity, not authenticity. Calculate checksums… saves a manifest | Post-v1 slice |
| Running a command for each item | Ctrl+G on files and folders on disk: a program with placeholders, or a shell command line (cmd.exe on Windows, /bin/sh elsewhere) with names quoted for it. Commands run one after another in each item's folder; output is not shown, but a failure reports its exit code and last output lines. A canceled job leaves a running program to finish | Post-v1 slice |
| Comparing files | Ctrl+I (Commands → Compare files…): two marked files, one marked file in each panel, or, with nothing marked, the file under the cursor and the file of the same name in the other panel's folder (letter case aside; when there is none, the file under the cursor there). Text side by side with the changes within lines, or exact byte ranges; for binary files, Align shifted bytes finds content again after inserted or removed bytes (inserted, removed, and changed stretches; labelled heuristic). "Identical" only when every byte matched. Progress for large files; a file changed after the comparison is reported when you return to the window, and F5 compares again | P7 |
| Synchronizing folders | Ctrl+F10 → Include subfolders lists every difference below (Enter or a double-click on a file present on both sides compares their contents); Synchronize… there: one-way Update (new and newer items) or Mirror (also replaces differing files and removes what only the target has, to the Recycle Bin, or permanently only when chosen for targets without one). Every step is listed and can be excluded (Space); names that differ only in letter case and unsafe names are left out; the steps run as ordinary jobs. The target must be a folder on disk; no two-way synchronization | P7 |
| Viewing pictures | F3 on a PNG, JPEG, GIF, WebP, BMP, or ICO file shows the picture (from disk, archives, servers, phones, and recovery views alike): fitted to the window or at actual size (Z), turned upright by its EXIF orientation, over a checkerboard where it is transparent; animations show their first frame and say so. It is decoded by FileCat in a separate process that reads only the file's bytes (on Windows at low integrity, in a job that caps its memory), so a damaged or hostile picture cannot take FileCat down. Pictures larger than 256 MiB or 100 megapixels are not shown; Text/Hex (F4) and Info (Ctrl+I) still are | P7–P8 (VIEW-004) |
| Inspecting files | Viewer (F3) → Info, or Ctrl+I, reads statically from bounded headers; nothing is loaded, decoded, played, or run. Windows executables and DLLs: architecture, ASLR/NX/CFG, sections, imports, exports, .NET header, version information, requested execution level, and symbols file name. ELF: interpreter, needed libraries, run paths, PIE/NX/RELRO. Mach-O, including universal binaries: platform, OS versions, libraries. Java class files. Android APK and AAB: package, versions, SDK levels, permissions, components, debuggable, ABIs, modules. Wherever a format has signatures, they are reported as present and never verified. Images (PNG, JPEG, GIF, WebP, BMP, ICO, TIFF): dimensions, depth, animation, color profile, EXIF. Audio and video (MP4/MOV, Matroska/WebM, MP3, FLAC, WAV, AVI, Ogg): duration, tracks, codecs, sizes, and tags. HTML: title, language, character set, counts, and the other sites a page loads from | P7–P8 |
| Other archive formats | Read-only: TAR (also gzip, bzip2, xz, and zstd compressed), 7z, RAR 4/5 (solid and multi-volume sets), single `.gz`/`.bz2`/`.xz`/`.zst` files, and ISO 9660/UDF images. Enter browses, F3 views, and F5 or Unpack (Alt+F6) extracts. Links, devices, and escaping names are shown but never extracted, and encrypted members are listed but not opened. Archives nest with ZIP in both directions, and Ctrl+PgDn opens a file by its signature. Changing these formats is not supported; legacy 8-bit TAR names show replacement characters | P8 (ADR-07) |
| ZIP updates | Each change rebuilds the archive beside itself and replaces it only when verified and unchanged since you saw it; encrypted archives and archives inside archives are read-only; there is no undo. A rebuild needs free space for a second copy of the archive | – (by design; see ADR-07) |
| Reading archive members | Members over 32 MiB are decompressed as they are read: F3 shows the first page at once, F5 shows progress from the start, stops when canceled, and needs no temporary copy. A ZIP member whose checksum does not match is reported as damaged (when copied, it is not kept); so is a member that ends before its declared size. Opening a member deep inside a solid 7z, RAR, or compressed TAR decompresses everything before it | P5, P8 (`docs/validation/P5-P8-archives.md`) |
| Shell thumbnails and programs' own icons | Quick view shows the Shell's thumbnail for binary files, and programs, icon files, and similar types show their own icons. Windows' handlers for these run only in a separate helper at low integrity that cannot start programs (ADR-06). Shortcut-like files, themes, `desktop.ini`, and cloud placeholders are never handed to the Shell. Network and removable drives are included only if you opt in (Settings → Privacy) | P7 |
| Icons in lists (Windows) | As Explorer shows them, made at the display's pixel size: types by extension; drives by kind, the system drive with its logo; known folders (Documents, Downloads, Desktop, OneDrive, …) wherever they were moved; programs and icon files with their own icons; shortcuts and Internet shortcuts with the icon they name or their target's, with the shortcut arrow; folders whose desktop.ini names an icon. FileCat reads shortcuts and desktop.ini itself and takes named icons only from this computer's drives; a removable drive's own autorun icon is not used. The location menu (Alt+F1/Alt+F2) shows its places the same way: drives, This PC, phones, working sets, Registry Editor's icon for the Registry, and folders. Linux: the desktop's icon theme (GNOME, KDE, or GTK settings; inherited themes and hicolor), types from the shared MIME database, the home and XDG special folders, drives by kind; PNG and SVG drawn by gdk-pixbuf. macOS: Finder's icons through NSWorkspace, types by extension, folders, apps, and volumes by their own icon | UX |
| Git status badges | Local Git worktrees show a small icon mark for clean, changed, added, untracked, and conflicted files or folders. FileCat reads Git status in a cancellable background task and refreshes on folder changes and window activation. On Windows, an installed Shell overlay takes precedence when the Shell assigns one; its handler runs in the restricted Shell helper. Git supplies the fallback mark. Ignored items have no Git fallback badge. Git runs only inside a repository, found by full path on PATH, without its file-system monitor, index writes (so no hooks), or submodules; a repository whose own configuration names clean filters or included files gets no badges, since reading its status would run them | UX |
| Themes | View → Theme… tries each theme on FileCat itself as you move through the list (Enter keeps it, Esc goes back); View → Next theme cycles; Settings → Appearance too. Classic, Classic Dark, High Contrast (always used when the system asks for high contrast), Cyberpunk (steady dark-green circuitry, clear green edges, and color-coded file types), Psychedelic (soft drifting light, slowly shifting edge colors, and rare subtle glitches), and Steampunk (walnut and brass with stained glass above the workspace and a quiet lower control strip). Animations pause while FileCat is in the background and stop when the system asks for reduced motion or Settings turns them off | UX |
| File context menus | On Windows, file-system selections (up to 128 items in one directory) open the actual Windows Shell context menu, including installed third-party commands and their icons. The handlers run in a short-lived child process with FileCat's current user permissions so their actions can launch programs without loading extensions into the main app. “FileCat actions…” opens FileCat's own themed action menu. When the Shell menu cannot be made, or for non-file-system locations and other platforms, FileCat's icon-bearing action menu appears. Property columns come from FileCat's own readers | UX |
| FTP details | FTPS accepts a certificate the operating system validates; any other needs your explicit choice, **Connect once** or **Trust this certificate** (pinned by SHA-256), and a changed certificate is refused by default. Unencrypted FTP is a knowing choice: in the connection dialog, or confirmed once per session for typed ftp:// addresses. An FTPS profile never falls back to unencrypted FTP. Times are exact where the server lists with MLSD; older servers' listings may be minutes-precise or in server time. At most 2 connections per FTP server. No terminal on FTP connections | P8 |
| Editing files on servers | F4 on a file on an SFTP or FTP server edits a private copy in your editor; Commit (F4 again, or File → Edit sessions) writes it back only while the server file is still the version the edit started from, and a changed file is never overwritten without an explicit choice | P6 (done) |
| SSH terminal and agent | Open terminal on an SFTP panel starts the OpenSSH client in that folder; it checks host keys against OpenSSH's own known_hosts. Connections can sign in with keys held by an SSH agent (ssh-agent, the Windows OpenSSH agent service, Pageant, 1Password, Bitwarden, KeePassXC): the agent signs, keys never leave it, and it is never forwarded | P6 (done) |
| Translations | English only. Command titles and key-bar labels can already be translated with `lang/<culture>.json` next to the executable. | Other UI text once translators and QA exist |
| Alternate data streams on FAT and exFAT | Each lost stream (and a lost download mark) is named per file | – (file-system limit) |
