## Implementation and validation

O1 service groundwork is implemented. No Owner/native reader is enabled by this package. O2–O7 and native
shipping gates remain pending. O1's stage acceptance is the service tests; performance shipping gates apply
at O4/O5 under §8.4 of the plan. Whole-feature OWN rows are not claimed complete by service-only tests.

Changes:

- Append Denied without renumbering existing states; add Current/LastKnown/Gone observations and an optional field detail formatter.
- Accept structured producer outcomes. Access exceptions become Denied; cancellation/retirement publishes nothing,
  including a producer that reports an I/O/access error after cancellation.
- Share applicability/Offline gates across Get, Compute and the new gated Peek. Plain Peek retains its existing contract.
  A cached explicit expensive result remains readable on a slow location, without automatic expensive production.
- Apply one effective interval to Get, the locked scheduling recheck and Compute: 5 seconds locally, six times
  the field interval on slow locations. Every refreshable completed production records time. Explicit analysis
  retries Denied/Unsupported/Failed; automatic demand does not retry cached Denied/Unsupported.
- A genuine transient refresh failure preserves a typed LastKnown value; Compute returns exactly the effective stored
  outcome. Successful refresh clears the marker. Nonrefreshable verification is unchanged.
- Expiry marks existing timestamps due and requests repaint without I/O. Resolver repaint has a public throttled hook.
- Add bounded field snapshot claims (64 by default). Publications carry field/key/revision/origin and retire conflicting
  claims synchronously under the publication lock. Own-origin analysis writes are exempt. Final memory attachment is
  atomic with the claim check. Targeted Forget conservatively retires that field's claims, preserving unrelated fields;
  retained buffers/shared byte reservations remain O5 work.
- Cells show `no access` and the `(last known)` suffix. Analyze captures its slow-location context before worker dispatch.
