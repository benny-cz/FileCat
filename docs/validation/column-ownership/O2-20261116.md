# Column ownership O2 evidence

Package O2 builds on O1 commit `3655e4b3`, on `codex/column-ownership` in the isolated worktree.
O1 is pushed to `origin/codex/column-ownership`; the user explicitly authorized ongoing pushes to that remote.

## Implemented behavior

Owner and Group store canonical typed principals, separate from account names. UID/GID and SID components compare
numerically, with kind/authority participating in identity. Display can abbreviate a domain/account SID while details
and keys keep the full ID. Instance field factories capture their source/resolver; static catalogue fields own neither.

`PrincipalNames` provides memory-only Peek/Capture, producer-only Request, demand-based expiry, coalescing and
LRU retention. Normal workers: two dedicated background threads; slow queued work permits up to four. A single
process-wide four-slot admission counter includes blocked and retiring calls across resolver lifetimes. No domain
prefix suppresses another. The cache/queue/in-flight state is bounded by 4096 entries, 262144 UTF-16 characters and
256 queued requests. Native lookup buffers are bounded at 1 MiB on Unix. Oversize names become a bounded
Unavailable record. Invalidated/disposed native completions cannot publish; their entries remain charged until return.
Disposal does not wait for blocked native calls, and waiting workers exit. Signals are disposed after the last worker exits.

Linux uses final-component no-follow/no-automount `statx`, validates UID/GID masks independently, and distinguishes
Gone/Denied/Unsupported/transient failures. Zero is valid only with the corresponding returned mask bit. Uncached
NSS lookup distinguishes successful-null NotFound from every nonzero error; EINTR/ERANGE retries and buffers are bounded.
Existing UnixPermissions stat/name-cache callers retain their behavior except the specified Linux no-automount flag.
Permissions gains octal detail. Metadata services own fallback resolvers or borrow explicitly supplied ones; AppServices
owns its resolver and disposes subscriptions/services in order. Resolver completions only request repaint.

The macOS policy wrapper captures/sets/restores thread policy on the same device worker. A restoration failure retires
that worker before another job can execute on it, including retirement of an empty device queue. Capture/set failures
skip the read. The **shipping macOS route remains Unsupported pending GM1**, so no native macOS guard/ABI claim is made.

## Native gates and limits

**GL1 core: Passed for this Ubuntu x64 environment.** Owned regular files, a folder, a final symbolic link and a broken
final link matched an independent GNU `stat -c %u:%g` observation. Missing paths returned Gone; a deliberately unmapped
high UID returned native successful-null NotFound; the fixture's owner resolved. Kernel-returned masks were usable.
Set-bit zero and independently clear masks with zero/nonzero garbage are deterministic adapter cases, not a claim
that a native UID-zero fixture was created. Terminal flags are source-verified as `0x100 | 0x800` and the native call
succeeded; no automount mount fixture was available. No general intermediate-folder/no-mount guarantee is claimed.
NFS/CIFS/vfat/btrfs/stopped-NSS diversity and the release-pinned runtime remain Not run. The new route is enabled
for Linux x64; Linux ARM64 is conservatively Unsupported until native validation.

**GM1: Not run.** The guarded macOS shipping route is conservatively unavailable. All policy wrapper/retirement paths
above use deterministic fakes; they establish no APFS/Apple silicon/dataless behavior. The existing Permissions route is unchanged.

Native references checked during implementation: [Linux statx](https://man7.org/linux/man-pages/man2/statx.2.html),
[Apple resource.h](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/resource.h),
[Apple errno.h](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/errno.h). The Apple headers are moving
source references, not a fingerprint of an available native machine. In particular Darwin EDEADLK is 11, distinct from Linux.

O1's recorded PF1/PF3 timing misses remain open for the O4/O5 performance gates; O2 does not relabel them.
