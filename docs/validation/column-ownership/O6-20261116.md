# Column ownership O6 evidence

The new ListingModel.PreparingStore hook runs on the UI thread before a replacement store starts enumeration or
captures ordering keys. TabViewModel retires its retained analysis/complete claim and Owner/Group values and running
productions for the affected filesystem folder. Navigation also retires the departed folder's ownership work.
Folder-scoped claims in other folders survive this targeted invalidation. Other metadata fields are preserved.

During a pending refresh, the old displayed store cannot start more ownership reads. Obsolete queued viewport work
also checks this demand-store identity. A failed/canceled refresh re-enables demand for the old store it kept.
Navigation intent cancels analysis before awaited preparation; same-location replacement and close cancel as well.
Retiring workers keep their independent store/buffer leases until their native call returns.

Window and tab activation call ExpireRefreshable explicitly; the service marks due times and raises its repaint
notification. Hidden rows remain idle. Both Reread command routes invalidate the name resolver generation and the
metadata service. Attributes completion retains its existing metadata invalidation, which now retires claims too.
