# Column ownership O3 evidence

O3 follows pushed O2 commit `3e8f5ea7` on `codex/column-ownership` in the existing isolated worktree.

## Implemented

Metadata presentation now has one typed path for cell text, detail, inspection text and whether a value needs
explanation. The existing GetMetadataText signature remains. A trailing optional MetadataField.NeedsExplanation
predicate lets ownership factories inspect their captured resolver's typed name status, without parsing rendered text
or depending on a different resolver instance. Its callback is memory-only, as are Format and Detail.

Rendered metadata cells retain sanitized detail and explanation eligibility. Tooltips include it for clipped values,
denied/unsupported/failed outcomes, unnamed IDs, provenance notes and LastKnown values. Fully shown resolved names
and Permissions remain quiet. Pending ellipses are explicitly tooltip-suppressed, even in a narrow cell. Empty Gone
cells have no tooltip. The existing verification tip still takes precedence.

Inspection uses the gated Peek with paint-time row/path/device context. It does not create a new provider item
reference, read an owner, or start a name lookup. Inapplicable fields are omitted; unavailable provider paths and
not-yet-read data have distinct actionable text. Gone retains its reason; LastKnown retains its failure explanation.
Full identity and octal mode detail are available without hover. The 8192-character tooltip and 1 MiB inspection
limits include the added detail text.

Only the focused row currently being painted requests horizontally hidden profile metadata, including eligible
expensive fields, through normal demand admission. A vertically offscreen focused row requests nothing and can
use its retained context, or the not-read hint if none exists. Context retention is bounded to visible rows plus
one focus context for the current store, and is cleared on store/tab replacement. Current viewport membership is
published before paint demand can run, avoiding a dropped first request against the previous viewport.

DescribeItem, FileListAutomation, dialog structure and per-row accessibility nodes are unchanged. Ownership/name
notifications keep the existing state update path but do not alter the spoken focused value or its name/value events.
