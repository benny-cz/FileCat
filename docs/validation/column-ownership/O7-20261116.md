## Narrow integration additions

EntryStore's source gained two small accessors beyond the plan's original file list: TryAtCount attaches memory
state under the existing append gate, preventing an append between a final row-count check and analysis attachment;
Scan.Materialize adapts the existing mapped scan to the producer API without positioned spill reads for every row.
The former supplies the required count-race guarantee; the latter addressed the measured bulk-capture/analysis
cost. Their race/materialization tests are recorded with O5/O6. They change no EntryData/store/spill layout,
enumeration policy or lifetime format, and do not introduce a general provider or sorting rewrite.
