# Archive member commands and local transfers

This connected component passes its focused, complete Core, Windows native and independent-reader matrix.
The [checkpoint](member-commands-checkpoint.json) records exact source/DLL/PDB bindings and process cleanup.
It does not qualify or register a production writer.

The implementation connects local F5/F6, exact member deletion and rename, and nested empty-folder creation to
the six container backends. It preserves captured input/origin/destination/queue intent, reviews a complete
native catalog before submission and retains preparation ownership through cancellation. Existing RAR5/7z
passwords are requested in a masked field, retried after refusal and transferred to the job only on submission.
The subsequent [password browsing component](ARCHIVE_PASSWORD_BROWSING.md) covers read-session integration;
external edit sessions remain unfinished.

Writable listings carry a whole-source revision. The command checks it before launching an assessment, so a
stale duplicate ordinal cannot silently select a different stored member. Directory rows carry the same
revision, including implicit folders. Ordinary duplicate advisories allow exact commands; incomplete/damaged
listings do not. The complete strict catalog determines recursive physical scope and preserves case and Unicode
spellings. Directory intents use an explicit trailing slash and files always use a concrete occurrence ordinal.

Bulk additions default conflicts to Skip. Replacing unique existing names requires an explicit danger action.
Duplicated names and file/folder conflicts remain skipped. A sealed borrowed input subset grants reads only for
the resulting plan; it retains original native identity and metadata checks and expires with either owner.
An entirely skipped update does not publish. F6 removes only committed captured inputs after publication;
skipped children keep their original ancestors too.

Validation uses checked source deltas, early connected Core/UI gates and a Windows native UI matrix before the
complete regression and independent-reader cohort. Every failed phase is retained. Reuse requires exact binary
hashes and compiler-source binding; a changed production assembly invalidates affected runtime evidence.
