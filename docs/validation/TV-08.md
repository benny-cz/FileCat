## What the measurements found and changed

- **Content search allocated a 1 MiB byte buffer and a 2–4 MiB character buffer for every file.** Searching 50,000
  small files allocated 150 GB and took 38.5 s. The buffers are now made once per search, and chunks are matched as
  spans instead of new strings: 3.0 s, 38 MiB.
- **Ignoring case was ten times slower than matching it** (linguistic comparison, 40 MB/s). An ordinal match now counts
  at once, and only text where the two can differ (non-ASCII or control characters) takes the linguistic path:
  200 MiB in 67 ms instead of 5.1 s. It also finds more: Czech collation treats "ch" as one letter, so the linguistic
  search alone did not find "hata" in "chata".
- **Aligned binary comparison read through cached 1 MiB chunks and allocated buffers for every match.** A 64 MiB file
  shuffled in 4 KiB pieces read 16 GiB, 16 zero bytes against 16 MiB of zeros took 5 s, and 64 MiB of unrelated input
  5.5 s. Matches are now verified and extended with reads that start at 256 bytes and grow, one set of buffers serves
  the comparison, a repeated find of the same stretch is kept once, and a filter rules out most windows before the
  index is asked: 378 MiB read, 0.2 s, and 1.0 s. Changes closer together than a block hid the equal bytes between
  them (99.83% paired where 99.99% was right); the stretches between matches are now looked into.
- **Binary comparison stepped byte by byte** (230 MB/s). Equal runs are now skipped a vector at a time: 256 MiB in 76 ms.
- **Canceling a large text comparison waited for its first phases** (224 ms). Numbering lines and finding anchors now
  check for cancellation every 65,536 lines: 4 ms.
- **Registry search opened every key from its hive's root**, one open per path component, and every subkey once more
  to check for links (about 10,000 keys/s). It now walks depth first with one open handle per level, and one open per
  subkey serves both the link check and the reading: about 40,000 keys/s.
