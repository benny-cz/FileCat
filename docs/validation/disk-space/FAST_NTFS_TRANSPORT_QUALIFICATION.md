# Fast NTFS metadata transport

This packet covers the transport portion of W7. The installed broker plan, whole-volume source binding and enumeration, dataset projection, and installed-package qualification remain open.

The Windows server uses a fixed local pipe name derived from a 256-bit nonce. It requests the first instance, one connection, and remote-client rejection. The requester logon SID receives individual data and synchronization rights. The client sends the exact rights mask and identification-level quality of service through an NT open. The connected handle's granted access is checked before exchanging frames. [Named-pipe security and access rights](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights), [CreateNamedPipeW](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-createnamedpipew), [Object attributes](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntdef/ns-ntdef-_object_attributes)

The transport checks the kernel's peer PID and session against a held process and captured creation, image, user, logon, and authority evidence. The installed launcher still needs to supply the expected trusted process on each side. The Windows fixture exercises a pair of local pipe handles from the ordinary test process. It also checks rejected process identity changes, a second instance, illegal permission requests, and the client's identification level.

Frames use a four-byte little-endian length and strict JSON with a 1 MiB limit. The protocol rejects unknown fields and commands, duplicate fields, incorrect versions, nonces and sequences, malformed UTF-8, and invalid order. A watchdog closes stalled sessions. Windows deadlines use the elapsed system clock, which includes time in sleep and hibernation. [Windows elapsed clock](https://learn.microsoft.com/en-us/windows/win32/sysinfo/windows-time)

Earlier Windows runs exposed two token-query failures and a client-open failure. The current implementation reads the logon SID, elevation and integrity through native token queries and opens the pipe with the fixed rights mask. Run r1421 exchanged the metadata messages through the native pipe and confirmed identification-level QoS. Its negative check also found that Windows could return a handle for a request using the append or instance bit. The follow-up verifies the actual granted access and explicitly denies instance, DACL and ownership rights to the requester logon SID. [Windows token information](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ne-winnt-token_information_class)

Windows also returned a client handle with granted access `0x00100004` when a separate open requested the append bit with the explicit deny ACE in place. The r1423 follow-up used that handle for a one-byte write to the disposable pipe and checked a second server instance. Both system calls returned access denied and the write transferred zero bytes. The fixture checks those effective permissions as well as the exact mask on the protocol's own client handle. The elevated installed helper and ordinary-requester exchange still needs qualification.
