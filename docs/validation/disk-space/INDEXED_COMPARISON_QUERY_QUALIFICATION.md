# Indexed comparison predicates, cohorts and ordering — 2026-11-16

The indexed comparison tab now applies a text predicate, recorded side, change cohort and order together. Current, Previous, Either and Current-otherwise-Previous follow the existing three-valued memory comparison semantics. A match on one alias retains the whole accounting row and its original charge; filtering does not split or recount an object cohort. Definite and uncertain accounting-row counts are separate from Unknown change classifications. Invalid, canceled or refused requests retain the applied query/index/page. Reset restores the default view, and a successful metric change retains the applied query, cohort and order.

All four orders are indexed: absolute difference, absolute relative percentage with a known-baseline distinction, current amount with known/missing distinction, and ordinal recorded path. Numeric keys retain UInt128 precision and stable derived row IDs break ties. Path keys use full escaped names and roots before enforcing the bounded exact-key size; an oversized key is refused rather than ranked by a clipped label. Names, sizes, allocation components, dates, roots, state and exact signed deltas use the existing typed filter. There is no regex, glob execution, property reflection or source reconnection. Each used side parses against its own captured timezone and root-display context; unavailable calendars require explicit offsets.

Query construction advances through individual captured rows, aliases, ancestors and component facts in bounded background batches. Selected keys are staged in private authenticated storage, then sorted into a paged index. Neither complete inputs nor alias cohorts become managed arrays. Construction has one shared place, releases its temporary inputs before publication, and keeps actual cancellation/cleanup ownership. Comparison read leases retain both input indexes through query lifetime after the comparison owner closes, with eight reader places and close completion only after the last reader and actual operations retire. The tab closes its query before its comparison to preserve that lifetime ordering.

The two previously recorded UI findings are fixed: aggregated/wrapped unconfirmed-close errors enter the error/latching path and retain admission; refused or canceled metric rebuilds reset the selector to the metric of the retained page. Retry reconstructs the retired index. Native-capture/headless-view controls verify these paths, query application, all side/order selectors, alias inspection, invalid-query preservation, reset, paging and applied-query survival across metric changes.

129 new Core controls cover four metrics × four sides × four orders, all eleven cohorts, uncertain results, raw names and root-display IDs, used/unused captured calendars, signed UInt128 extremes and zero baselines, empty-input syntax checking, failure/cancel/retry, retained readers, actual construction admission and 14,000-entry/cohort paging. Eight new native-filesystem/headless-view controls pass on the actual Windows VM, Mac and Ubuntu VM. These are distinct from physical pointer/keyboard/screen-reader qualification and full 1M/10M or process-resource measurements.
