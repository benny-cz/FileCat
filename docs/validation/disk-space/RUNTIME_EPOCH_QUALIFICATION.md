# Runtime rescan epochs and native preparation

The Core epoch API and internal app preparation passed their applicable Windows VM, Mac and Ubuntu VM controls. The [immutable evidence](source-manifest-r1197-runtime-epochs.json) retains compiled sources, exact input hashes, original run results and focused fixture deltas. This source cohort is based on `378fab83`; the combined performance/new-main integration is a separate checkpoint.

`AnalysisCoordinator.Rescan` requires an actual runtime predecessor and freshly prepared sources. It preserves SessionId, increments Epoch and Revision, tags progress, and keeps the previous snapshot/dataset independently readable through its existing leases. It waits for completed producer/source closure, rejects unconfirmed closure, verifies scheduler/profile and physical root continuity, and permits only one successor per epoch. Constructor failure releases unpublished resources and rolls back the reservation. Pause/resume preserves the refresh phase; stop preserves the predecessor.

Fresh local native bindings have fresh connection references. Their physical source identities must still match. Changed locations, roots, boundaries, name rules, remote connection references and reused source objects are refused. Inventory records cannot construct a runtime predecessor or become a filesystem capability.

The app prepares a fresh private context and checks all three private boundaries against cached runtime physical witnesses. A copied profile marker does not establish directory identity. Explicit bounded-memory fallback retains its ephemeral correlation only when the private boundaries remain unchanged. Unused, imported and closed preparation contexts cannot issue a refresh. Existing profile bytes and private-name exclusion remain intact.

The fixture set has 23 Core epoch cases, two Windows native cases, seven native app cases and three additional private-directory replacement cases. Platform-specific native fixtures run on their applicable systems. Broad results include Core 2,015 cases, Windows native 77, rendering 786 and settings 36, with declared platform skips. The extra three fixtures use only a changed test DLL/PDB: production inputs are hash-identical to the broad cohort, the old guest payload is verified and copied, and each transfer is about 0.75 MB. Successful broad cases are reused.

The first Windows launcher was refused by a host parameter range before deployment. A focused Unix runner initially had CRLF line endings and failed before extraction or tests; the corrected runner is recorded separately. One small cache-verification receipt was copied separately after the original collector omitted it; the collected archives were preserved. Every completed test process exited and collection-time process inventories were empty. Tests were postponed when another worker appeared.

This is native filesystem and headless application qualification. Public rescan controls, old-view adoption/focus restoration, branch refresh, public feature registration and the complete W1 lifecycle are unfinished. The full goal and final independent UX/UI/functional/security review remain open.
