# Named replacement and explicit recovery

This packet connects the prepared private `.fcdsa` replacement transaction to the memory and indexed Save interfaces and implements fresh, explicit recovery of its pending states. The full disk-space plan, process-death boundary qualification, physical desktop matrix and independent final review remain open. Product command/action gates remain off.

Entering an existing cataloged name now prepares the complete incoming revision before a themed Keep existing / Replace analysis review. Keep existing is the default and cancel choice; Replace is a separate danger action. The review names the destination, both complete sizes, observation intervals, coverage, provenance and consequences. Unknown/unindexed names and pending maintenance cannot enter this replacement route. They preserve existing files and require another name or explicit pending-entry review. Replacement works at the eight-tab limit without allocating another session.

The saved browser lists a pending replacement once, excludes its current metadata from ordinary saved choices, and offers Review pending replacement. Its normal Open/Delete controls do not act on that selected pending row. Recovery is available in both memory and indexed views at the eight-tab limit. Leave pending is the preserving Enter/Escape default. Restore previous and Keep incoming and finish separately review discarding the other captured version. Copy previous to a new name is create-new only and preserves the original name, pending record and every remaining version; the copied inventory is unindexed and opens by filename with the default view.

Recovery never replays a recorded execution phase. Preparation reads the application-prepared private profile/catalog, exact metadata identities and complete remaining containers. The review distinguishes actual original, incoming and previous presence, validates expected IDs/size/coverage/taint, and reports damaged, unsupported or foreign files as preserving states. Conflicting complete copies are not silently reconciled. Each one-use runtime review belongs to its original store. Execution obtains the writer, checks profile/catalog/metadata identities again, opens the exact reviewed native objects, and verifies complete bytes before mutation. New occupants, changed bytes and active readers refuse the old decision.

Restore can recover an unchanged old original, atomically restore a complete backup over the reviewed incoming original, or create-new a verified previous copy when the original is absent. Current incoming catalog metadata retires before changing its data binding. Finish can retain an already switched incoming file, complete the switch from a verified incoming payload while first preserving a complete old backup, or create-new when the original name is absent. Reconstructed incoming display settings use the default view; an existing confirmed incoming entry retains its saved view. Copies remain bounded to 64 KiB admitted turns and preserve the usual space reserve. Existing complete-copy restore/cleanup can work below the save reserve without allocating another payload.

Logical incoming-save confirmation precedes previous-copy cleanup. Cleanup refusal retains its receipt; cleanup uncertainty explicitly says the incoming save was confirmed. A later unconfirmed close is recorded by actual-work ownership and cannot become a generic claim that the old name was restored. Unknown/corrupt/future bytes are preserved. The native guarantee remains confined to the cooperating owner-private store, not generic source operations or imported-path authority.

Opened memory and indexed inventories now retain their verified saved filename and inventory identity. Replacement invalidates only references to the replaced UUID/name; the saving view records the new receipt. Recovery restore invalidates the discarded incoming reference, while finish invalidates the previous reference. A recovery copy, including an uncertain copy publication, leaves the original saved references unchanged. Losing a memory view's saved copy retains its observations and makes closing require the preserving temporary-work review. Deferred indexed page publication retains the persistence outcome notice.
