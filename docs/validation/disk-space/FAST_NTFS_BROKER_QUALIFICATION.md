# Fast NTFS broker and volume reader

This packet covers the whole-volume selector, broker plan and consent dispatch, and native metadata reader. The analyzer's dataset projection and installed-package qualification remain pending.

The ordinary requester captures a volume GUID from current Windows enumeration and binds it to the NTFS root's serial and file ID. Drive-letter selections are checked through a second held root handle. The approved plan contains one metadata verb, a fixed protocol and field list, a 256-bit one-use nonce, and installed requester process evidence. The broker binds the requester and root before consent, checks them again afterward, and handles metadata through its own read-only endpoint. The consent dialog names the whole volume, describes access to names and metadata, and defaults to Cancel. [Windows volume enumeration](https://learn.microsoft.com/en-us/windows/win32/fileio/volume-management-functions)

The reader verifies the raw volume serial before issuing its first metadata enumeration query. It uses fixed volume-information and file-metadata controls through a read-only handle. Each page preserves exact UTF-16 name bytes, file and parent IDs, and basic attributes. Allocation, logical sizes, link counts, timestamps, and complete alias coverage still need qualified evidence. The broker report retains counts and controlled status messages.
