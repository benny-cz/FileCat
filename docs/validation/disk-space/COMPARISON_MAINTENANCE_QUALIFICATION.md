# Saved-comparison maintenance qualification

This packet adds deletion of current-profile `.fcdsc` comparison bundles through the narrowly scoped `OwnedAnalysisStore` capability. A bundle contains both captured inputs and its display settings; independently named inventories, source files and open captured data remain intact. This extends r917's inventory-only maintenance namespace; profile/header/lock/capacity controls and generic source paths remain excluded. The complete persistence gate and full plan remain unqualified.

The comparison browser stays available at the shared eight-tab limit. Opening another comparison acquires a tab slot before reading its inventory. Deletion requires a matching browsed selection and a separate themed review with name, location, size, saved time, sensitive-provenance notice and consequences. **Keep comparison** is the default/cancel action; **Delete comparison** is danger-styled. Deletion is not described as secure erasure.

Preparation verifies the private profile, portable contained name, generated comparison UUID, native file identity, exact byte count and full-file SHA-256, then probes actual exclusive maintenance access. The one-use review belongs to that exact owned-store instance. Execution obtains the catalog writer lock and exclusive native file lease, revalidates the same identity and bytes and requires actual removal/close. Pre-unlink refusal preserves the file; post-unlink or close uncertainty is reported without an automatic retry. A comparison is one file, so no catalog tombstone/journal is required. This route accepts no source path or generic-operation maintenance flag.

The new bounded inspector shares strict comparison-header decoding with the ordinary importer, checks both embedded inventory containers and their identities/provenance, validates the outer checksum and EOF, and computes a digest including the trailer. It does not import a whole graph or turn recorded paths into authority. Two inspections may hold the bounded inspection buffers; existing nested parser reservations, per-store compound-operation limits and native/device I/O bounds remain in effect. All reads and actual buffer/file closes run on admitted Background device turns. Container verification is distinct from full graph-semantic import validation.

Known removals and uncertain removals invalidate matching in-process saved references by generated ID, filename and kind. Observations remain available; comparison close again uses its temporary-work preserving review. Memory and indexed named-inventory views also clear the obsolete saved filename. The per-profile AppServices registry uses weak observers, removes disposed targets, isolates broken view observers and does not serialize or grant authority. Normal view consumers update on the UI thread; late background presentation posts do not retain native-operation ownership behind a stopped UI. This is notification of FileCat's own operations, not a filesystem watcher for external changes.
