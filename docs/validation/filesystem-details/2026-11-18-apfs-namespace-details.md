# APFS case behavior in full file-system details

An explicit full report checks the filesystem type and device with a no-follow Darwin volume query. On a matching APFS device, a second query checks the case-sensitivity and case-preservation capability bits independently against their validity mask. FileCat checks the second result’s device and type again before reporting either capability. The facts describe the volume. The summary issues no volume capability query, and the full report leaves Unicode normalization uninspected. [Darwin volume attribute ABI](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/attr.h). [Darwin volume attribute implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/vfs/vfs_attrlist.c).

On the Apple silicon Mac, two disposable images supplied case-sensitive APFS and case-insensitive APFS. A lowercase lookup of `MiXeD` failed on the former and succeeded on the latter. Both reported case preservation. An ordinary file and its volume root agreed. A link on the insensitive volume to the file on the sensitive volume reported the insensitive device. Inspecting the file through a directory alias into the sensitive volume reported its actual sensitive device. FileCat’s explicit full reports matched all six cases. The synthetic test also checked wrong-device and truncated replies, an out-of-bounds name reference and a missing capability validity bit.

The focused Core suite passed 26 tests and skipped seven Linux-only fixtures. Both owned images were detached after the run.
