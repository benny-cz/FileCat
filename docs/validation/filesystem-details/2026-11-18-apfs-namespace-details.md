# APFS case behavior in full file-system details

An explicit full report checks the filesystem type and device with a no-follow Darwin volume query. On a matching APFS device, a second query checks the case-sensitivity and case-preservation capability bits independently against their validity mask. FileCat checks the second result’s device and type again before reporting either capability. The facts describe the volume. The summary issues no volume capability query, and the full report leaves Unicode normalization uninspected. [Darwin volume attribute ABI](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/attr.h). [Darwin volume attribute implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/vfs/vfs_attrlist.c).

On the Apple silicon Mac, two disposable images supplied case-sensitive APFS and case-insensitive APFS. A lowercase lookup of `MiXeD` failed on the former and succeeded on the latter. Both reported case preservation. An ordinary file and its volume root agreed. A link on the insensitive volume to the file on the sensitive volume reported the insensitive device. Inspecting the file through a directory alias into the sensitive volume reported its actual sensitive device. FileCat’s explicit full reports matched all six cases. The synthetic test also checked wrong-device and truncated replies, an out-of-bounds name reference and a missing capability validity bit.

The focused Core suite passed 26 tests and skipped seven Linux-only fixtures. Both owned images were detached after the run. The native control log is `~/FileCatValidation/filecat-apfs-namespace-0f17180b-r4/results.log`. FileCat’s test receipt is `~/FileCatValidation/filecat-apfs-details-0f17180b-r2/apfs-details.trx`. Intel macOS, other filesystems and normalization have separate qualification requirements.

## APFS file sharing

The full report queries Darwin’s extended attributes for an ordinary file on the observed APFS device. The second sample must agree on file kind, device, file ID, creation and change timestamps. FileCat displays private bytes, clone ID and the sharing flags from their own returned fields. The summary stays on the minimal metadata request. Links and directories omit the sharing section. [Darwin extended attribute constants](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/attr.h).

On Apple silicon with macOS 27.2.1, a native `clonefile` fixture reported all blocks shared and zero private bytes for the source and its untouched clone. A byte-for-byte ordinary copy reported its full 524,288 bytes as private. A second clone with its first 65,536 bytes rewritten reported possible sharing and 65,536 private bytes. An independent Darwin query observed that this clone’s ID had changed while its sharing flag remained set. FileCat preserved all fixture bytes, and the full report remained metadata-only. The report describes per-file evidence. Total sharing and reclaimable space require a separate observation.

The focused Core suite passed 32 tests with nine platform or opt-in skips. The result is `~/FileCatValidation/filecat-apfs-sharing-8cc99073-r2/apfs-sharing.trx`. The tested `FileCat.Core.dll` SHA-256 is `FE6CD19453D431DCD26F6F33166983529CBD349CD4F3E381D04B15430412D90B`.
