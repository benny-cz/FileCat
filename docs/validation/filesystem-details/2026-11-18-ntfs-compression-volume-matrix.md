# NTFS compression volume admission and directory defaults

The Windows 11 x64 VM ran the production candidate under medium integrity. Native GET/SET/GET distinguished compression of the main stream from both compressed and clear alternate streams. The folder tests verified that newly created files and directories inherit the current default, entries already present retain their state, and same-volume renames in both directions preserve the moved file's state and contents. Removing the parent's default affected later creation and left the previously created child default intact. [Windows compression attribute](https://learn.microsoft.com/en-us/windows/win32/fileio/compression-attribute)

The ordinary 4 KiB NTFS system volume admitted a compression review on an owned file. The 64 KiB NTFS VHD refused both actions with the allocation-unit reason. A read-only 4 KiB NTFS VHD identified its volume as read-only, and FAT32 and exFAT reported the filesystem boundary. An inspection-only review of the active Windows tree refused the target. Three sparse logical lengths, 29,999,999,999, 30,000,000,000 and 30,000,000,001 bytes, confirmed that enable admission ends above the ceiling and that an already-clear file may be reviewed for removal above it. Actual large compressed removal and the remaining volume and device cases still require evidence.

The Windows enumeration tests also passed the existing ordinary parity fixture, long Unicode paths, exact junction and symbolic-link tags, and empty and missing directory handling. ReFS, mapped SMB and the separately measured scale case were the three fixture skips in this combined run. The result was 59 passes with zero failures. See `.tmp/filecat-compression-volume-matrix-tests.xml`. Platform release flags remain gated.
