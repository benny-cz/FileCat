# EFS protection in archive disk caches

The archive reader records protection through the actual input handles it opens, including later RAR volumes and streams it closes before materializing the requested member. Before a disk cache it resamples the retained witness and volume handles. An observed EFS input or unknown protection stops caching. Progressive reads check before and after the buffer read, before creating or writing the cache. Cross-provider nested spooling admits the member through its own archive reader before creating its temporary file. Cached nested reads recheck the current archive before lending a spool.

The Windows 11 x64 suite passed 73 tests, with one Unix-only rename fixture skipped. A 33 MiB member of an EFS-encrypted compressed TAR was refused when it needed a disk cache and read successfully through the forward-only path. In a six-part RAR, part one remained clear and part three was encrypted. A small member remained readable in memory, while requesting a disk spool for it was refused. A cross-provider request for a member of an encrypted ZIP was also refused. The three EFS fixtures each confirmed that the refusal created no cache directory. Results are in `.tmp/filecat-native-archive-efs-spools-verified-tests.xml`.

Ubuntu and macOS each passed 95 ordinary archive tests, including nested source lifetime across eviction, with three Windows-only skips. This qualifies the tested E-OUT10 paths. Re-admission across additional format-specific opens and broader platforms still require evidence. Memory members remain available to read. Their protection must be carried into the separate transfer and drag publication gates before EFS is enabled.

Both providers now count the full archive chain before opening any nested spool. The existing limit of eight inner archives applies to mixed ZIP and TAR chains as well. Alternating chains starting with each format returned the expected payload at depth eight. Depth nine and a direct spool request for the ninth archive were refused with no cache directory created.

The follow-up suite included archive formats, source replacement, case-distinct sources, spool lifetime through eviction and EFS output controls. Windows 11 x64 at medium integrity passed 99 tests with 16 case-sensitivity skips. Ubuntu x64 passed 108 tests with seven Windows-only skips. Apple silicon macOS passed 92 tests with 23 Windows-only or case-sensitivity skips. The exact XML results are `nesting-bound-tests.xml`, `nesting-bound-ubuntu.xml` and `nesting-bound-mac.xml` in the respective validation `.tmp` locations.
