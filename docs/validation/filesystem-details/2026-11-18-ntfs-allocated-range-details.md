# Bounded NTFS allocated byte ranges

The full record can show the queried main-stream ranges of a sparse or compressed file on local NTFS. It checks the live original handle for reparse, recall and sync-provider state before reopening that same object for the metadata query. It then checks the reopened identity and compares the reported stream size and allocation before and after collection. Windows 11 x64 local NTFS returned error 87 when `FILE_FLAG_OPEN_NO_RECALL` was passed to `ReOpenFile`. The successful local recipe uses `FILE_FLAG_OPEN_REPARSE_POINT` with the prior eligibility checks. The summary never opens the additional descriptor. This route does not issue payload reads. [Microsoft's `ReOpenFile` contract](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-reopenfile). [Microsoft's allocated-range query contract](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_query_allocated_ranges).

The collector reports the validated prefix when a later request fails or reaches a limit. It checks byte counts and ascending offsets, clamps terminal rounding to logical EOF and stops at 256 queries or 100,000 records. The returned range count and covered logical bytes describe only this query. A range can contain zero bytes.

The Windows 11 x64 VM passed all 22 focused tests. The sparse native fixture produced 1,025 allocated ranges across multiple requests and a complete full report. The preceding diagnostic run isolated the failed reopen flag. Ubuntu and macOS each passed 19 portable decoder tests, with two native NTFS fixtures skipped. See `.tmp/filecat-record-ntfs-ranges-qualified.xml`, `.tmp/filecat-ranges-reopen-probe-results.log` and `.tmp/record-ntfs-ranges/results.xml` in each portable checkout. Hard-link name acquisition and wider architecture and provider qualification remain open.
