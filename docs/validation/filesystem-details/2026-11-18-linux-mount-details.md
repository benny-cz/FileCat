# Linux file-system type from the held item

File-system details looks up the mount ID reported by `statx` on the live `O_PATH` descriptor. It checks the process mount table on procfs and requires the same mount ID and device number before it reports a volume-scoped type. A missing, oversized or inconsistent observation has an explicit unavailable state. The summary uses a bounded mount-table read and opens neither the item's payload nor a raw volume. [Linux statx](https://man7.org/linux/man-pages/man2/statx.2.html). [Linux process mount table](https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html).

On the Ubuntu 24.04 x64 VM, the fixture put a symlink on ext4 pointing into procfs. Details for the symlink reported the host mount, while details for a file accessed through that directory alias reported `proc`. The run also exercised the existing FIFO no-payload case and the opt-in ext4 FIEMAP fixture. There were 21 passes and one Darwin-only skip. The VM receipt is `~/FileCatValidation/details-92d52654.zR6HolZy/src/tests/FileCat.Core.Tests/TestResults/linux-bound-mount-details-final.trx`.

## ZFS mounted dataset and filesystem accounting

On Linux x64, the metadata-only full report uses the mount ID and device of the held `O_PATH` descriptor to obtain the OpenZFS source and case mode from the corresponding mount-table row. It restores spaces escaped by OpenZFS when displaying the dataset name. A separate `fstatfs` on the same descriptor checks `ZFS_SUPER_MAGIC` and validates total, free and caller-available block counts and the allocation unit before converting them to bytes. The counters describe the filesystem as seen from the item and can reflect quotas and pool space. The summary omits the dataset section. The collector issues no payload read or ZFS management call. [OpenZFS mounted source and options](https://github.com/openzfs/zfs/blob/zfs-2.4.1/module/os/linux/zfs/zpl_super.c)

Ubuntu 24.04 x64 kernel `7.0.0-43-generic` with OpenZFS kernel module `2.4.1-1ubuntu5.1` ran the fixture as a standard user. A case-sensitive outer dataset had a case-insensitive, AES-256-GCM encrypted child named `child space`. The two read-only fixture mounts reported distinct totals of 201,326,592 and 50,331,648 bytes. FileCat matched independent `fstatvfs` counters for both roots, both files and a parent symlink into the child. The child file denied an ordinary data open. A leaf symlink kept its source inspection scope. The test also confirmed the differing lookup behavior and exact displayed dataset names. The Core run passed 55 tests with eight opt-in or platform skips. The owned pool was exported. The controls and `zfs-details.trx` are under `~/FileCatValidation/filecat-zfs-details-846814b7-test-r2`.

Dataset compression, encryption and key status still need a property join bound to the held dataset. On the tested module `FS_IOC_GETFSUUID` returned `ENOTTY`, and the runtime `fstatfs` IDs differed from the persistent dataset GUIDs. OpenZFS supports renaming a mounted dataset without remounting it, so a name alone does not establish that join. FileCat leaves these properties uninspected. The probe is `~/FileCatValidation/filecat-zfs-details-846814b7-probe/results.log`. [Linux filesystem UUID ioctl](https://github.com/torvalds/linux/blob/v7.0/include/uapi/linux/fs.h) · [OpenZFS rename](https://openzfs.github.io/openzfs-docs/man/v2.0/8/zfs-rename.8.html)

The follow-up confirmed that the installed Ubuntu module is still 2.4.1 and that the upstream 2.4.4 Linux mount path also lacks the pool-and-dataset UUID export. The OpenZFS development branch documents a candidate join using both GUIDs from the superblock. A released environment that returns them can be tested with a read-only property query, including mounted renames, missing device access and mismatched GUIDs. The candidate must establish that the property response belongs to the held dataset before FileCat can report it. [OpenZFS 2.4.4 mount implementation](https://github.com/openzfs/zfs/blob/zfs-2.4.4/module/os/linux/zfs/zfs_vfsops.c) · [Development UUID contract](https://github.com/openzfs/zfs/blob/master/man/man7/zfsprops.7)
