# Recovering an EFS file with a restored key under a second account

The Windows 11 x64 VM used two fresh standard accounts with separate loaded profiles. The owner encrypted a synthetic file with an unnamed and a named data stream, then exported its sole newly created EFS certificate and private key using Windows. The second account received access denied when reading the file's data. After Windows imported the fixture PFX into the second account's `CurrentUser\My` store, the test verified the exact certificate thumbprint, private-key presence, and access to both streams.

The second account submitted decryption through the FileCat EFS review and job executor. The job completed with one observed native call and no setup or key prompt. The journal recorded the change from encrypted to clear and ended normally. The original file identity and both exact payloads were preserved. The account's different SID stayed explicit throughout the test. FileCat received only the selected file and its reviewed action. Windows handled backup creation, passwords and import through the isolated fixture controller.

The xUnit case passed in 1.41 seconds with no skips. The controller removed the disposable PFX and disabled both newly created accounts. The VM and workspace `.tmp` receipts are indexed by run `c98cad54d5354b84a676bb29b9ce43aa`. This independently verifies recovery for the tested software key. The interactive wizard, managed recovery agents and hardware providers have separate qualification requirements.

## Native ARM64 first use and independent restore

On Windows 11 Enterprise ARM64 build 26200, the hosted fixture used two newly created standard local accounts with loaded profiles and 4 KiB NTFS. The owner started with zero EFS certificates. Refusing setup preserved that empty state. Explicit setup created an actual association with a freshly matched key and removed the verified empty setup file. The owner then encrypted a synthetic file with a named data stream and exported its sole private EFS certificate through Windows. [Run and per-case XML receipts](https://github.com/benny-cz/FileCat/actions/runs/44506429572)

The second account could read the ordinary ACL control. Before key import FileCat refused the encrypted control without a native mutation call, and Windows denied a direct read of the separate recovery source. After the exact PFX import, the second account decrypted the recovery source through FileCat's review and executor. One observed call changed the state from encrypted to clear, with no setup prompt. The source identity, unnamed bytes and named-stream bytes matched. `first-use.xml`, `no-key.xml` and `restored-key.xml` each recorded one executed pass and zero skips. The source commit was `b434a190b760b1d202e7e25ad383d4cb5d297cf3` and the test assembly SHA-256 was `842907A9B9915E833719ACDC7536D21FE1F88755FD7DE765170B090072DDA3C9`.

## Native ARM64 managed recovery policy

The disposable Windows 11 Enterprise ARM64 runner on build 26200 applied a local Group Policy with one public data recovery certificate. The fixture verified the effective certificate and recovery record before encryption. A new standard owner account accepted FileCat's recovery declaration for its freshly matched ordinary EFS key. The Encrypt job recorded that same user key after its native call. An independent Windows certificate query confirmed that the distinct policy recovery agent was also attached to the encrypted file. [Windows EFS Group Policy](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-gpef/07431794-db1c-42f5-b198-77a9e603d86c)

A second standard account could read the clear ACL control. Windows denied its read of the encrypted file until it imported the exact recovery-agent private key. The Decrypt job then completed one observed native call, with no encryption-key approval. The original file ID and both complete payloads matched before and after decryption. The controller completed its policy and temporary private-key cleanup without errors. This qualifies the tested software recovery agent on ARM64. ## Windows x64 managed recovery policy
