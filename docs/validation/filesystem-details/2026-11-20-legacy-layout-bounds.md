# Windows legacy layout inventory bounds — 20 November 2026

The older direct `WindowsFileRecords.Read` report still exposed a layout section outside the newer metadata-only `ReadFull` route. Its extent loop could retry a header-only `ERROR_MORE_DATA` response without advancing, and its sparse-range loop could accept malformed or capped output as a complete byte count. This change routes both through the existing bounded, validating collectors. Incomplete extent observations show only a validated prefix and its reason; they no longer infer a complete fragment or resident-file result. An empty complete mapping also no longer guesses that a nonempty file is resident in its MFT record or that a directory index is inline. Sparse observations report an incomplete inventory rather than a stored-byte total. The sparse query now reopens the held object by handle instead of resolving its pathname again. Complete range counts are described as allocated byte ranges; they do not claim nonzero content or physical savings.
