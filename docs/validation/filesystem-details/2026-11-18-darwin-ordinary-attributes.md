# Darwin ordinary attributes on a compressed APFS file

The Apple silicon Mac extracted an owned archive with `/usr/bin/tar --hfsCompression`. The APFS file reported the `compressed` flag, a logical length of 2,350,000 bytes, and 24 allocated 512-byte blocks. The uncompressed source reported the same length and 4,592 blocks. The native control issued size queries only. It found `com.apple.decmpfs` and `com.apple.ResourceFork` with `XATTR_SHOWCOMPRESSION`, while ordinary no-follow queries omitted both. [Darwin extended-attribute options](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/xattr.h)

FileCat's ordinary view reported zero ordinary attributes and resource forks for that path observation. A request for compression backing shows that it was not inventoried. An ordinary-only request shows that it was not requested. Both observations remain partial and expose no bound value actions. Apple describes `O_EVTONLY` as an event-monitoring open. A bound compression-visible reader still requires independent selection, device and provider qualification. [Darwin open manual](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/open.2)

All 10 supplementary-data tests passed on the Mac. Ubuntu x64 passed nine tests and skipped the Darwin-only fixture. Exact results are `darwin-ordinary-xattrs-mac.xml` and `darwin-ordinary-xattrs-ubuntu.xml` in the native `.tmp` locations.

The Apple silicon Mac also ran a standalone resource-fork fixture. The test wrote a 24-byte fork through `..namedfork/rsrc` on an otherwise fresh APFS file. FileCat observed one resource fork with its correct length and zero ordinary attributes. It displayed `1+` because the pathname observation has no lifetime binding, kept the role unqualified for deletion, and issued no value query. The same run verified the ordinary view of a newly compressed 3,000,000-byte fixture. Nine supplementary-data tests passed with one Linux-only skip. The Mac receipt is `FileCatValidation/ci-fix-3877f7ef/tests/FileCat.Core.Tests/TestResults/darwin-fork-inventory.trx`.

## Event-only descriptor probe

On the Apple silicon Mac, `open` with `O_EVTONLY | O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC` returned a descriptor for an owned compressed APFS file. `flistxattr` with `XATTR_SHOWCOMPRESSION` exposed both compression records and the size-only `fgetxattr` query returned 16 bytes for `com.apple.decmpfs`. The ordinary descriptor inventory returned zero names. A one-byte content read succeeded on that same descriptor.

The same flags also opened an owned FIFO as a reader. A separate `open` with `O_WRONLY | O_NONBLOCK` returned `ENXIO` before the event-only open and succeeded while the event-only descriptor was held. The observed FIFO side effect rules out this recipe for acquiring a metadata-only descriptor after a pathname check. The bound compression-visible route still requires a same-object acquisition that excludes special-file opens. The local probe log is `.tmp/filecat-darwin-event-open-probe.log`. [Darwin open manual](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/open.2), [Darwin vnode open implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/vfs/vfs_vnops.c).

On 20 November 2026, a separate arm64 macOS 27.2.1 probe on the APFS Data volume used `O_EVTONLY | O_NOFOLLOW | O_CLOEXEC` on an owned ordinary file. The descriptor passed `fstat`; `flistxattr` returned 18 name bytes; `fgetxattr` returned the 21-byte value of `com.filecat.probe` from that descriptor. This establishes that the ordinary descriptor can read an attribute value, beyond the earlier size-only check. It does **not** make pathname-to-descriptor acquisition safe against the FIFO replacement demonstrated above. FileCat's Mac inventory remains observational and its bound value/report actions remain unavailable. The disposable file was removed after the probe. The ignored local receipt `.tmp/mac-xattr-evtonly-20261120.log` has SHA-256 `3A9F7D9CD3AD31E3E104E1025052FF89A5371E501C9BF19B453D6D2A7AC1CEE2`; the probe source and runner are in the same `.tmp` directory.

## Open-by-ID and event-descriptor policy

On macOS 27.2.1 arm64, the test obtained the filesystem and object IDs of an owned regular file. Apple's system Python opened the exact object with `openbyid_np`. The same request from the ordinary .NET process at effective UID 501 returned `EPERM`. XNU admits platform binaries or callers with its private open-by-ID entitlement. The event-descriptor read/write policy returned `EINVAL` at thread scope and `EPERM` at process scope. These paths leave the bound compression-visible route unqualified for FileCat. See `.tmp/filecat-darwin-bound-attributes-40e51441.log` and `.tmp/filecat-darwin-openbyid-40e51441.log`. [XNU open-by-ID admission](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/vfs/vfs_syscalls.c#L5122)
