# Sparse files through the held compression job path

The Windows compression candidate now reviews ordinary sparse regular files on qualified local NTFS. For each requested change, it captures the sparse flag, EOF, allocation and reported range union on the same main-stream mutation handle used for compression. It reads at most 4,096 records in one 64 KiB query. Adjacent records are coalesced and allocation-boundary rounding is clipped at EOF. Failed, malformed and incomplete queries refuse the change before issuing compression. A no-op needs no range inventory.

The held preparation and pre-call observations must agree. After the native call, the adapter compares the sparse flag, EOF and range union. If the layout changed or cannot be established, it records an uncertain result and stops for review. Native compression can change allocated bytes within the same ranges. FileCat issues neither sparse-flag changes nor zero writes to make the transform succeed. Compression remains scoped to the main stream and does not enumerate named streams. Existing EFS and file eligibility checks still apply.

The Windows 11 x64 VM used NTFS with 4,096-byte allocation units and ran as a normal user. The actual review, job, journal and held-handle pipeline passed compress and remove-compression for five 4 MiB fixtures. These covered an all-hole main stream, main-only holes, named-only holes, holes in both streams and a sparse main stream with no holes. The test observed both streams' full payload hashes, identities, EOFs, range maps and allocations. Two additional jobs per fixture verified that already-satisfied states produced no call record. A real 4,097-range file refused compression before any native intent, and the remove-compression no-op succeeded without inspecting the inventory.

The first combined run passed 34 cases and failed three during overlapping job admission and teardown. The shared accounting budget scans previously registered journal roots. The job-executor, evidence and sparse job fixtures now share one xUnit collection so one fixture cannot remove its journal directory during another fixture's scan. The initial XML is retained at `.tmp/filecat-sparse-compression-jobs-tests.xml`.

The final run passed 54 cases with zero failures across the sparse, inspection, traversal, job and evidence classes. The optional FAT/exFAT evidence export case was skipped because its fixture was absent from this run. Detailed observations are in `.tmp/filecat-sparse-compression-jobs-final-tests.xml` and `.tmp/filecat-sparse-compression-jobs-final-results.log`. The release gate still needs wider mutation, sparse race, large-file and output qualification. The EFS adapter's per-stream sparse preservation remains separate work.
