# Parented EFS private-key backup

The Windows adapter opens the backup wizard only after an explicit request for an exact certificate from the invoking user's observed EFS associations. It looks up that certificate in CurrentUser My and hands Windows a fresh certificate context after a silent, no-healing comparison of the actual private key. The wizard requires a visible owner in the current process, requires private-key export and disables private-key deletion. The application supplies no backup filename or password. [Microsoft's CryptUIWizExport API](https://learn.microsoft.com/en-us/windows/win32/api/cryptuiapi/nf-cryptuiapi-cryptuiwizexport).

Only a successful Windows result provides backup evidence. That evidence identifies the observed object, invoking SID and certificate. The recovery approval accepts it only for the matching actual setup association and binds it to the reviewed encryption scope. Cancel produces no completed backup evidence. A user-declared recovery arrangement remains a separate choice. The application does not read the backup or verify recovery from it.

The final Windows 11 x64 VM run passed 20 tests with zero failures. Three cases were skipped because they cover unqualified hosts, new accounts or deliberate default-key rotation. Both wizard cases used an exportable key from the VM's normal user's actual zero-byte EFS setup. Clicking Cancel returned `ERROR_CANCELLED` and produced no PFX. Completing the parented wizard returned success. The test confirmed that the PFX contained the exact reviewed certificate and its private key using ephemeral load, then verified that the original key was still accessible. Only the disposable qualification test supplied a password and read its own synthetic PFX.

The earlier test driver missed Windows' success popup because its title differed from the supplied wizard title. A second run reached the popup and timed out because the generic command did not activate its actual OK control. Window inspection confirmed the native success message. The final driver activates that control and also handles a direct native return. Evidence is in `.tmp/filecat-efs-backup-wizard-c-tests.xml` and `.tmp/filecat-efs-backup-wizard-c-results.log`.

This qualifies the held application adapter and the software-key wizard path on the supplied Windows VM. The product EFS dialog, key decision orchestration, interactive hardware providers, wider native coverage and durable execution integration remain open.
