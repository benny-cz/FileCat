# Read-only Btrfs properties on Linux x64

**Read full record** shows the containing subvolume ID and the inode's compression policy for ordinary files and directories on Btrfs. FileCat resolves the file-system type from the live `O_PATH` descriptor and mount ID. When the inode device number differs from the mount table's device, an additional `fstatfs` on the held descriptor must confirm Btrfs. The full report reopens the same pinned object through procfs and checks type and identity before the native queries.

The subvolume query uses `BTRFS_IOC_INO_LOOKUP` in its unprivileged ID-only form with tree ID zero and object ID 256. The Linux x64 fixture's headers gave request `0xd0009412` and a 4,096-byte structure with tree ID, object ID and name at offsets 0, 8 and 16. The compression query reads the kernel's fixed `btrfs.compression` property into a 16-byte buffer and recognizes only exact documented values. A missing property, explicit disablement and a denied query each have distinct wording. The report describes directory policy for new entries and file inode policy separately. Existing extent compression and mount-wide defaults are outside that policy observation. [Btrfs ioctl contract](https://btrfs.readthedocs.io/en/stable/btrfs-ioctl.html#btrfs-ioc-ino-lookup) · [Btrfs inode properties](https://btrfs.readthedocs.io/en/latest/btrfs-property.html#inode-properties) · [Linux kernel property handler](https://raw.githubusercontent.com/torvalds/linux/master/fs/btrfs/props.c).

The Ubuntu 24.04 x64 VM ran kernel `7.0.0-43-generic`, glibc 2.39 and btrfs-progs 6.6.3. A normal user inspected a new 256 MiB loop-mounted image with a zlib default and a nested subvolume. The mount table reported device `0:76`, while `stat` reported devices `0:77` and `0:78` for the tested inodes. FileCat reported the same top-level and nested IDs as `btrfs inspect-internal rootid` (5 and 256). It distinguished an absent inode property, a zstd directory policy and its inheriting file, lzo, zlib, explicit `none`, and access denial. A symbolic link and FIFO produced no property section.

The traced native fixture passed. The summary and full reads together made seven ID-only ioctls, seven fixed-property queries and zero payload reads on fixture files. The independent positive control made one payload read. Ubuntu passed 22 focused tests with two skips for separate ext4 and FIEMAP fixtures. macOS passed 19 with five Linux-only skips. The Ubuntu receipts are `FileCatValidation/ci-btrfs-6eea2ee8/tests/FileCat.Core.Tests/TestResults/btrfs-native.trx` and `btrfs-details.trx`, and the syscall traces are in `FileCatValidation/btrfs-fixture-DfGmU9`. The image was unmounted after the tests. This receipt qualifies Linux x64 on the tested kernel and filesystem. Other F7 adapters and architectures have separate gates.
