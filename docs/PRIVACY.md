# FileCat privacy policy

FileCat is a file manager that runs on your device. It does not require a FileCat account or send usage analytics to a FileCat-operated service. It stores settings, workspaces, history, job records, caches and diagnostic logs locally in the selected profile's application data (or the portable data folder). Local logs hash the paths FileCat records by default, although an error message from the system can still name a file. If you enable diagnostic mode, selected paths can appear in the local log.

FileCat connects to network locations when you use its remote or network-browsing features. Files and credentials you choose to send to those locations are handled by the selected server and its operator. Saved connection secrets use the operating system's credential store when available, with a session-only fallback where it is not. FileCat does not put passwords in its settings file.

Automatic update checks are on by default for new profiles and can be turned off in **Settings → Privacy**. A saved off preference stays off. When FileCat starts and its last completed check is at least a day old, it asks the GitHub releases API for FileCat's newest release and sends its version in the HTTP User-Agent. A check counts as completed even when it fails offline or times out. A check still running when you close FileCat does not count, so it is made again at the next start. A newer version opens the same release dialog as **Help → Check for updates**, with an option to skip that version in future automatic checks. Manual checks still show skipped versions. Offline or timed-out automatic checks stay silent and never hold up startup. The check only reports availability; it does not download or install an update. GitHub processes these requests under its [privacy statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement).

**Tools → Export diagnostics** creates a local ZIP for you to preview and share yourself. It includes environment details, your settings in plain text without stored credentials (they name saved server hosts and user names, key-file, start and tool paths, and ignored folders), and local logs or crash reports where available. It does not include file contents or credentials. Error messages and crash reports in it keep the system's own text, which can name a file. If diagnostic mode is enabled, exported logs may include selected paths. FileCat does not upload the ZIP automatically.

You can remove FileCat's locally stored data from its profile or portable data folder. For a privacy concern, use the repository's [private vulnerability reporting](../SECURITY.md) when disclosure would expose sensitive information, or open a [GitHub issue](https://github.com/benny-cz/FileCat/issues) for a general question.
