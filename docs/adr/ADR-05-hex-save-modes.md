# ADR-05 — P4b fixed-length hex save modes

**Decision.** Windows local files open with a read/write handle that denies ordinary write and delete sharing for the entire edit session. A sparse overlay allows only fixed-length replacements, with an 8 MiB touched-byte and 32 MiB undo-data budget. The existing-file save mode is explicit journaled in-place writing: a user-local, checksummed record of original and replacement ranges is flushed before the first target write. Each range and the target are flushed; read-back verifies the result. Restart offers guarded resume or rollback only when the full 128-bit file ID, volume ID, length, and each current byte match a journaled state. Save As creates a new target, and patch export records exact ranges without changing the source.

**Why.** The protected baseline excludes ordinary concurrent writers from the start of editing. In-place writes preserve file identity, hard-link aliases, ACLs, alternate streams, and allocation semantics. A sibling replacement could be more atomic for small files, but its identity, hard-link, sparse, stream, and security effects need an independently validated preservation policy. It is deferred rather than exposed with an implied guarantee. Network paths and file links are read-only in this mode.

**Limits.** A sequence of range writes is not atomic or power-loss-proof. Raw-device writers can bypass sharing. Save As may use substantial space and creates a new file without the source's ACLs, streams, or sparse allocation. The editor does not insert or remove bytes. Recovery refuses an unrecognized target or unrelated byte change and keeps the journal. Original bytes in recovery records live under the user's local application-data directory, including in portable mode.

**Evidence.** Automated tests cover multi-terabyte synthetic offsets, range overlap and undo/redo, write-sharing denial, new-file Save As, journal interruption before and after a write, guarded resume/rollback, unrelated-byte rejection, corrupt journals, and a headless editor smoke. TV-04's sparse/non-sparse, mapped-file, disk-full, process-kill, and hardware checks remain external release gates.
