## Execution rules

1. Select the highest-priority **Failed** or **Open** row whose dependencies are available. A Blocked row is not executable until its named dependency changes.
2. Record the exact producer and stopping condition before a repeat. Historical tests are not rerun to reconstruct status.
3. After a slice, update the affected ledger row and report accepted, reopened, newly required and blocked cases. Add chronology only to the activity log and evidence only to the evidence index.
4. Preliminary component/native acceptance remains distinct from REL-FQ-CANDIDATE. Stable publication remains REL-GO-PUBLISH and requires explicit human GO.
