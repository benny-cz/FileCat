# E-I530 — Unix saved-state FIFO startup admission

FileCat automatically loads settings, history, the window layout and working sets through `JsonFileStore`. On Unix, the old `FileStream` open could wait indefinitely if a same-user saved-state pathname was replaced with an unwritten FIFO. The same store reopened damaged state for preservation and wrote to a fixed `.tmp` pathname; a crash-left FIFO at that path could block saving as well. The I530 change opens saved input nonblocking and accepts only an opened regular-file descriptor. An unavailable primary or backup is shown from a safe backup or defaults as read-only, with a visible status, and is not preserved or overwritten. Saves refuse nonregular state/backup paths and use a fresh exclusive owner-only temporary sibling.

The bounded original-product Mac comparison used the old Core DLL from the retained `09a47bbe` native payload with the six-case new test assembly. Its no-writer FIFO case exceeded an external **8.026-second** deadline; no result XML was produced. The `JsonFileStore.cs` Git blob is unchanged between that payload's source and the immediate parent `e7aaddba`, retained in the private record. The timed-out test left one owned temporary FIFO; its type and backup hash were checked, then that exact fixture was removed. This timeout is a failed baseline, not a passing test.

With the corrected Core DLL, native Mac ARM64 and Ubuntu x64 each pass the **six FIFO cases** and the surrounding `PathAndStateTests` **17P/1 explicit skip/0F**. The cases include direct and linked primary FIFOs, a FIFO backup after damaged primary, refusing primary/backup FIFO saves, and ignoring a crash-left fixed `.tmp` FIFO. The exact later combined I530/I531 source was republished and independently repeated on both native systems with the same **6P + 17P/1S/0F** results. The final Mac and Ubuntu Core package SHA-256 values are `412d697b823c24cf6c9a380bfd99db2154fcf2f433ce0388cd43961b29a233b0` and `340ba568fa3b00cfa82689fadc3676bd6b310679df4914c37a8cbd37b39e9053`; their owned stages are verified absent. On Ubuntu 26.04.1, the earlier self-contained App opens a visible main window in the ordinary-user GNOME session despite an unwritten portable `Data/settings.json` FIFO; after eight seconds its owned process is alive in `ep_poll`, the FIFO is unchanged, and the process and both guest stages are removed. A retained guest capture shows the window. It is a portable native startup check, not installed-candidate acceptance.

Windows' first focused attempt failed two pre-existing state tests because the initial cross-platform implementation assigned `FileStreamOptions.UnixCreateMode` on Windows. That was corrected; the failed raw log/TRX remain. The first complete Windows App run then exposed one more regression: a fixed `.tmp` directory previously forced the failed-save notification, but the new randomized temporary filename bypassed it. That full run **failed 1,661P/55S/1F** after 13 minutes 24 seconds; it remains failed in the archive. The final implementation keeps Windows' original fixed temporary-path and overwrite behavior while using the fresh exclusive sibling only on Unix. Its state-save fixture blocks the destination on Unix and preserves the old Windows control. Final Windows focused Core passes **17P/7 explicit skips/0F**, affected App **28P/25S/0F**, complete Core **4,155P/150S/0F**, and complete headless App **1,662P/59S/0F**.
