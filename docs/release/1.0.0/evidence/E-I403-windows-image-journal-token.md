# E-I403 — Windows image change time missed a rapid in-place rewrite

2026-10-12 CEST. **Preliminary Windows regular-image correction at `2e1673f797bd2e29e064804f528cc7b46d94b2ce`; I106/I110 physical-source HOLD remains.** No candidate exists.

The [exact I401 original-push CI](E-CI-I401-held-recovery-image-reader.md) failed two Windows ARM64 Core cases: a same-path, same-identity, same-length image had been fully rewritten and mtime restored, but I400 returned the old deleted-file catalog and I401's held reader returned replacement bytes without refusing. That run retained raw 28,624 passes/914 skips/two failures and three unavailable ARM64 downstream inventories. No later result rewrites that run as green.

The I400 Windows token used `FILE_BASIC_INFO.ChangeTime`. The correction queries `FSCTL_READ_FILE_USN_DATA` on the read-only opened file handle and parses positive USN record v2/v3 values, combined with ChangeTime. A zero, malformed or unavailable journal result falls back to ChangeTime rather than being treated as proof of an unchanged file. On an active-journal NTFS host volume, the USN changed during the rapid owned rewrite even when the change-time component did not; the Windows VMware control also records a changed USN with the same identity and restored mtime. An inactive-journal host volume returned USN zero and exercised the fallback. The system call is documented by Microsoft: [FSCTL_READ_FILE_USN_DATA](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_read_file_usn_data), [READ_FILE_USN_DATA](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-read_file_usn_data), [USN_RECORD_V2](https://learn.microsoft.com/en-us/windows/desktop/api/winioctl/ns-winioctl-usn_record_v2), [USN_RECORD_V3](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-usn_record_v3).

The first stronger-token focused run safely refused two post-write image opens while the journal advanced between path and handle observations; its **two failures** are retained in `usn-corrected-focused.trx` and the raw log. The final three affected tests use a bounded maximum of three fresh listing requests after only a changed-image `IOException`; each still requires the replacement catalog/content and never accepts stale bytes. Final exact host focused **23P/0S/0F**, full Release Core **4,033P/105S/0F**, and solution build zero errors pass. The same hashed payload passes all **23/23** focused controls on Mac, Ubuntu VM and Windows VM. Windows VM I400/I401/I402 records include changed USNs, same file identity/restored mtime, fresh `_THER.BIN`, held-read refusal, scan refusal with zero published names, and cleanup.
