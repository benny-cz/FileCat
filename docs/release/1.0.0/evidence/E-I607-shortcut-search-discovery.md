# I607 — shortcut editing was absent from Search commands

**2026-11-01 · Medium UX · reopened after owner retests of `5c0a9730` and `44ca270e`; revised chooser at `e2a0b173`; owner workstation retest and final candidate open.**

## User consequence and scope

The owner searched for “change shortcut” and found no command. The existing editor was reachable through F1 → Keyboard reference → select the target command → Change shortcut, but Search commands had no matching synonym or useful direct result. The owner also tried `Ctrl+Alt+H` after an earlier isolated exploratory shot. That chord was assigned only temporarily in the disposable VM to **View as hex / alternate viewer** and then reset; its default is `Alt+F3`. No `Ctrl+Alt+H` binding was shipped or added by this correction. The Ctrl+Alt+letter family is avoided for defaults because it can act as AltGr on European keyboards.

## Adjacent command coverage

The actual command search takes its entries from the command registry. It excludes only platform-inapplicable commands, numbered bookmark bindings handled by the bookmark list, and column-profile slots without a saved profile. A focused App test enumerated every applicable main-menu command and confirmed that the search contains exactly one entry for it and finds it by its displayed name. The normal native Keyboard reference showed **167 of 167** commands; the dedicated remap chooser correctly excludes its own launcher. Focused command-search, shortcut-editor and reference controls passed **36/36** at `e2a0b173`, including exact title ranking in the top field and palette, F1 filtering, Enter-opening edit mode, no self-entry in the remap chooser, and existing shortcut capture. This is menu/registry coverage, not a claim that every possible colloquial phrase is indexed.

## Stopping rule

The owner confirmed the result in all three search surfaces but found the prior chooser confusing. Keep I607 open until a rebuilt `e2a0b173` or later workstation app can follow Search commands or F1 → **Change shortcut…** → select a different command → key-capture dialog without another reference loop. Final 1.0.0 acceptance additionally requires that route and a target-command key edit in the frozen installed candidate, plus its source CI producer, Windows x64, Windows ARM64, Ubuntu and macOS lanes with skip reconciliation. Public unsigned preview.5 predates this change. Stable 1.0.0 remains NO-GO.
