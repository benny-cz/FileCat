# I624 — Picture grid thumbnail stability

**Status:** Remediated preliminarily at product commits `b8a5d24a` and `44f8c7da`; exact-source main and tagged CI passed, while installed 1.0.0 candidate qualification remains open. **Severity:** Medium UX and resource use. **Owner observation:** opening a folder with many photos in Picture view repeatedly reloaded thumbnails and visibly blinked; scrolling the owner's OneDrive photo folder also caused long waits and apparently missing pictures.

## Finding and correction

The grid cleared every decoded thumbnail on each listing refresh, including an unchanged watcher or manual reread. It also kept at most 64 cached entries while a large viewport could demand more than 64 visible tiles. Its render pass recorded only *uncached* thumbnails as visible demand; once an image appeared, the cache considered it offscreen and could evict it on the next completion. These paths caused repeated decoding and redraw without a changed picture.

The first correction retains a thumbnail across an unchanged listing refresh, using item identity, size and modification time as its revision key. It includes cached visible pictures in demand and never evicts a visible tile. Leaving Picture view or navigating to a different tab/location still retires that view's cache. A changed file revision requests a new decode.

The owner's later folder exposed a second cause. Of its 297 JPEG entries, 212 carried Windows' Offline attribute. The old grid attempted automatic content reads for those OneDrive placeholders, even though Quick view already refuses automatic cloud recall. That could stall thumbnail slots and leave ordinary file icons while it waited. The corrected grid does not automatically read offline content; it displays **Online only / Open to download** so the missing image has an explanation and opening it remains the user's explicit choice. For available files, the decoded cache now holds up to 512 answers or 96 MiB of pixel data per grid, with visible tiles protected even at the limit. This keeps this album's 85 locally available photos warm across scrolling. Larger albums remain bounded and may reread evicted offscreen entries; no unlimited cache or automatic cloud hydration is claimed.

After correction, all **65/65** settled in about six seconds; ten redraws and an unchanged listing refresh kept exactly **65** loads. Changing one BMP and its modification time led to exactly **66** loads and again **65** cached visible pictures. Both Picture-grid rendering tests pass **2/2**. Existing App Picture-grid tests pass **2/2**, including archive-provider thumbnails and ordinary file/folder rows.
- An isolated macOS ARM64 checkout at base `951caad6` plus the exact two corrected control files was built with the pinned .NET SDK `10.0.101`. Three consecutive Ctrl+R rereads started **zero** new `--picture-worker` processes. Changing one photo's bytes and time started **one** worker, and the subsequent unchanged reread started **zero**. The exact test process exited and all three disposable Mac test paths were removed. The diagnostic build and fixture were separate from release packages. Screen capture was unavailable from the remote session, so this native result establishes accessible grid continuity and worker activity, alongside the headless bitmap stability check, rather than a pixel-level visual comparison.

## Candidate acceptance and stop rule

On the exact installed 1.0.0 candidate, open a folder with more visible pictures than the ordinary cache limit on a large viewport. After tiles settle, redraw, wait for an unchanged watcher event and press Reread: visible thumbnails must stay drawn without new decodes or blinking. Change one owned picture's content and modification time: that tile alone must update. Scroll away and back across an album larger than 64 locally available photos without redecoding those still within the 512-entry/96-MiB cache. Include offline placeholders: they must remain listed and labeled without background content reads, and opening one must be an explicit action. Reconcile producer, Windows x64, Windows ARM64, Ubuntu and macOS CI results and the expected Unix-only skip against the preceding green source. Stop after these finite paths pass; reopen only for a demonstrated repeated visible reload, stale changed-file thumbnail, unwanted cloud recall or consequential resource regression. Existing preview.8 predates I624.
