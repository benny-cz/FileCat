# E-I516 — Linux mapped-volume recovery discovery and destination admission

The V09 two-VMDK stripe in [E-V09](E-V09-ubuntu-striped-vmdk.md) could be read and classified through native Core/Recovery components, but FileCat's Linux device list **excluded every `dm-*` and `md*` layer**. A mounted FAT32 stripe therefore could not reach the recovery chooser as a volume. At parent `30e76e70`, a new owned-sysfs regression failed **0P/1F**: `/dev/sdb` and `/dev/sdc` appeared, but `/dev/dm-0` did not. Its raw TRX retains the exact `Assert.Single` failure.

The correction offers a **mounted, supported file system** on a device-mapper or software-RAID layer as a volume, retaining the underlying disks as separate whole-disk choices. A mapped volume is not described or scanned as a single whole disk merely because it has no partition parent. Unmounted/unsupported layers remain outside this new chooser route; the wider V09 scope is still open. The accompanying mounted-drive advisory now refers to the operating system rather than Windows on Linux.

The synthetic Core regression covers a mounted `dm-0` FAT32 stripe, a mounted `md0` exFAT RAID volume, an unmounted layer that stays unoffered, unchanged underlying disks, mapped volume names, types and mount points. The App headless regression checks the mounted-volume classifier and its unmounted/unsupported contrasts. Final focused Core **12P/0F**, focused App **1P/0F** pass. A complete Core run before the final advisory wording and extra RAID assertion had **4,149P/142 explicit skips/0F**; the final-source focused repeat covers those subsequent changes. The exact-final complete App suite passes **1,653P/44 explicit skips/0F**, and the final production App project builds with **zero warnings/errors**. Its 14-minute-28-second run included a measured wait in the pre-existing Network-place deadline fixture; diagnostic stacks are retained without reclassifying the passing result.
