# E-I08-ENV — Unix picture-worker launch environment

2026-10-12 CEST. **Preliminary remediation; I08 remains open.** Earlier [current Unix controls](E-I08-current-unix-worker-boundaries.md) showed that the actual picture-worker launch inherited a synthetic parent environment marker on ordinary-user Ubuntu and macOS. The Unix launch clears the child's environment and supplies diagnostics refusal and its private parent-lifetime pipe identifier. A regression invokes the actual `PictureDecoder.Worker.Start` route with `/usr/bin/env`, supplies a unique parent marker, and verifies that the marker is absent. Framework-dependent apphosts also receive the root of the runtime already loaded by FileCat, derived from the runtime directory rather than copied from the parent's `DOTNET_ROOT`.

The Windows host built the App and test projects serially. The final incremental test-project build has zero warnings/errors; an earlier parallel build returned exit 1 during project-reference target-framework discovery with zero compiler diagnostics, followed by successful serial builds. That unexplained first result is retained. Source identity is `ab79d504e07a19d0830d40f32f51469b5fa11304` plus the declared product/test diff; this is **not** an exact committed or installed-candidate run. The working source, compiled platform payload members and prior native runtime members were pinned before transfer. The native controllers independently rehashed 86 Mac/85 Ubuntu payload members and 267 Mac/193 Ubuntu runtime files before and after testing.

On ordinary-user Mac arm64 and Ubuntu x64, each six-class picture/worker run reports **40 passes, zero failures, zero errors, zero skips**, including the new actual-launch environment check. The healthy viewer, picture admission/bounds, parent-lifetime and exited-root controls also pass. Native result archives were retrieved and independently matched byte for byte to their extracted members; the XML names/results and all payload hashes were independently audited. Both owned test roots and temporary directories were removed after output-hash and process checks. The first Mac controller stopped before any test because its system Python lacks `hashlib.file_digest`; its raw error/output and subsequent verified cleanup are retained. Ubuntu's first root-creation transport stopped before staging because VMware Tools stripped a quoted Python argument; the corrected command then passed. Neither failure is counted as a passing test.
