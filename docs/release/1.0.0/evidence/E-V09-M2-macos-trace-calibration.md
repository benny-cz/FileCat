## Primary source inspection

Apple's [formatter source at revision 408bba7](https://github.com/apple-oss-distributions/system_cmds/blob/408bba7453608006b89772db185defbac8fe2fd0/fs_usage/fs_usage.c)
distinguishes PID selectors and command-name selectors, and installs a dropped-event callback
that reports buffer overrun to stderr and clears its correlation state. Disk-I/O completion
events have separate process-filter handling; unrelated disk completions must not be confused
with selected syscall attribution.

The retrieved Git blobs and SHA-256 independently verify: C source
`a8a03a9cd1375740249ed513150ab6e78c8f791efd2186fe521ed59a6d052c81`, manual
`516b37f33b209156bb6ebffef63aa8f14c7c5b5c21535e09340ebb499dc8f97a`.
The manual is byte-identical to the installed manual. This does **not** establish that the
downloaded C source produced the installed binary. No downloaded Apple source is executed.
Source inspection guides controls; native observations must establish installed behavior.

V09 forbids any FileCat source write, so a future capture may be useful without positional
offsets only if operation, source FD/path, every process/child, lifetime and loss controls
independently qualify. That possibility remains unproven; this slice changes no release oracle.
