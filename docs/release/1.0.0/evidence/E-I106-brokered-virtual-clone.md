2026-10-12 CEST. **Preliminary virtual-only positive/refusal control at exact `095dadd3`; I106/I110 physical-source validation remains on HOLD.** This extends the earlier [direct/helper protocol and provider case](E-I106-broker-protocol-provider-clone.md) by calling the product `BrokeredDeviceSource.Open` API from an ordinary medium-integrity desktop process. The launched `FileCat.PrivilegedHost.exe`, plan validation, `ShellExecuteEx` `runas`, protected-folder check, requester-token/path check, custom consent dialog, named-pipe peer check and read protocol are the product implementations.

The requester was a **disposable test harness named `FileCat.exe`** placed with the exact-source helper in an administrator-protected folder inside the Windows 11 VMware guest. It was not the FileCat app UI or an installed release package. The guest's pre-existing UAC policy automatically consented to `runas`; a bounded high-integrity guest watcher mechanically clicked the helper's own custom dialog. The medium requester ran in session 1 and reported `Elevated=false`; the watcher ran in session 1 with `Elevated=true`. These observations qualify native launch mechanics in that VM, **not** a human review of consent wording, a standard Users-only account, the default UAC policy, or candidate installation.

After A detached, B mounted read-only at **the same disk number, length, Windows `UniqueId` and FileCat GUID** but a different present PnP interface. The original A interface was absent. Calling `BrokeredDeviceSource.Open` with the stale A selection made the actual helper refuse the plan: `Step 1: the device must be ... a present disk interface.` The probe recorded `PresentAtRequest=false`, `IOException`, no returned source and no read bytes. Inspection of the exact helper control flow places this refusal before `DeviceReadHost.Run`; it is not a kernel-level read trace. Freshly selecting B returned its new interface and repeated the same 4,096-byte hash and one recovery volume through the broker, excluding a blanket inability to read virtual disks.

The corrected script sorted by disk number; only its successful run supplies the clone result. Both VHD files had the original complete SHA-256 after the brokered runs and read-only detach. Cleanup found no active probe/helper process, restored the guest to its sole boot/system disk 0, removed the protected test folder, VHDs and package, and then removed the remaining named temporary scripts/results.
