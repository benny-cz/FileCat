# E-I424 — Unix held-device listing refuses a changed source path

2026-10-13 CEST. **Preliminary High source-correctness correction within I106; no physical-device or deleted-data-loss claim.** Exact preceding source is `8abc96904db1b2f5839a75dcb4872b2ed8aab45f`. `UnixDeviceSource` already held a read-only descriptor and could check that its selected path still named the same inode, but `RecoveryProvider` checked that guard only when admitting a recovery destination. A cached device listing reused the old scan without a path check; a warning callback could also change the path after scanning and before `AddBatch`. In both cases the old listing could be published after a different owned file took the selected path.
