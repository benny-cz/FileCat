# I623 — Picture browsing in the viewer and file panels

**Origin:** Owner-requested photo workflow on 3 November 2026. This is a feature, not a retrospective defect claim. The owner chose a thumbnail grid that shows folders and every file; supported pictures receive thumbnails. Space moves to the next picture in the same viewer, Backspace moves to the previous one, and both stop at the folder ends.

## Design and user outcome

- **F3 picture viewer:** A viewer opened from a panel retains a weak reference to that tab and its original folder. Space and Backspace use the tab's current visible, sorted order, skip nonpictures and folders, and replace the picture in the same window. The status line names both keys and reports a first/last boundary. If the source tab closes, leaves the folder, or hides the current item, browsing stops with a reason. A failed next image leaves the last good picture and its title intact; another press can continue past the failed candidate. PDF page keys and toolbar-button Space remain separate.
- **View → Pictures:** The active tab toggles between its ordinary virtualized file list and a thumbnail grid. The grid draws visible tiles from the same listing and preserves the same item identities, sort/filter, marks, keyboard focus, click/drag/context-menu paths and file commands. Its mode persists with the tab/workspace. Left/Right move one tile; Up/Down move by a grid row; Shift marking and accessibility peers retain their existing bounded selection semantics. Narrow panels reduce their column count and retain a vertical scrollbar.
- **Automatic thumbnails:** Only visible supported picture names are opened. Files over 64 MiB are not automatically decoded. A per-panel semaphore permits at most two thumbnail demands at once; the existing restricted picture worker has its own global admission and time/input limits. Cached decoded thumbnails are limited to 64 per panel and cleared on listing refresh, tab/mode switch and detach. Canceled late results are disposed. A file with no supported/usable preview remains present with a type icon/badge and can still be opened through F3. This uses each location's content provider, including archives and remote providers; the gallery never extracts an archive member to a durable local file merely to draw it.

The worker currently recognizes PNG, JPEG, GIF, WebP, BMP and ICO content. The automatic navigation extension set covers those formats and common name variants. Other formats, including HEIC, remain ordinary files in the grid; FileCat does not claim to decode them. A per-tab filter controls which pictures Space/Backspace can visit. This preserves the panel's visible sort and selection meaning.

## Remaining release qualification and stopping rule

Before accepting I623 for an installed 1.0.0 candidate, use exact final bytes on Windows x64, Windows ARM64, Ubuntu and macOS to: open a folder with two supported pictures, a folder and a nonimage file; toggle Pictures; verify thumbnails, selection/mark/drag/context actions, sort/filter and narrow-panel scrolling; F3 a picture and confirm Space/Backspace use one window and stop at both ends. Check one archive or remote provider on a supported candidate, a damaged picture retaining the previous good image, and a >64 MiB automatic-preview fallback. Reconcile five-lane CI and skips against the prior accepted source run. Stop once these finite paths pass. Reopen only for a demonstrated wrong item, lost operation, stale or misleading thumbnail, inaccessible content, or consequential cross-platform layout difference; do not re-run unrelated viewer/security cases without a new reason.

This source change is not an installed or signed candidate. Stable 1.0.0 remains NO-GO under its separate release controls.
