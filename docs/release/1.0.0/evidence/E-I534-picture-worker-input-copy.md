The same new eight-MiB synthetic stream test fails the old App assembly **0P/1F**: **25,166,352** thread-allocated bytes exceed its 20 MiB threshold. This is a transient worker-memory cost, not an established whole-process cap breach.

The worker now retains the bounded `MemoryStream` backing array and passes its exact logical segment to a length-limited `MemoryStream` for Skia; it does not copy the entire encoded picture. The input-size, source-pixel, output-size and timeout guards are unchanged.
