# E-I392 — pin automatic Unix keep-awake tools to system paths

2026-10-12 CEST. **High automatic-launch boundary, remediated preliminarily.** `PortableShellServices.SetKeepAwake` resolved `systemd-inhibit` or `caffeinate` from inherited PATH. Its Linux `systemd-inhibit` argument then named bare `sleep`, which the real inhibitor also resolves through PATH. An absolute PATH entry can be writable, even though FileCat avoids current-directory lookup. This only concerns FileCat's automatic keep-awake helper; explicitly configured external tools retain their separate behavior.

The disposable Ubuntu VM's real `/usr/bin/systemd-inhibit`, when authorized to inhibit sleep, ran a harmless owned `sleep` script from an absolute `/tmp` PATH entry and wrote its marker. An exact-current-source FileCat Core harness then called `SetKeepAwake(true)` with the same PATH: the marker was present, and the short-lived decoy made the inhibitor exit before the stop call. These are actual tool and product calls, not only a process-start plan. VMware guest operations run outside the interactive logind session, so the Linux inhibitor controls used local sudo; they do not establish ordinary-user polkit behavior. A separate real-inhibitor control observed one live sleeping child, then found it absent after killing the wrapper alone. It **did not** reproduce a residual child leak, and no process-tree change is attributed to this issue.

The correction selects automatic `caffeinate`, `systemd-inhibit` and the latter's `sleep` only from `/usr/bin` or `/bin`. If the required system tool is absent, keep-awake simply remains unavailable. The paired Ubuntu FileCat Core run with the same owned PATH has **no decoy marker**; its real inhibitor and one child are alive during the active period, and both are absent after `SetKeepAwake(false)`. The physical Mac arm64, running as ordinary user benny, likewise ignores an owned fake `caffeinate`, keeps the real system helper alive while active and stops it afterward. Both native packages and outputs match guest-side hashes. Full Windows Release Core passes **4,029/103 explicit skips/zero failures**; Release solution build reports zero errors and 41 existing warnings. Exact owned Mac and Ubuntu test roots are removed; known Linux probe PIDs are absent.

This resolves one demonstrated automatic PATH substitution. It does not prove a malicious payload was present, cover every indirect launch or path race, qualify ordinary-user Linux inhibition in the VMware Tools session, or constitute installed-candidate acceptance.
