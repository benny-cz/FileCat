# E-I527 — nonblocking Unix language-file admission

The automatic command-title loader already limited a language JSON file to 1 MiB after opening it. On Unix, opening `lang/cs-CZ.json` as a FIFO waited for a writer before that limit could run. The file can sit beside a portable executable or be reached through a symlink; a startup translation must not hold the application on a pipe.

At parent `094cd6bdaefbb8a4899a7f014041455fb5bd8f96`, a test-only Mac ARM64 payload with the unchanged product DLL opened an owned FIFO without a writer. The fully qualified xUnit case reached `CommandTranslations.Load` and the external eight-second controller killed its process group: **timed out, exit −9, no TRX**. Its product DLL SHA-256 is `bc279839256a69ac08e63890620a0e79661bcac77373f4dad256e061a6a11fc7`. An initial runner filter used only the short method name and selected zero tests; it is not counted as a product result. The corrected filter, raw log and timeout receipt are retained.

The loader now uses FileCat's nonblocking, opened-descriptor regular-file check on Linux and macOS. A FIFO or a symlink to one is refused with the existing English fallback; a regular language file retains the existing opened-handle byte bound and JSON behavior. Windows keeps its prior open route. The final command class checks both direct and linked FIFO names, a normal translated file, malformed input and oversized direct/linked files.
