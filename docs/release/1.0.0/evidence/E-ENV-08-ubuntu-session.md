# E-ENV-08 — Ubuntu guest desktop response after upgrade Welcome screen

On 2026-10-14, the owner reported that the authorized Ubuntu VMware guest's UI did not work and authorized restoration to its last working snapshot if needed. Background VMware operations found the Ubuntu 26.04.1 GNOME desktop showing the post-upgrade Welcome window. The `gnome-initial-setup --upgrade-user` process was stopped in the disposable guest; no snapshot was reverted. Files then opened in the existing guest session. A guest-only synthetic `/dev/uinput` tap also closed and reopened Files, and a later background capture still showed the ordinary desktop. Diagnostic windows and owned probe files were closed or removed in the guest.

The private `V:\FileCat\artifacts\release-evidence\ubuntu-ui-session-20261014-v1` archive retains eight chronological VMware screen captures and the input-probe source. All nine inputs rehash against `manifest.json`, whose SHA-256 is `4fa81102e2660b47354241673fdb23913eec0fb7d17091d8cde15c27cd264906`. The VMX is `V:\Virtual Machines\Barebit\Ubuntu 64-bit\Ubuntu 64-bit.vmx`. The screenshots show the Welcome overlay, cleared desktop, Files open after launch and synthetic input, and the later 15:48 local desktop.

These observations establish that the guest session renders and responds to a guest-injected input event. They do **not** prove that VMware console mouse forwarding from the host works, a clean install, an installed FileCat UI workflow or candidate acceptance. The guest stays available for background testing; if its interactive UI fails again, the authorized working-snapshot restoration remains available after checking the current guest state.
