# E-I469 — bound Windows download-mark writes to the readable limit

At exact parent `72b7568149421681db32b7d3fa953f0f27dc7d3c`, `WindowsFileOperations.WriteOriginMark` would write an arbitrarily long `Zone.Identifier` stream, while its paired reader refuses streams over 64 KiB. An owned NTFS test writes a readable, exactly 64 KiB ASCII mark, then attempts to replace it with one extra byte. The unchanged product returns `true` and the paired regression fails **0P/1F** (`Expected: False; Actual: True`). That behavior can replace a usable download mark with one FileCat itself cannot read.

The writer now rejects an over-limit character count or UTF-8 byte count **before** opening the stream with `FileMode.Create`, preserving any existing mark. The corrected case also attempts a shorter multibyte string whose UTF-8 encoding exceeds the byte limit. The final focused control passes **1P**, the complete Windows Platform suite passes **390P/38 explicit skips/0F**, and the Release solution builds with **zero errors/177 warnings**.
