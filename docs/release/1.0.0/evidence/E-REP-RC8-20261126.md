## Sealing: the owner's step at GO

DEC-10 makes the custody folder writable only by the owner at sealing. So the release session staged the package and did not write into `V:\FileCat\artifacts`. At GO the owner runs:

```powershell
pwsh -File E:\FileCat\.tmp\release-scripts\Seal-Rep.ps1 -ManifestSHA256 <the rebuilt manifest's SHA-256, as the GO names it>
```

The script now defaults to rc.8's staged package and to `V:\FileCat\artifacts\FileCat-1.0.0-rc.8-REP`. It:
1. Checks the staged package against the manifest.
2. Copies it to the custody folder, refusing if that folder exists.
3. Checks the copy.
4. Replaces the copy's inherited ACL: the owner's account keeps full control; Administrators, SYSTEM and Users may only read.
5. Checks the copy once more.

The GO names the rebuilt manifest's SHA-256. A correction later is a successor package with its own manifest, never a change to the sealed one.
