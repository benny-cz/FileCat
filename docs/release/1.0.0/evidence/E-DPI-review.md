# E-DPI — Source review of the destructive-path inventory (plan §8.3, step 6)

Static review of the code behind each destructive-path row (DPI) of the release plan, at the commits named, with a test
for every defect before its fix. Rows reviewed earlier: P03 (I19), P15 (I15), P16 (I40). Preliminary: a review by the
executing agent, not the independent re-audit the plan requires before closure.

| Row | Reviewed | Outcome |
|---|---|---|
| P01 local/native/stream copy and move | `TransferExecutor` (staged and direct copies, publish, `DeleteMovedSource`, folder moves), `StreamTransferExecutor` | **I48**: a move across volumes checked its source unchanged but not that the copy was still at the destination before deleting the source; an antivirus quarantine or sync client taking the new file away left the source the only copy, and it was deleted (reproduced: gone from both places). Fixed `e72e3fc`. Folders are removed only when empty (`Directory.Delete(path, recursive: false)`); identity checks keep a source reached through a link. |
| P02 recycle/trash/permanent delete | `UnixTrash` (Linux, macOS), the share case of E-V08-S1 | No defect found: items move only within their own volume (renamed, never copied); a trash folder owned by someone else or replaced by a link is refused; trash folders are private; the `.trashinfo` file reserves the name by exclusive creation first. On a share without a Recycle Bin nothing is deleted without the agreed permanent deletion (lab). |
| P04 journal/staging/rename reconciliation | `JobJournal`, `JournalRecovery`, the hex-save journal, edit sessions | **I44**: a second FileCat on the same profile showed a running job as interrupted on Linux and macOS. Fixed `e399276`. The hex-save journal is held exclusively for the whole save and re-read before recovery; edit-session commits refuse a target that changed; staged leftovers are matched by the job's own prefix. |
| P05 hex save/recovery/Save As/patch | `HexSaveJournal`, `HexSaveAs`, `HexPatchExport`, `HexPatchOverlay`, `ProtectedHexFile` | **I53**: a patch that went over the 8 MiB limit of changed bytes stopped part way, staged in part, while the editor said nothing was applied. **I54**: on Linux and macOS, Save As kept a copy that could mix old and new bytes when another program wrote the file meanwhile. Both fixed `7a99f9d`. Held: the journal is durable before the first write and records each range written; recovery acts only on the same file (identity and length) when every byte is the original or the saved value; a journal too large for its limit means nothing is written; Save As never overwrites a name; a link is refused race-free on every platform; a patch is staged only where every expected byte matches. Residual (said before saving on Linux and macOS): a program writing the same bytes during the in-place save itself. |
| P06 Registry edits/import/delete/undo/backups | `RegistryChangeRunner`, `RegistryExecutor`, `RegistryImport`, `RegistryInterchange`, the delete flow | **I55**: a .reg file exported from the 32-bit view (FileCat's delete backups among them) could be imported into the default view, writing the keys at the same paths there. Fixed `cf92679`. Held: every value change checks the value it replaces; subtree deletes and copies check the confirmed subtree's fingerprint and each key's values as they go, never follow Registry links, and name partial results; a plan stops at its first failure and says how much ran; undo steps are guarded inverses; HKCU becomes the requesting user's own `HKU\<SID>` before elevation; the merged HKCR view is read-only; the import is limited to the chosen key and refuses contradictions within a file. |
| P07 privileged tree/attribute/Registry work | `ElevationBroker`, `ElevationExchange`, `ElevationPaths`, `ElevationConsent`, the helper's entry point | **Partial.** Held so far: the helper runs only from Program Files and refuses otherwise; it checks the requesting process and user and runs a plan once; paths cross the boundary as volume paths; the exchange folder is read and written without following links; consent shows every step (I17); a folder deletion is consented as the folder with everything in it, and links inside are removed as links. Not yet done: the V06 audit of the helper's loading before its entry point, which the plan requires on installed candidates (whether the framework-dependent ZIP should carry the helper belongs to it). |
| P08 ZIP rebuild/member edit | `ZipUpdateExecutor` | No defect found: the baseline is checked before and after the rebuild, the source is read with writers excluded, the rebuilt file is verified before `File.Replace` swaps it in (keeping security and the download mark), a failed or stopped rebuild deletes only its own temporary file, which the journal names for recovery. Residual: between releasing the read lock and the replace, a writer could slip in unseen (milliseconds). |
| P09 remote publish/delete/move/resume | `SftpJobs`, both channels, real servers (E-V08-L1, E-V08-L2) | **I49**: a move from a server deleted each copied folder whole, with whatever appeared there or changed after it was copied; a move to a server deleted a local source that changed during the upload. Fixed `e72e3fc`. Also from this row's lab work: I33, I35, I36, I46, I47. |
| P10 sync/results/working sets/bulk rename/links | `SyncPlanner.BuildRequests`, the delete, recycle and copy executors for Synchronize's jobs | **I50**: removals and replacements acted on whatever was at the path when the job ran; a target edited while the plan was reviewed was deleted or overwritten. Fixed `99145cf`: each goes only while the item is as compared. A folder's own time proved unreliable for that on NTFS (listed late; unchanged within a clock tick; blind to changes deeper in): since `efc128f` a folder goes only while all it holds is as compared. Bulk rename's journaled chains were reviewed with P04. |
| P11 attributes/times/recursive Unix chmod | `AttributesExecutor` | **I51**: a link chosen itself had read-only set through it on Linux and macOS (a chmod that follows links), changing its target. Fixed `65a76f8`. Recursion skips links; permissions were already refused for links; times are set on the link itself (checked on Windows and macOS). |
| P12 ADS/EA/xattr deletion/export | `WindowsHiddenData`, `UnixHiddenData`, the delete command of the hidden-data view | No defect found: deletion asks first (naming the download mark's role when it is among them); Linux and macOS read and remove extended attributes without following links (`l*xattr`, `XATTR_NOFOLLOW`); Windows opens a file's EAs on the item itself. Residual: on Windows a file symbolic link's streams are listed and deleted through the link, on its target — consistently, so the view acts on what it shows. |
| P14 recovery outputs and FileCat's write roots | `RecoveryProvider.CheckTransferDestination`, the recovery entry flow, `AppPaths`, the topology of each platform | **Corrected 2026-10-01: I09.** This row first said no defect was found, taking the warning about FileCat's own files on the source disk as enough; plan V09 says a warning followed by writes fails. FileCat now refuses such a scan and offers `--data`; destinations behind loop devices, disk images, VHDs and shares served by the same computer were taken for other disks (fixed `27256f6`, `7418c04`). |

## Trust boundaries (V23)

| Boundary | Reviewed | Outcome |
|---|---|---|
| B10 folder metadata → automatic tools/contact | `GitStatusReader`, `NativeIconSource`, `OpenPgp`, `VerificationService`, `FolderSidecars`, `ChecksumManifests`, `ShellPreviewPolicy` | **I16** (fixed `2f35a6b`): a repository's linked paths and an icon named in desktop.ini were touched before they were known to be local; programs were looked for in the current directory. Held: Git runs only in local folders, with its configuration checked for programs it would run; automatic checks hash only files listed in the folder, local, settled and within the size threshold; a manifest's entries are confined to its folder while it is parsed (absolute paths, network paths among them, and `..` refused before any file call); gpg runs with `--batch --no-auto-key-retrieve` and file names after `--`; the Shell sees no shortcut-like files, folder customization files or cloud placeholders, and network and removable drives only when allowed. |

| B06 persisted/private data → reads/writes/cleanup | `AppPaths`, `AppLog`, `JobJournal`, the hex-save journal, `VerificationCache`, the listing spill, archive spooling, drag staging, the benchmark | Fixed `34c4b9d`: on Linux and macOS a crash left spooled archive members in the private temp folder for good (now swept after a day); the developer benchmark wrote to a predictable name in the shared temp folder through any link there (now unguessable and made new). Held: state, journals, caches and temp live in the user's own folders, made private on Linux and macOS (I40); diagnostics hash paths unless diagnostic mode is on; the hex journal is held exclusively and removed after a save; the verification cache is bounded; the listing spill and spools use random names and delete on close; dragged files are swept after a day. Residual: where the system gives no local application-data folder (no home folder), the private root falls back to the shared temp folder, where a folder another account made first cannot be made private. |

| B08 image/device → raw privileged access/output | `RecoveryProvider` (sessions, destinations), `DeviceTopology`, `UnixDisks`, the helper's `ReadDevice` step, `MainViewModel.Recovery` | **I09** (fixed `27256f6`, `7418c04`, `0a52b7b`): FileCat's own folders on the source disk were only warned about; destinations behind loop devices, disk images, VHDs and shares served here were taken for other disks; device scans reopened from the folder history; a disk swapped under a chosen number was read. Held: raw handles only read; the helper takes one read step on a `\\?\Volume{…}` or `\\.\PhysicalDriveN` path and nothing else; recovered files go only to a disk known to be another one; workspaces and back-history never kept device scans. Residual: V09's write trace, same-size swaps, OS writes. |
