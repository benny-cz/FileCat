### Inventory additions

*Internal workers:*
- **`FileCat --native-context-menu [--extended] --background X Y FOLDER`:** the folder's own Shell menu.
  - It takes exactly one fully qualified folder.
  - `--extended` adds the Shell's extended verbs, on item menus too.
  - Output: READY and INVOKE lines, and exit codes. The Send-to-ZIP, Copy, Cut and Share exits belong to item menus only.
- **`--analyze-disk-space` and `--analyze-selected-folders`:** item menus only. They exit 20 or 21, after which FileCat analyses the roots it chose before the menu.
- **The exit-19 report.** After a folder-menu New entry that makes its item itself, the helper's last stdout line is `FILECAT_CONTEXT_CREATED <base64 UTF-8 name>` and it exits 19.
  - It looks only on fixed or RAM drives, for 2 s and up to 100,000 entries.
  - FileCat keeps lines up to 4,096 characters and counts the report only as the last line. It takes one plain name.
  - FileCat then only focuses that listed item for the ordinary Rename, within 5 s, and only while the cursor, marks, tab and focus are unchanged.
- **`FileCat.ShellHost --serve` request kind 5, `TypeIcon`:**
  - It takes one plain extension, and both sides refuse the 16 shortcut-like types.
  - It returns an icon only, from a simple ID list for a name in a folder that does not exist. No file is opened.

*Shipped test modes that FileCat never starts:*
- **`--native-context-menu --probe-verbs [--background] [--extended] PATH…`:** prints labels and canonical verbs, with submenus filled. Nothing is invoked.
- **`--probe-new VERB FOLDER`:** VERB is `NewFolder` or a dot-led name, checked before any Shell code. It runs the folder menu's command with that canonical verb without showing a menu, then gives the exit-19 report.

Any helper failure is one stderr line and exit 1.

### Held

Every new mode runs with the token of whatever starts it, so a process that starts one gains nothing:
- FileCat starts the context-menu helper only below high integrity, and the helper refuses a high token before it reads its arguments.
- `--probe-new` makes its item with its caller's rights, or runs a ShellNew command, such as New → Shortcut's wizard, with them.
- An elevated FileCat starts the Shell helper only on the verified, restricted, low-integrity token.

None of them listens where another account can reach it:
- Their channels are inherited anonymous pipes.
- The context-menu helper's hidden owner window is on the caller's desktop, like every FileCat window.

### Residual

The `--probe-new` verb check admits any dot-led name of 2–64 characters without invalid name characters, not only one plain extension. Only a menu command with exactly that canonical verb runs.

## Notes for I629's record

- **I629 lists exit codes 0, 10–17 and 19.** At the tag FileCat also accepts 20 and 21, from the analysis options added on 2026-11-18. They are reviewed above.
- **`--probe-new` can run a program rather than make an item.** That happens for a type whose ShellNew entry names a command or handler, such as `.lnk` with New → Shortcut's wizard. It then exits 0 with no report, still with its caller's rights. This was read from source, not run.
- **The owner window takes input as Explorer's menus do.** It accepts it from processes on the same desktop at equal or higher integrity. It is not a listener.
