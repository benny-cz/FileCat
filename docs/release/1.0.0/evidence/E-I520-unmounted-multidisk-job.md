# E-I520 — unmounted two-disk mapped-source destination job

At exact pushed source `1705d6c1803e281776a880af459524155c2d5fa7`, the authorized Ubuntu 26.04.1 VMware guest received two temporary 256 MiB VMDKs at unused SCSI units 1 and 2. Its existing boot disk stayed `/dev/sda`. A 256 MiB `striped 2 128` mapper over the lower half of **both** test disks held an owned FAT32 deleted file and stayed **unmounted and read-only** while FileCat ran. A separate 128 MiB linear mapper over the disjoint upper half of `/dev/sdb` was mounted **read-only** as a test destination. The mapper regions did not overlap, but they shared one physical backing disk, which FileCat must conservatively refuse as a recovery destination. This is a virtual native-component test, not physical-device or installed-app consent qualification.
