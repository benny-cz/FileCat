# E-I412 — Windows shell-menu helper stderr retention

2026-10-13 CEST. **Preliminary source-level resource correction; no observed menu memory spike or installed UI acceptance is claimed.** Parent product source is exact pushed `d9705179bba21090cd02fe38bea152c740834d88` (I411). `WindowsContextMenu.ShowAsync` started `child.StandardError.ReadToEndAsync()` before awaiting the shell-menu helper, retaining the complete stderr text for the helper's lifetime, then logged only its first 240 characters on an abnormal exit. A shell extension can write on the child's inherited stderr while its menu is open. The source-level baseline is retained byte-for-byte, SHA-256 `ac613b0c3c7dce4ef4bfa1f771c60e402e6acf8fc84c8410d0647105767bfaf5`; this work did not reproduce a real extension emitting large stderr.

The correction reads stderr in a reusable 4 KiB buffer, preserves only the first **240 characters** and continues draining until EOF so the child is not blocked by a full pipe. No menu lifetime limit or action-result semantics are changed. The headless App test feeds an owned 4 MiB-plus stream, requires the exact 240-character prefix and verifies the underlying stream was consumed.
