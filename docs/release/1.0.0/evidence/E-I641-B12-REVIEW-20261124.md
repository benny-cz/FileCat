## Method

- **Source:** a desk review of the tag (`7269ec61`). `git diff 7269ec61 origin/main -- src/` is empty, so the line numbers are the tag's. Paths are relative to `src/`.

- **Probe (F1):**
  - I built `FileCat.Core` from the tag's source.
  - I called `DragStaging.Sweep` and `AppPaths.SweepTemporaryLeftovers` with the arguments `AppServices` passes, from this computer's elevated session.
  - The fixtures were owned and sat in a temporary folder; they were removed afterwards. The results are under F1.

The ordinary window creates it new (`FileCat.Platform.Windows/Elevation/ElevationExchange.cs:31-52`). ### Held

Every worker mode reviewed here runs with at most the rights of what starts it, so a process that starts one gains nothing:
- The storage query runs on FileCat's own token.
- The archive workers run below that token, and each refuses to read input outside its confinement:
  - Windows: a verified low-integrity LPAC token with no administrative group and no privilege but `SeChangeNotifyPrivilege`, in a job.
  - Linux: an ordinary identity under `no_new_privs`, a cgroup, seccomp and Landlock.
  - macOS: the App Sandbox, without a bootstrap port.
- No elevated or root FileCat starts an archive worker.
- The Linux picture sandbox only removes rights before it runs the worker.
- The EFS helper runs on an ordinary FileCat's own token, never on an elevated one's.

Two modes run with more than their starter, by design and only after the system's own approval:
- The Linux census runs as root after PolicyKit approval, and answers one bit.
- The administrator window runs elevated after UAC. It takes only hash-bound, link-free, validated requests, and asks before each write.

None listens where another account or a lower integrity level can reach it:
- The channels are anonymous pipes and inherited descriptors.
- The one named pipe, the EFS helper's, admits only the current user, and each end checks the other's process.

Exceptions: F1, F2 and F3.

### Findings

**F1 — An elevated FileCat sweeps the ordinary account's temp folder, following links. Severity: High.**

- **Code path:**
  - At startup, every FileCat runs three sweeps on its profile's temp folder (`FileCat.App/Services/AppServices.cs:153-158`). None of the three checks the token, so an elevated FileCat runs them too.
  - Elsewhere, FileCat refuses user-profile state at high integrity (`FileCat.Core/State/WindowsTokenAuthority.cs:6`; `FileCat.Core/State/JsonFileStore.cs:47-51,142-143`), and so does the staging itself (`FileCat.Core/Operations/DragStaging.cs:31`; `FileCat.App/Services/ClipboardVirtualStaging.cs:48`).
  - The folder is `%LOCALAPPDATA%\FileCat\temp`, or `Data\local\temp` in a portable copy (`FileCat.Core/State/AppPaths.cs:76`). Any medium-integrity process of the account can change it.
  - `DragStaging.Sweep` handles each directory under `temp\drag` whose own creation time is more than a day old, junctions included. It lists the files inside, through the junction, sets each file to `Normal`, then deletes the directory, or only the junction (`DragStaging.cs:109-121,149-157`).
  - `AppPaths.SweepTemporaryLeftovers` lists `temp`, also through a junction. It deletes each `member-*` or `nested-*` file older than a day, by its path through `temp` (`AppPaths.cs:264-282`).
  - `ClipboardVirtualStaging.Sweep` deletes each old `temp\clipboard\*` folder, recursively and by path (`ClipboardVirtualStaging.cs:164-179`).
- **Probe** (the exact methods, an elevated token, owned fixtures):
  - **Junction under `drag`:** `temp\drag\planted` was a junction, its creation time set two days back, to a folder holding a read-only, hidden, system file. `DragStaging.Sweep(temp, 1 day)` removed the junction. The folder and the file stayed, and the file's attributes became `Normal`.
  - **`temp` as a junction:** `temp` was a junction to another folder holding a two-day-old `member-owned` file. `SweepTemporaryLeftovers(1 day)` returned 1, and the file was gone.
- **Failure scenario:**
  1. A process of the ordinary account plants `…\FileCat\temp\drag\x` as a backdated junction to a folder that only administrators may change.
  2. The user opens FileCat as administrator, by any route: `Open FileCat as administrator…`, a denied folder, the change journal, or a link or task review.
  3. At startup, with no action from the user, the elevated window clears read-only, hidden and system on the files in that folder, until one refuses.
  - **Not run:** the planting process can also make `temp` itself a junction and use the usual opportunistic-lock technique. Between the listing and the next deletion, it retargets the junction to an object-manager directory whose links name other files. The deletions then remove files that this process names, as administrator. That primitive is commonly turned into SYSTEM code execution.
- **Class:** the same as [FCSEC-011 and FCSEC-025](../../../security/FILECAT_SECURITY_REVIEW_AND_PLAN.md): an elevated write through a link planted in medium-writable state, rated conditional High.

**F2 — The root census opens a path that another account controls. Severity: Medium.**

- **Code path:**
  - The root census lists every process (`RecoveryProcessCensus.cs:43`; `SingleInstance.cs:40-133`).
  - For each process not named `FileCat` or `dotnet`, it opens `Process.MainModule.FileName` with a plain `FileStream` and reads up to 512 MiB (`SingleInstance.cs:110,136-141,145,157-180`). That open follows links and blocks on a FIFO.
  - On Linux, that name is the text of the `/proc/<pid>/exe` link (see Method). For a deleted executable, the text ends in ` (deleted)`, and whoever can write the executable's folder can create a new file under that exact name.
- **Failure scenario:**
  1. Any local account, the user's own included, starts a program from a folder it owns and deletes the program.
  2. It creates `<path> (deleted)` as a FIFO, or as a link to a device.
  3. The user starts a device recovery, and an administrator approves the census. Root opens that path.
  - **A FIFO:** the census blocks until something writes to the FIFO. FileCat gives up after 90 s, takes the answer as unknown and refuses the scan. FileCat cannot stop the root process, so it stays.
  - **A link:** root opens that device or file and reads from it, at most 512 MiB, with whatever its open and close do. For example, opening a Linux watchdog device starts its countdown.
  - Nothing is disclosed: the census answers one bit.
  - Not run.
- **Why Medium:** it is local, it needs an administrator's approval, and the scan fails closed. The project rated FIFO blocks of automatic reads High ([I454](../FILECAT_1_0_RELEASE_ISSUES.md#i454), [I455](../FILECAT_1_0_RELEASE_ISSUES.md#i455)).

**F3 — An elevated FileCat loads code named by the account's environment. Severity: High (premise inferred).**

- **Code path:**
  - The administrator window is `FileCat.exe`, a standard .NET apphost, relaunched with `runas` (`FileCat.App/Services/AdministratorWindow.cs:14-24`).
  - Its self-contained build disables startup hooks (`eng/publish.ps1:103-104,180-184`).
  - Nothing removes the runtime's `DOTNET_*`, `COMPlus_*` and `CORECLR_*` variables before CoreCLR starts. The administrator helper's native entry has done that since [I155](../FILECAT_1_0_RELEASE_ISSUES_I001_I299.md#i155) (`FileCat.PrivilegedHost/NativeBootstrap.cpp:138`).
  - Its `--storage-cloud-query` child inherits the same environment (`WindowsStorageCloudQuery.cs:24-30`).
  - The framework-dependent ZIP's `FileCat.exe` also keeps startup hooks, and finds its runtime through `DOTNET_ROOT` (`eng/publish.ps1:107-109`); that case is in [I640](../FILECAT_1_0_RELEASE_ISSUES.md#i640)'s scope.
- **Premise (not observed here):** under classic UAC, an elevated process gets an environment built from the account's profile, `HKCU\Environment` included. Medium-integrity processes of the account can write `HKCU\Environment`.
  - The [plan review](../../../design/FILECAT_1_0_RELEASE_READINESS_PLAN_REVIEW.md) recorded this as an inference for the helper (RF-H04).
  - [E-I155](E-I155-broker-native-profiler.md) showed the CLR loading the DLL that `CORECLR_ENABLE_PROFILING`, `CORECLR_PROFILER` and `CORECLR_PROFILER_PATH` name, before the entry point of a .NET apphost.
- **Failure scenario:**
  1. A medium-integrity process sets those three variables in `HKCU\Environment`, naming a DLL it wrote.
  2. The user next opens FileCat as administrator and approves FileCat's UAC prompt.
  3. The DLL runs in the elevated process before `Main`.
  - Not run. Under Administrator Protection, the elevated environment is that separate account's own.
- **Why High:** I155 rated the same loading in the helper High. This is separate from I640, which covers code loaded from a folder the account can write.

### Residual

- **R1 — Undisclosed switches:**
  - Shipped builds honour all 28 `FILECAT_QUALIFY_*` switches, and nothing in the product says that one is on. The diagnostics bundle records no variables (`FileCat.App/Services/DiagnosticsBundle.cs:38-46`).
  - In an elevated window, the readers follow a medium-writable environment.
  - In an ordinary window, `FILECAT_QUALIFY_WINDOWS_ACL_VOLUME_ROOT` offers volume-root DACL edits through the administrator helper, behind UAC and the helper's consent.
- **R2 — Elevated start with chosen options:**
  - Any process of the account can start FileCat elevated with these options. UAC is then the only gate.
  - The elevated window then opens a read-only view on its own: a folder, the journal, a file in the viewer, checksums, a search or a Registry key. Any process that can read the screen sees what the view shows.
  - Every write still waits for the review.
- **R3 — Census name match:** a process named `FileCat` or `dotnet` makes the census report `running`, and the scan is refused. This fails closed.
