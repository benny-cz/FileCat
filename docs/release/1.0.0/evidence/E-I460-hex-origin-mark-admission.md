# E-I460 — hex Save As refuses unreadable or oversized download marks

At exact parent `56355754b5b7a3166686105f4a0baea99b404cd3`, the Windows `HexSaveAs.CopyOriginMark` path checked `File.Exists` on `:Zone.Identifier` and caught a read error as `null`. An owned file with a valid Internet-zone mark and a second handle holding that ADS with `FileShare.None` reproduced the unsafe result: the new regression expected `IOException` and no published copy, but **0 passed/1 failed** because `CreateNew` returned normally. The old code thereby treated an unreadable security mark as absent. The source and all test files were owned disposable files; no device or user content was opened.

The corrected path opens the ADS directly. Only `FileNotFoundException` means no mark. Sharing/read errors refuse publication; an opened stream is limited to **64 KiB plus one growth byte**. It copies exact ADS bytes to the staged destination and flushes them before publication, and a write error also refuses publication. The staged copy is removed on failure. A second owned control supplies a 128 KiB valid-prefix `HostUrl` mark and verifies bounded refusal and no published file. Existing unmarked and marked-copy cases remain in the twelve-test hex class.

The first corrected class run had **10 passes/2 failures** because both new tests tried `File.ReadAllBytes` on a source still protected by the editor handle. That test assertion was corrected to read through the already held `ProtectedHexFile`; its raw failure is retained. The final class passes **12/12**. The full Windows Platform suite passes **385/385**, with **38 explicit skips** (including physical-device/manual cases). Release solution build completes with zero errors; the first full build reported existing warnings, and the retained incremental build has zero warnings/errors. Independent archive `V:\FileCat\artifacts\release-evidence\i460-hex-origin-mark-20261014-v1` preserves parent and both corrected TRX, full Platform TRX, build output and source diff; its seven-file manifest independently rehashes at SHA-256 `eb3b82ee4e617fb83279742a9e808ac49e01c9e63324767f7644abb6f62b2b10`.

This is a preliminary Windows Save As correction. Concurrent mark replacement, other origin-mark consumers, installed UI and exact pushed-source/candidate CI require separate qualification. I106/I110 physical-source HOLD and explicit human GO remain unchanged.
