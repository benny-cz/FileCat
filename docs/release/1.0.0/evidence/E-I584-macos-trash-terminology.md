# I584 — Mac delete and Undo called Trash the Recycle Bin

## Consequence and prior-work boundary

On the physical Apple-silicon Mac, a user deleting one owned local file through the ad-hoc-signed after-I583 source package saw **“Move … to the Recycle Bin?”**, and the completed job and Undo review repeated **Recycle Bin**. The actual system action moved that file into macOS `~/.Trash`; Undo restored it. The mismatch made a safety-sensitive, reversible operation appear to use a Windows service that does not exist on Mac. Prior `UnixTrashTests` accepted the low-level move/restore behavior, and Windows Recycle Bin wording is correct on Windows. This record addresses the native user-facing term, without reopening their accepted filesystem controls.

The isolated before-fix package was ZIP SHA-256 `09a1f56957da82616b13e4fc413c543b42777e45ae0fe234cb7f27aaba9b4594`, App DLL SHA-256 `d53f77639ff558590018426a18ee17d546ee54c82b78f41dd007204d02935933`. The source was preview.5 commit `8adaf1f1` plus I583 commit `1c52c4e6` applied in a separate Mac worktree; its SBOM called out the dirty-source identity. The 21-byte test file `/Users/benny/FileCatValidation/ExploratoryTwenty/journey11/source/filecat-trash-20261031.txt` had SHA-256 `d054ace42c7ae6f169ba30a7c20075f64992167c61481efb563193f7d14f49d4`. All other marks were cleared before the one-file action. Native AX saw the incorrect review, job title, completed report and Undo review. The exact owned file appeared in `~/.Trash` and was absent at its source; after reviewed Undo, it returned with the same hash and the exact Trash entry was absent. No unrelated Trash item was enumerated or changed.

## Correction and native after-check

Product commit `537032c1b8fc8cdd25afb0e12f4139e9e30c3b88` gives recycle/Trash UI text a platform term: **the Recycle Bin** on Windows, **Trash** on macOS and Linux. It applies consistently to delete review, job/status/Undo text, Settings, Sync warnings, archive/member explanations and unsupported-location messages. The underlying recycle/trash classification, deletion, restore and safety policy did not change. Windows-only Recycle Bin place names and diagnostic messages remain Windows-specific.

The Mac worktree, still based on immutable preview.5 plus I583, applied only the I584 source/test patch and produced a separate ad-hoc-signed local ZIP, SHA-256 `6a04415bebe32ab56370c8785dfb854de93a476615b4440e1753f9065d7d1d1a`; App DLL SHA-256 `19f5e5b536072f5f4162a617d372da81920ac4aee9cc314a6a946ca299ae429c`. `ditto -x -k` extraction passed `codesign --verify --deep --strict`, and the app reported version `1.0.0-preview.5`. The isolated new process used its own `--data` root. Native AX showed **“Move … to Trash?”**, **“Move … to Trash: done.”**, and Undo named that same Trash operation. The owned file again moved to its exact Trash path and was restored by the reviewed inverse with **1 restored / 0 kept / 0 failed**. Its SHA-256 remained `d054ace42c7ae6f169ba30a7c20075f64992167c61481efb563193f7d14f49d4`; the exact Trash entry was absent afterward.

The focused cross-platform headless dialog regression asserts the rendered user text, not only the formatter: Windows x64 **1P/0F/0S**, TRX SHA-256 `293a54506ecb6e98580bb9563e97a5ef2ee4dcde7d89bf0a8a02d4d515a79ea7`; Mac ARM64 **1P/0F/0S**, TRX SHA-256 `2f8933efcfae97dcfc92be40ad21d7aa89b29240b2d95f6e72f93e77a5eb3510`. Directly affected Windows DialogViewport, Settings, SyncReviewState and OperationCenter tests passed **51P/0F/0S**, TRX SHA-256 `4cf1645a4ed8e3dbab888725d6db29f323575d2484276cb124f1cecdd100fd8f`.

## Disposition and stopping rule

Medium platform-specific UX defect, remediated preliminarily at `537032c1`. Exact-source [main CI run 41243996143](https://github.com/benny-cz/FileCat/actions/runs/41243996143) passed producer, Windows x64/ARM64, Ubuntu and macOS; tag-only package/draft jobs skipped by design. The later I585 source remains the current CI gate. The separate local Mac package is a source-build verification, not an immutable release artifact or an installed 1.0.0 candidate. Public preview.5 predates I583 and I584 and must not be relabelled. The final candidate still needs native platform delete/Undo wording and the contract's other qualification gates. Reopen this result only if a later UI text path contradicts the platform term, a native user observation does, or exact-source CI finds a consequence. Stable 1.0.0 remains **NO-GO**.
