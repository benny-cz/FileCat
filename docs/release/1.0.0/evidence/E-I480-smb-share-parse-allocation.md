# E-I480 — bound transient SMB share-list parsing allocation

`smbclient -L -g` output is limited to one million characters before FileCat parses it, but `ParseSmbclient` split every line and every `|` field. A malformed 999,946-character reply containing 999,900 separators between two valid `Disk` rows made the exact `1e1885aff9563159a6d525e47ebfc143a6f2edb2` parent allocate **18,389,680 bytes** in a Windows isolated harness while still returning the two shares. This measures managed allocation on the parser thread, not retained memory or a whole-process peak.

The parser now scans newline-delimited spans, examines only `Disk|` rows, and creates strings for the share name and first comment field. It preserves the existing handling of empty comments, non-Disk rows and extra fields. The same new regression test and 250-input package are used for both native binaries; only `FileCat.Core.dll` and its PDB differ. The parent Mac and Ubuntu `UnixNetworkTests` each report **5 passes, one failing allocation control and one explicit Samba-server prerequisite skip**; the failing control measures **18,384,552 bytes**. Corrected Mac and Ubuntu classes each report **6 passes, the same skip and zero failures**, with **320 bytes** in that control. Windows corrected focused tests pass **2/2**, and the full Core suite passes **4,103/4,244** with 141 explicit skips and zero failures; its control also measures **320 bytes**. A Release solution build succeeds with zero errors and 42 warnings.

Both Mac and Ubuntu runs were headless under ordinary user `benny` with .NET runtime 10.0.12. Each parent and corrected package has 250 manifest-verified inputs; the old/final package SHA-256 values are respectively `4c125490e71e18c5c06c0eb6490aadf0c3f197af840a00c4e24149e0e075b446` and `550fb41e8e1466397231ca8c6dd4aac8c81bfef3e61c6909f00b67558b6687fd` on both machines. Nine owned Mac paths and four owned Ubuntu paths verify absent after retrieval. No desktop UI was operated.

The host's repository-pinned SDK 10.0.401 disappeared before this local test. The first full build from the isolated scratch SDK 10.0.101 stopped before compilation with no diagnostics inside the sandbox; an elevated repeat from the same SDK passed. The scratch-only `global.json` is retained. Neither result is represented as a run of the missing pinned SDK; exact pushed-source CI remains a separate qualification.
