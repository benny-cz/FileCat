# I575 — stale Find result could copy a replacement under the old review

Recorded 2026-10-31 from exploratory journey 7. This is distinct from the live panel watcher/selection control in journey 5: Find holds a result snapshot while an external process replaces the path before the user requests Copy.

## Owned before/after observation

On Ubuntu 24.04.5, exact Git-built source `ed87efc9`, Find returned one owned `result.txt` row at **17 bytes**. Outside FileCat, the original was renamed to `retired.txt` and a **30-byte** replacement was created at the old path. F5 still reviewed `Copy "result.txt" (17 bytes)`. Approving it completed a copy of the **replacement** to the target, with no warning that the found item had changed. The old content remained intact at `retired.txt` (SHA-256 `0d8b42e1e23559492448d17d6760625bc810dae54bd0322582e0940d0b5ee414`); source replacement and target both had SHA-256 `780b3ed42c741e74d814704a4d60519d7e81abf64f736648ce31bd02129f09ce`. This proves a misleading review and different copied bytes, not loss of the original. Ignored local captures: `artifacts/exploratory-20261031-find-{results,review}.png`.

Product `9a619a26` checks the selected local result's kind, size and modification time before showing a transfer review, then again before the queued job creates a destination and before each root is processed. If the item changed, Find reports: “A selected result changed since it was listed. Search or refresh the results, then review the current item before copying or moving.” A nonlocal/mixed result and same-metadata substitution are outside this metadata check; this is not an atomic native object-binding or content-hash claim. Ordinary panel transfers keep their previous semantics.

On the clean exact `a00dcfd7` Ubuntu checkout, the same one-result search and external 17→30-byte replacement caused **no Copy review**, showed that message in Find, and left the owned target empty. Source and retired hashes stayed as above. Focused Windows Core `ReviewedSourceTests` passed **18/18**, including changed/unchanged queued-copy controls, and App `FindWindowTests` passed **17/17**, including a replaced-result pre-review refusal and unchanged-result positive control. The exact Ubuntu Release build had zero warnings/errors. The isolated app, owned files and state were removed; ignored local capture `artifacts/exploratory-20261031-find-refused.png` remains. Latest-source five-lane CI is in progress; no hosted pass is inferred.

## Finite 1.0.0 stopping rule

On the exact installed candidate, search one owned file, replace it externally at the same path with different size/bytes, then invoke F5 from the stale result. Require the visible changed-result reason, no transfer review or job, unchanged original/replacement bytes and an empty target. Rerun Find on the replacement and approve a new Copy; require the current size and exact target hash. Separately queue a reviewed result transfer, change its source before execution, and require refusal before destination creation. Reconcile producer, Windows x64, Windows ARM64, Ubuntu and macOS CI for the final source. Same-size/timestamp substitutions and adversarial check-to-use swaps are not covered by these metadata checks; do not present this evidence as object-bound transfer security.
