# E-I461 — Windows origin-mark reader refuses unreadable ADS before extraction

Exact parent `8dc884204ebcf0c4b81db030880631f2fa46e7dd` returned `null` from `WindowsFileOperations.ReadOriginMark` when a valid Internet-zone ADS was held with `FileShare.None`. The direct owned-file test expected an error but got none. A second owned file's 128 KiB mark was read without a bound. Most consequentially, a real ZIP-member copy through `JobManager` reached `Completed` while the downloaded ZIP's ADS was locked. These three exact-parent tests are **0 passed/3 failed**. The direct return value and `StreamTransferExecutor`'s mark propagation show why the completed copy lacked a readable origin mark; the original test stops at the unexpected `Completed` state before asserting the published file's mark.

The correction opens `:Zone.Identifier` directly and treats only `FileNotFoundException` as an absent mark. Sharing, access and unsupported-stream errors no longer become `null`; an opened stream is capped at **64 KiB plus one growth byte** before text decoding. A locked archive mark therefore aborts the job before its member is published. Healthy marked ZIP extraction and Mark-of-the-Web round trip remain covered in the same Windows file-operations class.
