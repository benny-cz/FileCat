# E-I537 — in-memory TAR-family extraction duplicated member bytes

At base `5b7d63c402479cf2ede5a9fc8bdd7a243c766abb`, `ArchiveIndex.Extract` preallocated a `MemoryStream` for a member below its 32 MiB in-memory threshold and called `ToArray()` before returning it. The TAR, 7z, RAR and other `ArchiveProvider` formats share this extraction path. The deterministic 16 MiB TAR test fails against the base assembly **0P/1F**: **33,905,152** current-thread bytes allocated, over its 25 MiB threshold.

The correction lends the extraction array to `MemoryContentSource` with the exact logical member length. If a malformed declared size makes `MemoryStream` retain more than the existing 1 MiB member slack beyond the logical length, it still trims the excess array. The same test and archive bytes pass **1P/0F** at **17,127,912** allocated bytes, **16,777,240 fewer**. The test checks the content length, both edge ranges and EOF.
