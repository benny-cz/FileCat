# E-I508 — bounded Windows Origin-column input

2026-10-15. At exact parent `f34125292874c02282729a3b0aff60da694978c0`, the cheap Windows Origin metadata producer used `File.ReadLines` on `Zone.Identifier`. A controlled owned NTFS file with one 8 MiB newline-free alternate-stream line made that producer allocate **50,338,264 bytes** on the Windows host and **50,338,336 bytes** in the Windows 11 VMware guest, while the test's measured interval excluded construction of the input. Each old result failed the 2 MiB allocation ceiling. A normal `ZoneId=3` and a file without the stream remained controls.

The correction opens the stream once, limits both its reported size and actual bytes read to **64 KiB**, and reserves only the small observed size until growth requires more space. Oversized input returns the generic `Marked` display without treating an unparsed zone as Internet/Trusted; a normal mark remains `Internet`, and an absent stream remains absent. Read cancellation is checked within the bounded loop. The normal Windows file-operation origin reader already has a separate 64 KiB bound; this change closes the automatic metadata path.
