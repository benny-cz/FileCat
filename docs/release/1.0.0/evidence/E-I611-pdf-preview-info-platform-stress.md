## User result and bounds

F3 now opens a PDF visually on page 1. Previous/Next and Page Up/Down change pages; zoom, fit and pan use the existing picture controls. PDF pages have a neutral canvas and visible page boundary, checked against an actual Windows VM screenshot. Info reports the PDF header version, page count, current page, page size in points/inches and file size. F4 and the Text/Hex buttons expose original bytes. When a later page fails to render, the last good page and its number remain together; Refresh clamps to page 1 when the revised document has fewer pages.

The renderer is the MIT [PDFtoImage 5.2.1](https://www.nuget.org/packages/PDFtoImage/5.2.1) library integrated with FileCat's own viewer. It uses the existing isolated picture worker and [bblanchon PDFium binaries](https://github.com/bblanchon/pdfium-binaries) rather than loading native PDFium into the main process. No PDF script, link or form action is invoked. The worker receives only streamed file bytes, limits PDF input to 64 MiB, bounds output dimensions by the picture protocol, and inherits the existing 30-second parent timeout and platform sandbox/lifetime rules. Malformed and encrypted files return bounded reasons and keep Text/Hex available. Info deliberately does not claim to interpret title, author, attachments or form fields; no search or text selection is claimed for the visual preview.

## Candidate check and stopping rule

For the frozen Windows x64, Windows ARM64, Ubuntu and macOS 1.0.0 packages, use one owned two-page document, one malformed and one encrypted document. Verify F3 page 1, page change, fit/zoom and Info, F4 original bytes, an understandable no-render message, close/cancel and no document-initiated navigation. Verify one changed document with fewer pages on Refresh. Reconcile the exact-source producer, Windows x64, Windows ARM64, Ubuntu and macOS CI jobs and the expected tag-only skips; on Windows ARM64, require its native runner's PDF viewer tests and package start because no separate physical ARM64 device was available. Verify the final shipped PDFium binary hashes against the retained upstream release, complete notice copy and artifact SBOM before stable approval. Stop at this bounded set; broad adversarial PDF fuzzing and arbitrary third-party documents are not inferred from the owned fixtures. If native binary attribution or platform isolation cannot be qualified, keep stable release NO-GO or remove the integration before a final candidate.
