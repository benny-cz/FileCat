# I368 — Unix device selection before the first read

2026-10-12 CEST. **Preliminary remediation at exact `c6c7f309a0ed63d94add24da04f199ef9734ac4c`; I106/I110 physical-source validation remains on HOLD.** This is the Unix counterpart of the [Windows pre-open identity gap](E-I106-preopen-device-identity.md). Before this change, `UnixDeviceSource.Open` compared the device path with its received descriptor only from the moment opening began. The `UnixBlockDevice` originally listed for the user carried no identity into `RecoveryProvider.ForDevice`. A same-sized replacement before `Open` began could therefore be accepted as the chosen source. This baseline finding follows the exact source path; a separate pre-fix native scan was not claimed.

The committed change captures the Unix device entry identity while building the list, carries it through confirmation and safety checks, and compares it with the descriptor actually opened for recovery before `RecoveryScanner` reads. An unavailable list identity refuses the choice; a changed or unavailable opened identity closes the reader and refuses the scan. The existing size check and the separate path-versus-descriptor check during authorization remain. The selected identity uses the existing `UnixFiles.Stat` device/inode representation, not a new topology guess.

The exact committed source was built as framework-dependent `linux-x64` and `osx-arm64` test payloads with no source overlays. On the Ubuntu VMware guest and the Apple Silicon Mac, eight native `UnixHeldSourcePathTests` passed per platform. The three added cases use two owned, equal-size regular images: replacing the path and retargeting a symlink each yielded a distinct opened identity, **zero scan reads, zero entries, and a disposed reader**; leaving the entry unchanged yielded the same identity, three reads and the expected deleted entry. Both original and replacement source bytes were checked after each case. The five existing held-path cases also passed. No real device, authorization dialog or physical source was opened in this batch. Windows host compilation and focused recovery tests passed, with the Unix-native cases explicitly skipped there.

The first Ubuntu controller saw eight passing tests but failed its cleanup assertion on an empty xUnit-created `filecat-tests` directory. The corrected repeat verified and removed that empty directory. The first Mac controller stopped before test execution because its system Python lacks `hashlib.file_digest`; the compatible repeat passed. Both adverse controller outputs are retained separately and are not recast as passing runs. The independent audit checks all 143 payload members per platform, the two XML inventories, three per-case observations on each platform, source blobs, transport receipts and owned temp/process cleanup. Its private `FileCatReleaseEvidence/i106-unix-selection-audit-20261012-v1/independent-native-v1.json` has SHA-256 **`dfcb551d1013d4475b445dd5b064cf7fb78bc6d6512cb33dacd06204014e7ea2`**.

This proves a bounded regular-image descriptor case and the committed selection check on both Unix systems.
