# E-I501 — helper client requested and accepted bytes past its reported source end

2026-10-15. Exact committed parent `f1a21ad05138a398fe9afe02dbb822eff13bb3c0` (I500). This is a controlled helper-client IBlockSource contract defect, not a physical wrong-byte observation. `PipeDeviceSource` accepted the helper's plausible 2,048-byte source description but, for a 1,536-byte caller buffer at offset 1,024, requested all 1,536 bytes rather than the 1,024 bytes remaining. An honest `RawReadProtocol.Serve` clips that reply; a scripted helper that sent 1,536 bytes made the original client expose all 1,536, crossing the boundary it had itself advertised.

The same compiled four-test assembly against the exact parent Platform DLL gives **2P/2F**: its near-end request says `Requested:[1536],Returned:1024`, and its beyond-end reply returns without an I/O error. The correction caps each request to `Length - offset - done`, rejects a reply larger than that cap through the existing terminal malformed-frame path, and rejects negative offsets before arithmetic. The unchanged assembly then gives **4P/0F**: bounded near-end request, beyond-end refusal, interior exact-byte read and normal zero at the reported end.
