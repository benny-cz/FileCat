# E-I528 — Unix instance metadata and lock paths must refuse FIFOs before opening

`SingleInstance.ReadInstanceMetadata` read an owner endpoint or independent-instance runtime JSON through an ordinary `FileStream` open. A same-user stale or replaced metadata pathname could instead be an unwritten FIFO. The byte limit after opening could not prevent that open from blocking the second-launch forwarding path or the recovery writer-location census. The latter must treat missing metadata as unknown and keep recovery fail-closed.

An owned Apple Silicon Mac comparison used the exact `094cd6bdaefbb8a4899a7f014041455fb5bd8f96` App assembly and a test-only new `SingleInstanceMetadataTests` assembly. With a no-writer FIFO, the old reader exceeded an external **eight-second** deadline: the in-process runner started but produced no XML, and the FIFO remained present. The corrected App assembly, differing in the instance-metadata opener, passed both direct and symbolic-link-to-FIFO cases **2P/0F** in 0.084 seconds. The original timeout is retained, not counted as a passing test.

The final source opens Unix metadata nonblocking and requires the **opened descriptor** to be a regular file, preserving the existing 32 KiB actual-byte bound. Windows keeps its existing file stream. An unreadable or not-yet-published Unix endpoint remains subject to the existing finite forwarding retry; an unreadable independent-instance record remains unknown to the recovery-safety census. A fresh final-source Mac stage passed the metadata class **2P/0F** and the affected `RecoverySafetyTests` class **27P/11 explicit platform skips/0F**. Focused Windows tests pass **3P/2 Unix skips/0F**. No installed second-launch UI, recovery device or final candidate was exercised by these tests.
