# I371 — pre-scan write safety used a reusable disk number

2026-10-12 CEST. **Potential Critical; remediated preliminarily at committed `df10ff0`. I106/I110 physical-source validation remains on HOLD.** Whole-disk recovery selects a present PnP interface and later opens that exact path, but its initial and post-confirmation `CheckDiskSafety` calls still used `PhysicalDriveN` from the earlier listing. A disk-number change between listing and consent could therefore make FileCat evaluate its own write folders and pause decisions against a different disk from the selected reader. The recorded test proves the mismatched arguments, not an actual physical-number change or an unsafe write.

A declared test overlay on exact committed `e353eba22be29723a0bd56f57e43fde306988e07` records every source passed to the real whole-disk admission route, with a synthetic selected interface and a recording reader that never opens a device. In the Windows 11 VMware guest, the old product's 32-case `RecoverySafetyTests` run had **26 passes, three failures, three explicit skips**. All three new failures were the whole-disk confirmation variants: every safety query used `PhysicalDrive99999` rather than the selected `\\?\recording-disk-interface`. Their raw XML and unchanged old product blob remain retained.

The correction sends `disk.InterfacePath` to both safety calls, matching the later reader's path. A missing or unresolved interface cannot supply a known-separate safety result. With one declared product overlay and the same test overlay, the native guest rerun had **29 passes, zero failures, the same three explicit skips**. Exactly those three cases changed outcome. The host build and focused headless run also pass, with six Windows-route skips because that host test process has no installed helper; those skips are not native positives. No physical USB source was opened.
