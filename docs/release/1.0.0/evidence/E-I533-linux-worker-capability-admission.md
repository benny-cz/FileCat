The pushed `7bef94da` I532 Unix worker fix verified real/effective/saved-root user and group IDs but not Linux capabilities. On disposable Ubuntu 26.04.1, an ordinary `1000/1000` self-contained Probe with the sole file capability `cap_dac_override=ep` returned `Refusal:null` and `Unprivileged:true` from the exact I532 Core DLL, yet read a root-owned mode-0600 fixture. The actual FileCat apphost with the same file capability showed UID/GID `1000 1000 1000 1000` and `CapPrm=CapEff=0000000000000002` **before image input**, then decoded a 2×2 PNG to a 51-byte `FCPX` response. This proves a remaining hostile-picture containment gap; no malicious image or privilege exploit was run.

The ordinary Linux bounding set alone is not treated as an active capability. The worker's existing refusal path runs before opening stdin or invoking Skia. macOS has no Linux capability probe.
