# E-I383 — verification summary snapshots its folder cache under the writer lock

2026-10-12. **High potential I06/V15 concurrency defect; preliminary source correction.** `VerificationService.SidecarsOf` and `FolderChanged` mutate the bounded `_folders` dictionary under `_folderLock`, including replacement and eviction. `Summary`, used for the visible verification status, previously called `TryGetValue` on that dictionary without the lock. A summary can run while another worker changes the dictionary. This is a source-level unsynchronized read; **no actual concurrent crash or wrong summary was observed**, so no incidence or reproduction is claimed.

`Summary` now acquires the same lock only long enough to look up and snapshot the immutable `FolderSidecars` reference. It computes per-file cache keys and counts after releasing the lock, preserving the existing `Good/Bad/Unknown/NotChecked` logic without holding the writer lock during file metadata or cache access. This is a product change; I382 and I384 are separate test-fixture corrections in the same batch.
