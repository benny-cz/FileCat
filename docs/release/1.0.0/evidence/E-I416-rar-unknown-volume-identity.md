# E-I416 — multipart RAR reuse with unidentified secondary volume

**Preliminary High source-correctness correction; no release candidate.** The exact `c82e9b2eb6f7f3d35e36dc2b3b446ef0ee3060b7` parent held a native change token for each opened RAR volume but allowed a cached multipart catalog to be reused when a secondary volume's opened file identity was unavailable. In that state, the next request could not bind the secondary path to the volume previously opened. No wrong returned member bytes under a colliding token were observed; the controlled failure is reuse despite missing required identity evidence.

The new test uses FileCat's six owned RAR5 fixture volumes. It supplies a stable selected-volume identity and deliberately unavailable identities for the other opened volumes, while leaving native change tokens available. It verifies the unchanged catalog names and independent complete member hashes, then requires a second request to reopen rather than reuse the unverifiable catalog.
