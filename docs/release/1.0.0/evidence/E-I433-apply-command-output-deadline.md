# E-I433 — Apply command waited for a descendant-held output pipe

2026-10-13 CEST. **Preliminary High availability correction within I16/I06.** An explicit Apply command ran `/bin/sh` on one owned file. Its main shell printed `owned helper error`, exited with code 7 and left an owned `/bin/sleep 8` child holding the inherited stdout/stderr pipes. Against exact pushed parent `549629c38817083bb5c695fee39bfcc371578e6d` plus this test-only overlay, the job waited for the child despite the main command having exited: **0P/1F** on Mac (8,115 ms) and Ubuntu (8,055 ms), with `prompt=False`. Both failures have their own raw TRX and command receipts. This control uses an owned temporary directory and shell child; it opens no recovery device and no host UI.

The original `DataReceived` callbacks also built a complete line before FileCat retained only its last 2,000 characters, so a command emitting a long line could consume unbounded intermediate memory. The correction reads both streams concurrently in fixed 1,024-character buffers and retains only the last 2,000 characters of each. Once the main command exits, collection has a 750 ms grace plus a bounded one-second join; if a descendant leaves either pipe open, FileCat cancels the reads and records a warning rather than waiting for that descendant. Exit code 7 and the available stderr tail still produce the failed Apply job. This is a bound on FileCat's collection; it does not terminate a child process that the user's own tool created.
