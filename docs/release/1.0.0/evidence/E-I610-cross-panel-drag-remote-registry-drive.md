## Finding and correction

The owner reported that dragging from FTPS to a local panel did nothing, then identified a whole drive as another source that could not be dragged and requested both Registry-to-folder export and Registry-to-Registry copy. Source inspection found that drag preparation demanded a local file payload before the OS drag could start. Remote and Registry entries did not have one, and a Computer drive was not a valid export item. The owner specified that dragging a drive should begin a **reviewed copy of its contents**, and that Registry drags should offer both reviewed export and reviewed copy. No general claim is made about drags into external applications.

An internal drag now carries a process-local token and the captured source tab, location and item selection. A drop checks that token and the current source and target listing before invoking the existing reviewed transfer or Registry workflow. Remote files can move between FileCat panels without staging a server item before the pointer drag starts. Local-to-remote and remote-to-local use the same transfer review and job. Registry-to-folder opens the existing `.reg` export review; Registry-to-key opens the existing typed copy and overwrite confirmation. Shift-drag refuses Registry and whole-drive moves. A single drive dropped onto a different local drive asks for explicit whole-drive confirmation, then shows the ordinary Copy review with a named destination folder; the job executor retains its canonical inside-itself guard. Unsupported or incomplete destinations refuse before mutation.
