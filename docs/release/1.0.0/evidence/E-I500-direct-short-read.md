# E-I500 — direct Windows recovery reader treated an early end as normal EOF

2026-10-15. Exact committed parent `16df06f6698187afc3434020dc6866fdc9ac1c5e`. This is a controlled I106/I110 recovery-byte contract defect, not an observed physical-device wrong-byte report. A source advertised 2,048 bytes when opened, then stopped serving bytes at offset 1,024. The original `DirectDeviceSource.Read` returned 1,024 bytes for a 1,536-byte request and zero for a request starting at 1,024, although both requests were before the advertised end. A caller could mistake that for normal EOF. At the actual advertised end, zero remains correct.

An internal file-backed constructor was added solely to hold the native reader over an owned file whose length can change after open; production device opens still use their existing topology and served-length checks. With only that seam over the committed parent, the same compiled three-test assembly gives **1P/2F**. The production read change throws `IOException` when the native reader returns an empty span before the established length; the same assembly then gives **3P/0F**. The stable-source exact-byte/advertised-end control passes in both runs.
