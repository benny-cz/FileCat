## The product against the contract: owner decisions

1. **[I638](../FILECAT_1_0_RELEASE_ISSUES.md#i638): the update check is on by default.**
   - Contract: C25 and V22 say opt-in or explicit.
   - Product: `CheckForUpdates = true`, "On for new profiles", and Settings says so.
   - Changed by `ab30f474` on 2026-11-03 at the owner's request ([E-STARTUP-UPDATE-LIVE-20261103](E-STARTUP-UPDATE-LIVE-20261103.md)), and ADR-15 was amended. C25 and V22 were not.
   - PRIVACY.md and SERVICING.md follow the product. SECURITY.md still says "The opt-in update check".
2. **[I639](../FILECAT_1_0_RELEASE_ISSUES.md#i639): the x64 installer accepts Windows 10/Server 2016.**
   - Contract: PSD-W64 says "installer minimum build 22000 (`MinVersion=10.0.22000`)", and each platform row "lists exactly what is supported".
   - Product: `eng/installer/FileCat.iss` has `MinVersion=10.0.14393`, so that Server 2016 reaches an edition check. This came with `e5cf68f2` on 2026-11-23.
   - The README says Server 2016 is accepted; CAPABILITIES.md still says "build 22000 or later".
3. **[I640](../FILECAT_1_0_RELEASE_ISSUES.md#i640): FileCat reopens itself as administrator outside the installed build.**
   - Contract: DEC-04 and PSD-W64 say "administrator retry only in the installed build".
   - Product: since `2f786b07` (2026-11-19), any non-elevated Windows FileCat, the portable one included, can relaunch its own executable through UAC (`AdministratorWindow.CreateStartInfo`: `Environment.ProcessPath`, verb `runas`). It does so for Tools → Open FileCat as administrator, the change journal, a denied folder, link reviews and the file retry when no broker plan is available.
   - Nothing checks that the executable sits in an administrator-protected folder. So an elevated portable FileCat loads its code from a folder the ordinary account can write, which DEC-04 and the broker work (I154–I159) kept away from elevation.
   - ADR-14 was amended, and the README documents the portable route. CAPABILITIES.md ("needs the installed build") and SERVICING.md do not.

## Text that disagrees with the product or with other documents

These follow once the decisions above are made, unless noted:
- **SECURITY.md** says a diagnostics bundle "hashes paths by default". It hashes paths only in the log. The bundle's `settings.json` is the whole settings object, in plain text: remote hosts and users, key-file and start paths, Find's ignored folders, tool paths. The export's own preview says "tool paths included".
- **SECURITY.md** asks only for "the Windows version", although the macOS and Ubuntu previews are in the contract.
- **SERVICING.md** says CI signs "through SignPath once the Foundation project exists". SignPath declined on 2026-10-31 ([DOWNLOAD.md](../../../DOWNLOAD.md)), and rc.2 was signed through the owner-approved `signing` environment.
- **PRIVACY.md** says the check runs "at most once a day". A startup check that is cancelled when the window closes saves no timestamp, so its request repeats at the next start. This is from source and was not run.
- **The .deb's description** mentions phones, but MTP is not available on Linux. Changing this changes the package.

## 1.0.0 text that does not exist yet

- **The README and DOWNLOAD.md** describe preview.11 as the release. The README calls the other platforms "planned" and the packages unsigned.
- **The preview labels.** The contract requires Windows ARM64, macOS and Linux to ship as clearly labelled previews. rc.2's asset names, `--version` and About all say 1.0.0 without a label; only CAPABILITIES.md carries one. So the release page and notes must say it.
- **The release notes.** None exist for 1.0.0, and the candidate draft step sets no body. SERVICING.md promises notes that name the fixed issue classes.
- **The signing statement.** DOWNLOAD.md promises to name the signing provider and the signed packages before a package is offered as signed. rc.2 is signed.
- **Bug reports.** Only PRIVACY.md and the installer's support link point to GitHub issues. The README, DOWNLOAD.md, Help and About do not.

## In agreement

- **Reporting:** the private reporting route, which is enabled, with its 7- and 14-day commitments; and the 14-day servicing promise.
- **Packages:** the framework-dependent ZIP has no administrator helper; macOS is ad-hoc signed and not notarized, with "Open Anyway".
- **Platforms and features:** the ARM64, Linux and macOS rows of CAPABILITIES.md, and the absence of a media player.
- **Updates:** they only notify, never download or install, and send only the version, in the User-Agent.
