The owner asked for a recheck of the work the concurrent Codex agent pushed. Four independent read-only reviews covered the product and release-engineering commits from `fac7bb2b` (27 October) to `f986ad59` (28 October): containment (`5fe5e8a5`, `79bea6e5`, `445f20dc`, `559a7572`, `c0e9cb5a`, `97eb0e49`, `c257bb08`), the security bundles (`d1757bca`, `5518f8d8`), remote/recovery/UI (`67b3d66a`, `44107b0f`, `ff1585cd`, `9c7e2505`, `ecfedb5a`, `47f09505`, `38181fe1`, `5e403377` and the 27 October viewer fixes), and release engineering (`c7ed9540`, `49ecb362`, `a508a270`, `8ae4229b`, `c3966157`, `42eb82d0`, `b20f9bac`, `afe89f77`, `f58f7d09`). Nothing was built or changed by the reviews. **Verified** below means re-read in the current source by the release session; **confirmed** means the reviewer traced it in source; **plausible** means the mechanism is real but not reproduced.

Ownership follows the owner's split of 2026-10-28: the Codex agent owns CI regressions/I555, I08 containment and the [security plan](../../../security/FILECAT_SECURITY_REVIEW_AND_PLAN.md) findings; the Claude release session owns release engineering (I03/EXT-04/V20) and the other release items. ## Taken over after the security session stopped (29 October)

The owner stopped the concurrent Codex agent on 29 October afternoon, so its open findings here pass to the release session.
- **R-H1 (`fb59e594`).** An SFTP or FTP move's held original is journaled, durably before the move, as a rename back to its own name through the hold name, not as a staged file. Interrupted-job review restores it, or keeps it under the hold name and reports it when its name is taken or it cannot be reviewed; it never offers to delete it. A failed restore leaves the step open for that review. The new `SftpJobTests` case copies the journal at the moment of the hold, as a kill would leave it: the old code lists the original among the partial files to delete, the new code restores it. SFTP and FTP job tests: 118 passed.
- **R-H3 (`e423d85a`).** The Linux picture worker's pre-exec seccomp filter, which the worker inherits, now also denies truncate and every chmod, chown, extended-attribute and time call (x86-64 and ARM64, with the 6.13 `*xattrat` calls and `file_setattr`). `ftruncate` stays: Landlock refuses any descriptor open for writing, and .NET's double-mapped code uses it. The live probe tries chmod, chown, utime, truncate and setxattr on a file the user owns. On the Ubuntu VM (kernel 7.0) it stops at chmod without the change and passes with it; 38 Linux policy and picture tests pass. [E-I552](E-I552-linux-picture-filesystem-network.md) has the correction.
- **R-H4 (`16970200`).** The macOS picture worker's profile now also denies:
  - exec, except of the worker itself;
  - every service lookup, Apple events and launchd job creation;
  - signals to any other process (`(target others)` is not enforced, so the worker's own are the only ones allowed);
  - I/O Kit, pseudo-terminals and terminal reads.

  `/dev` is no longer a read root. On the Mac, a sandboxed probe ran another program and signalled another process under the old profile; the new profile refuses both. The launchd route itself did not work under the old profile either: launchd created no job for a sandboxed `launchctl submit`, though it does without a sandbox. 30 sandbox and picture tests pass. [E-I546](E-I546-macos-picture-sandbox.md) has the correction.

Fixed later on 29 October:
- **R-M1 (`1a7f071a`).** A Move whose copy went up as "a (2).txt" after Keep both now checks that name before deleting its source, not "a.txt", another file. `SftpJobTests` moves a file next to a same-size file of its name: the old code kept the source with a false warning, the new one removes it.
- **R-M9 (`1a7f071a`).** Jobs and comparisons list a remote folder whole, within a bound of their own: 250,000 entries, 64 MiB of names, 128 MiB on the FTP wire (`ISftpChannel.ListAll`, `IEnumerationSink.Whole`). A folder shown keeps the 20,000-entry limit. Tests:
  - an upload Move and a folder download, against a fake server whose listing for a folder shown stops at 20 entries;
  - the owned FTP and FTPS servers list 20,001 entries for a job and refuse them for a folder shown;
  - the job budget's boundary.
- **R-M14 (`1a7f071a`).** Checking reads each known_hosts file a line at a time and keeps only the server's entries: up to 64 MiB, lines of up to 64 KiB, 1,024 entries for one server. A file that still cannot be read whole refuses every key, since a revocation could hide in it. FileCat then says which file and why, as it now does for a revoked key, where the user saw only "Key exchange negotiation failed". Tests:
  - 50,000 lines (5 MB) still trust their pin;
  - a 70 KB line makes the check name the file and the reason;
  - a connection refused for an unreadable known_hosts tells the user before anything is asked.
- **R-M2 (`d74be210`).** Confirmed on Windows. In the Win11 VM, a FAT32 and an exFAT virtual disk both gave a file another 64-bit index after the hold rename: FAT32 0x401840 to 0x401900, exFAT 0x57000 to 0x57060. Neither has the 128-bit ID that FileCat reads, so an MTP Move from either aborted its job: reading the identity threw a `Win32Exception`, which `TryIo` does not catch. On FAT and exFAT the identity is no longer compared across the rename; the held bytes decide, as they already did. `FatMoveIdentityTests` (with `FILECAT_TEST_FAT_DIRS`) runs an SFTP Move and the MTP retirement from both disks at medium integrity, and passes. The G: stick is NTFS, so the VM's disks stood in for it.
- **R-H6.** The row above recorded a fix in progress; `f134ba37` completed it. At high integrity, `Remember` refuses before touching the host-key and certificate `.tmp` files. The verification cache's `Append` returns before writing, so its `Compact` never runs.

Still open then: R-M3, R-M4, R-M6–R-M8 and R-M10–R-M13. The `f134ba37` recheck listed only the findings that commit's own changes left open, and none of these had been rechecked against the current source since this review. Each was confirmed in the current source and fixed:
- **R-M13 (`6d82ad9a`).** A remembered mismatch or bad signature stays red after a refresh, marked as from its check, and the folder's status line counts it as failed. Only a remembered success turns neutral until the bytes are read again (FCSEC-006). A remembered hash against a new sidecar stays neutral, since no failure was ever found for that sidecar. Five tests that expected a remembered mismatch to turn neutral expect the failure again, two of them as they did before `f58f7d09`. The tests for a remembered hash against a new sidecar still expect neutral.
- **R-M10 (`d8e78733`).** An FTP listing that ends before its final reply is read (cancelled or failed mid-transfer) closes its connection rather than returning it to the pool, where the next command would have taken that reply for its own. A server's immediate final reply for an empty folder is not waited for twice. "550 No files found" for a folder that exists is an empty listing. MLSD's entries for the folder itself and its parent are not listed, and with "total", "." and ".." they no longer count toward the entry limit. Three tests against the owned pyftpdlib server fail on the old listing.
- **R-M11 (`4077d641`).** A phone Move's hold of its local source is journaled durably first, as R-H1 journals an SFTP one: recovery restores the original. A device that does not say which object it created has it found by its free name and size, with the full readback still required, so Copy works and a cleanup leaves no duplicate. A test copies the journal at the hold and recovers the original; without the flush before the hold it cannot. The phone was not connected, so the device tests did not run.
- **R-M6 (`0c309a2e`).** The Linux picture worker's inherited seccomp filter denies SysV IPC, tkill and process file descriptors, and lets kill, tgkill and the sigqueue calls reach the worker's own process only. Landlock ABI 6 also scopes signals and abstract Unix sockets. Before execv, every inherited descriptor but the standard three and the lifetime pipe is closed on exec. On the Ubuntu VM (kernel 7.0), the live probe now also tries `kill(-1, 0)`, signals its parent, creates shared memory and reads a descriptor the test held open. All are refused, and all 38 picture tests pass. Under the old policy the probe signalled every process.
- **R-M12 (`184175c4`).** "Elevated" is one decision: the token's high integrity on Windows, as for every other refusal of the security plan, and an effective user ID of 0 elsewhere. The tool-launch gates apply on every platform. A test with an elevated shell expects the configured tool refused; on Linux and macOS the old gate launched it.
- **R-M7 (`bf9124cc`).** Where WebKitGTK would start its page process without bubblewrap while still reporting its sandbox enabled, FileCat shows no page and says why: `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS` set to anything but 0, Docker (`/.dockerenv`), or a Snap. These are WebKit's own conditions. On the Ubuntu VM the page tests still skip for the AppArmor reason they skipped for before.
- **R-M8 (`90ad5e10`).** A context menu verb that outlasts its 20-second deadline is left to finish in its helper, which shows the Shell's own progress; FileCat stops waiting. Before, a paste of a large folder was cut off mid-copy. A stray line from a Shell extension during the verb no longer ends the helper.
- **R-M4 (`1e65bbfc`).** A transfer's pace starts again when the limit changes or the job resumes, and saves up at most a second of unused allowance. A lowered limit no longer stalls for what was sent at the old one, a resumed job no longer races through its pause, and a slow stretch no longer ends in a burst.

Also fixed: the operations drawer brings the selected recovery action's Stop itself into view, and keeps it there when the area changes while the action can be stopped (`ffb39752`). Hosted macOS had found Stop 15 DIP short of the viewport after a one-time scroll to the end.
