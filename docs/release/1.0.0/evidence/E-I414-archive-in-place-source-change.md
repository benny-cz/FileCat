# E-I414 — in-place archive rewrite and nested-spool source guard

**Preliminary correction after exact `95da426905a66ea6fad03f8bfa08d838cbd8e8bb`; no release candidate.** This tests owned regular-file TAR and nested TAR archives on observed filesystems. The outer path, identity, length and restored mtime are held constant while its native change token advances. It does not exercise a physical source.

The pre-I414 product kept `alpha.txt` in a cached TAR listing after its bytes became a same-length TAR containing `omega.txt`. A held large TAR member could return changed bytes, and an inner TAR spool remained stale after an in-place rewrite of a TAR or ZIP outer archive. On both ordinary-user Mac and Ubuntu, one identical test DLL (`ab5e93675103d7c955bc9cb3cb4cfb8107b4422d870257d4c79c7256ca0c4b9b`) against the 82-member baseline package (`c88ca13ed908736696b77d78afc2cfe599cf5d2be2b79ffef3a74a6390a7c744`) produced **32 passing existing archive-replacement cases and four new failures**. All 102 paired retirement controls passed. The initial host baseline also failed the four new cases; its wider archive-replacement class had sandbox-only atomic-rename denials and is retained raw, not counted as native product evidence.

`ArchiveProvider` now owns a verified, read-shared witness handle alongside each index. It checks that handle's native change token before cache reuse and before/after small or progressive member reads; a changed token retires the cached catalog. With no native token, reuse is disabled. A failed lazy member open retires the index and witness so the refused source does not remain open. Nested spools from TAR or ZIP also include the outer source token in their reuse key. These changes retain bounded index/spool ownership and leave unavailable/coarse-token and arbitrary concurrent-mutation limits explicit.

The first corrected Windows guest full Core run exposed **23 failures** despite passing the four focused, 36 archive-replacement and 102 retirement controls: twenty direct-reader failure-injection cases had no provider witness, and three lazy-open refusal cases found the witness handle retained. The raw VM result is **4,017P/112S/23F**. The final correction permits a direct one-off reader to operate without a witness and closes the provider index on a lazy source refusal. The first/final 82-member packages differ only in `FileCat.Archives.dll` and its PDB; the test DLL and Core DLL are identical. The final package SHA-256 is `4d9d48cc770ee88c54a168d868f504ad7b09b15ac30ef42bd364cd85749f8a9f`.
