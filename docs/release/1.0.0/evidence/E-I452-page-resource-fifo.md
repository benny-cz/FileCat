# E-I452 — page resource FIFO no longer blocks the viewer

**Scope:** High availability within I06/I25. At exact parent `fde6522aedf0aac45f8c4e7930f2cdfd738a873e`, `HtmlPage.ResolveCore` checked `FileInfo.Exists` and `Length`, then called `File.ReadAllBytes` on a resolved resource in the page folder. On the physical Mac, an owned FIFO had normal attributes and `FileInfo.Exists=True, Length=0`; an isolated probe mirroring those exact old calls reached `ReadAllBytes` and timed out after three seconds with no writer. The old FileCat page class itself was not invoked against the FIFO, so the baseline is a direct old-call probe, not a claimed full-product failure run.

The correction opens local resources with Unix `O_NONBLOCK|O_CLOEXEC|O_NOFOLLOW`, refuses a nonseekable descriptor, enforces the **64 MiB** limit on the opened handle, and reads bounded chunks with cancellation and EOF checks. Windows uses an opened `FileStream`. A new Unix page test creates an owned FIFO beside a normal page, requires prompt refusal, and confirms the normal page remains readable.
