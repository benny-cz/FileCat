# E-I538 — held recovery image read after source-path replacement

At exact base `5b7d63c402479cf2ede5a9fc8bdd7a243c766abb`, a held recovery reader could keep a handle to an image after its selected path was replaced. The read verifier checked the handle's change token only when the selected path still identified that same file. An owned 32 KiB FAT image was scanned and held, renamed away, rewritten at its former path, and replaced at the selected path by a different image. The adverse test fails on the old Recovery DLL **0P/1F**: the held read returns 4,096 bytes from the rewritten former image with no error. The selected and current path identities differ, and the former handle's change token advances. The old read SHA-256 is `C63A5297922FF6397C876303408824106561B4D6CBC701D909114F3139135C17`.

The correction refuses a held read when the selected path no longer names the opened image; it then checks the opened handle's change token when the identity still matches. The same adverse test passes **1P/0F**, returning an `IOException` and no bytes. The old/final former-image SHA-256 is `C651AA6C2CA099AE3E1D70ACF304A8E8B1CB657A2723B82EF8B2675AA83AF936`; the replacement image SHA-256 is `2D088EE9470A2F7FA57E36851FB19134D0479470556DF2BC692BF3808EE7E4B6` in both runs. The test checks exact bytes, identity and token change, closure and deletion of every owned file. A fresh reader on the replacement remains separately tested.

The first full Windows Core run exposed two lifetime tests that still required a replaced-path reader to return the former bytes: **4,162P/2F/149 explicit skips**. Those assertions now require refusal while still checking that the owned handle remains open until the last reader closes and missing ranges stay empty. Both affected classes pass **38P/0F**; the final full Core suite passes **4,164P/149 explicit skips/0F** (4,313 total). The Release solution build exits zero with **36 warnings/zero errors**. The original failed full suite is retained as raw evidence, not counted as a passing run.

Private archive `V:\FileCat\artifacts\release-evidence\i538-held-image-20261016-v1` retains exact old/final source and assemblies, old/final focused XML and logs, affected-class and complete-suite XML, the initial two-failure full suite, build, patch and setup notes. All **37 manifest entries** independently rehash with zero mismatches; audit SHA-256 `ccd00599ff8efa7875567f2a909379bf13e1ac3ff98077bf5249ab8921da5f61` and manifest SHA-256 `3862c598ad1a0ebda95cf359f160a8c707a0285e80478b990e4e54b03704046c`.

This establishes refusal for an owned regular image on Windows NTFS with available path identity and change token. It does not qualify a physical disk, unavailable identity/token routes, an atomic adversary, installed UI or a release candidate. The selected path may have moved without a content rewrite; the verifier conservatively refuses that held read because it cannot attest to later bytes from the former file.
