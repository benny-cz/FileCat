# E-I539 — headless scroll fixture used parent-relative pointer coordinates

The exact pushed-source [I536 CI run](E-CI-I536-zip-buffer-failed-scroll.md) failed one Windows x64 App test, `FileListSmokeTests.Refresh_does_not_pull_a_manually_scrolled_view_back_to_its_focused_row`, while every new I536 ZIP Core test passed. The test constructed a synthetic pointer click from `scroll.Bounds.X/Y`, which are relative to the scrollbar's parent. `Window.MouseDown` and `Window.MouseUp` expect a position relative to the window. This can miss the intended track when the hosted layout places the scrollbar within another visual parent; the CI assertion observed no manual scroll (`manuallyScrolledTop > 100` was false). The official failed test XML and all other lane results remain in the separate exact-commit CI archive.

The test now translates a point inside the scrollbar to window coordinates with `scroll.TranslatePoint(..., window)`. It retains its assertions that the focused row does not change, the user reaches a manually scrolled position, and a changing-folder refresh does not pull the viewport back. This is a test-input correction; it does not change FileCat's panel scroll implementation.

The corrected focused test passes **12 consecutive local Windows x64 headless runs**, each with its own raw TRX and log. A first complete local App attempt could not connect VSTest to the testhost within 90 seconds and was aborted before a valid suite result; its raw XML/log/exit are retained. The elevated complete Windows Release App suite then passes **1,663P/59 explicit skips/0F** (1,722 total) in 13 minutes 11 seconds. That is a separate successful run, not a reinterpretation of the abort. The [exact corrected-source hosted CI](E-CI-I537-I539-corrected-source.md) passes the scroll row and all required lanes. Installed Windows guest pointer interaction and candidate acceptance remain separate.
