# Disk space operation guard feasibility

This is early W4 development evidence for plan §31.4. It neither qualifies an operation adapter nor closes SG02. All analyzer actions remain off. Existing ComparedContent deletion/replacement keeps its complete-content requirements.

The controls use only generated ordinary-user fixtures. Windows runs inside the NTFS VM as `filecatdsa_r2`; Mac runs on APFS and Ubuntu on ext4 as `benny`. The passing assertions below deliberately demonstrate missing guarantees. A passing counterexample is not a passing action qualification.

| Candidate | Actual native observation | Disposition |
|---|---|---|
| Windows held parent ancestry plus selected-child DELETE/READ_ATTRIBUTES handle, with read-only sharing | Primary ReadData is denied by ACL. The metadata-only handle still opens, excludes an ordinary writer, prevents selected-alias rename and parent movement, and removes only the selected hard-link alias. The other alias retains its bytes. An already-open writer prevents admission. | Useful selected-entry/lifetime foundation on this fixture; insufficient complete proof. |
| Same Windows sharing guard against attribute-only access | Another handle with WRITE_ATTRIBUTES changes LastWriteTime while the guard remains open. | Sharing alone cannot establish unchanged recorded version metadata through commit. |
| Windows R, RH, RW and RWH oplocks on the metadata-only guard | Each request actually returns ERROR_IO_PENDING, establishing a granted oplock. Another attribute-only handle changes LastWriteTime; the mutation finishes and the break event stays unsignaled. Cancellation waits for the actual pending request before freeing its buffers and event. | These oplocks do not repair that version-metadata gap. No action registration follows. |
| Unix held parent plus metadata-only child descriptor | The selected child can be renamed and replaced. `unlinkat` relative to the held parent removes the replacement while the old descriptor retains its original identity and the renamed original survives. | Descriptor-relative lookup alone does not bind the approved child at mutation. |
| Unix held parent/child after ancestor movement | The selected parent can be renamed and replaced. `unlinkat` using its descriptor acts in the old directory despite the changed selected ancestor binding. | A live descriptor alone does not preserve the approved ancestry. |

The Windows results agree with Microsoft's [attribute-only create exception](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/irp-mj-create2) and the [set-information operations that check oplock state](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/irp-mj-set-information2). Actual grant/completion handling follows the [FSCTL_REQUEST_OPLOCK contract](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_request_oplock). These documents explain the tested primitives; the FileCat authorization contract still requires independent implementation evidence.

The fixture implementations are `AnalysisWindowsTests.OperationFeasibility.cs`, `AnalysisWindowsTests.OplockFeasibility.cs` and `AnalysisOperationFeasibilityTests.cs`. The [r36 validation receipt](../validation/disk-space/operation-feasibility-r36.json) names final XML and source/binary provenance. Initial Linux probing used a managed seeking API that does not support O_PATH; the final probe uses native descriptor metadata. Shared-budget exhaustion tests now run in a nonparallel collection after actual contention failures; production budget refusal remains unchanged.

Remaining work includes a complete source/root capability, exact raw-name/case rules, protected-object checks, immutable approved membership and one-shot submission, queue/handle budgets, commit/version linearization, native recycle/move/target-replacement outcomes, interruption/journaling and filesystem matrices. The existing shared NT open primitive uses case-insensitive object attributes; these simple ASCII fixtures do not qualify a case-sensitive namespace action. Alternative native mechanisms and the precise support matrix need further investigation. Do not replace a missing guarantee with path reopen/recheck, release guards while queued, or treat these results as proof that every possible native adapter is unsupported.
