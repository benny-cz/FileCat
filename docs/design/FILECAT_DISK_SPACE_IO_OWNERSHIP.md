# Analysis I/O ownership

`AnalysisIo` admits at most eight requests process-wide and one native operation per provider device key. Preparation, root containment, enumeration creation, metadata batches, enumeration disposal and final backend release use that admission. The per-device entry is reference-counted and removed when no caller or waiter owns it; the admission dictionary itself is bounded by the request budget.

Caller cancellation can stop admission and is checked again on the actual worker. It is also available for cooperative boundaries inside the operation. It is never passed as the scheduler task's cancellation token: an awaiting task cannot finish early while its native delegate still owns a cursor, backend or I/O budget. The actual worker releases the admission in `finally` after the delegate returns, with an idempotent outer release covering work canceled before entry. This also avoids retaining available slots merely because an awaiting thread-pool continuation is delayed.

`DeviceIoScheduler` shutdown cancels queued work and leaves running work owned until return. This behavior is a dependency of the analysis lifetime contract. Tests cover cancellation during work, cross-scheduler device serialization, eight simultaneous requests with a ninth waiting, canceled admission and scheduler shutdown both before and during owned-handle release. The capacity barrier is asynchronous so it does not starve a smaller native machine's thread pool while another case releases a slot.

Owned metadata cursors and backends close on admitted workers. A prepared source that arrives after its view closes also transfers to worker cleanup. View disposal clears its prepared list before scheduling those releases and performs no native close itself. Scan completion waits for cursor and backend cleanup; Stop can still freeze the published observation while an unresponsive call retains its original resources.

Terminal scan cleanup attempts each independently owned backend once. A failed close records a qualified issue while the store remains writable, continues with the other roots and cannot strand global scan admission or finalization. A native close is never retried against a potentially reused descriptor. Scheduler shutdown produces a stopped, partial, source-unavailable revision; an unexpected producer failure produces Failed/Partial rather than a complete finished result. Controlled failures cover both paths. A previously frozen Stop revision remains immutable.

If application shutdown cancels a queued cleanup before it enters its worker, only release of an existing metadata capability can use a lazy process-wide close scheduler with one worker and no replacement thread. That release retains the same global and device admission. Running releases are never retried. This route cannot create sources, enumerate, perform persistence, publish files or execute actions. It does not change publication or privilege-refusal policies. Existing held handles can close when new analysis work is unavailable under the actual process authority.

The development Save/Open workflow also routes native private storage through this admission. It retains the exact displayed revision and its memory reservation until actual work returns. Imported inventory leases retain inert data only. Root preparation has Stop binding and watchdog status with worker closure of late results. Epoch refresh, resource-pressure and unresponsive-device matrices, full persistence integration, filesystem device-key qualification and the broader W1/W8 evidence remain open. This foundation does not qualify a release gate.
