# Active-analysis profile capacity

This implements an internal cross-process scratch-capacity owner for plan §27.12. It does not enable public indexed acquisition or qualify the complete resource, package or persistence gates. Product commands, operations and the privileged helper remain off.

The public Core entry `AnalysisProfileQuota.Open(Guid, AnalysisPrivateDirectory)` accepts the trusted local UUID and transfers a retained native profile-directory capability on success. It verifies the existing private UUID before accepting capacity work. Imported `SessionIdentity.HostProfile` values cannot choose a directory or a namespace. The internal indexed acquisition now transfers its original verified inventory directory into this owner. Its `AnalysisStorageOptions.CreateProfileQuota` factory runs on admitted storage work, and the workspace, derived arenas, datasets and readers retain capacity after the factory/acquisition owner closes. Capacity returns after actual scratch closure and final retained ownership, not after a cancelled await or an original owner closing.

Each owner rounds its current byte reservation up to 256 MiB units. Thirty-two units impose an 8 GiB ceiling across cooperating ordinary processes opening the same verified private profile-directory object, including separate Linux IPC namespaces. This is reserved capacity, not a claim that 8 GiB of payload has been written. Conservative rounding can refuse smaller concurrent sessions before their exact bytes total 8 GiB. The existing 4 GiB session limit, process budget and free-space reserve also apply. Failed growth rolls back new units and its parent byte reservation before payload writes; an operational failure latches further admission while existing readers and cleanup remain available.

## Native private-file boundary

Each unit has one immutable create-new metadata file, `capacity-00.state` through `capacity-31.state`, in the retained private inventory directory. Its 64 ASCII bytes contain the closed v1 protocol marker, the trusted profile UUID in canonical N format and a two-digit slot. Length and every byte must match before locking. Existing unknown, malformed, linked, nonprivate or wrong-profile data is preserved and refused. A concurrent creator is accepted only by reopening and verifying its exact complete marker. Publication uncertainty is not retried. No PID, mutable reservation count, runtime directory or source name chooses the boundary. The closed metadata namespace reserves these 32 names; directory enumeration has 32 additional bounded entries, with its unchanged byte limit.

Linux/APFS use native nonblocking `flock(LOCK_EX | LOCK_NB)` on separately opened private read handles. Windows uses `LockFileEx(EXCLUSIVE | FAIL_IMMEDIATELY)` on a dedicated byte at 64 MiB beyond EOF. This leaves the fixed marker and its 64-KiB buffered read window available for peer validation and allocates no 64-MiB payload. Actual native handle closure retires the runtime lock, including process death. Token files persist without persisted reservations, replacement, unlink or an unproven reset. Held files and their directory ancestry count toward the existing native-handle bound. This coordinates cooperative instances; it does not claim security against arbitrary code with the same user's ability to alter owned filesystem objects.

The existing bounded owner thread serializes commands, checks actual authority and retains the directory through final readers. Product scratch operations hold their admitted I/O turn through this work. The current native integration fixtures use one declared data root/device. **Multi-device admission for profile coordination and scratch on different devices, portable/package/sandbox/Windows session variants, bounded-memory fallback and complete native resource/scale qualification remain required before public spill.** No private-location or IPC-only fallback is silently selected.

## Historical IPC-only prototype

The Guid-only entry is now internal and remains for primitive and counterexample fixtures. It is not the application acquisition factory. Its scope is one native IPC domain; the actual namespace test below demonstrates why that boundary alone cannot qualify production spill.

This prototype uses explicitly current-user-only, cross-session named mutexes on Windows. A bounded dedicated owner thread preserves mutex thread ownership. An abandoned token protects no mutable state and is reusable. Held tokens count against native-handle admission, and a planted object of another type is preserved and refused without exposing the private namespace digest.

On Linux/Darwin the prototype uses an owner-private System V semaphore set, `SEM_UNDO` capacity/registrations, a nonblocking registration lock and strict UID/mode/shape/protocol checks. It ignores runtime-directory environment choices. Unknown or uninitialized records are preserved; no SETVAL/SETALL repair is used. Last ordinary close retires an idle initialized set, and actual process death restores its capacity within that IPC namespace.

Its namespace hashes contain no source names. Finite-key collisions can conservatively combine capacity or refuse a foreign protocol. A crash before initialization can leave an unavailable record. Separate IPC namespaces can provide an additional ceiling, so this prototype is insufficient for the public acquisition path.

Both modes retain at most eight owner threads per process, a one-item command queue and actual-worker join at final closure. Native requests are nonblocking for contention; Unix interruption retry is bounded. Missing primitives or operational failure refuse the affected work. Public bounded-memory fallback and end-to-end device/resource limits remain required.

## File-boundary qualification checkpoint

The actual Ubuntu r382 namespace fixture holds all 8 GiB in an ordinary helper, launches another ordinary helper in a different observed IPC namespace, and observes the internal IPC-only prototype admitting one additional byte. With private-file capacity, the second helper exits with the explicit capacity-refusal code while the first still holds its reservation. Killing that first helper releases its locks; a fresh namespace then reserves the full 8 GiB. All helper PIDs exit, profile/token bytes and the neighboring canary stay unchanged. Namespace setup alone uses sudo; setpriv drops all UID/GID/capability authority before executing FileCat, whose ordinary-process checks still apply. This is a capacity primitive proof, not 8 GiB of scratch payload or a 10M-source/resource benchmark.

Native regressions exercise same-profile owners, failed growth without reservation changes, retained owners, wrong UUID/foreign marker preservation, and normal/crashed owned children on all three platforms. They exposed missing-token translation on Unix and Windows buffered marker reads overlapping the initial lock byte. Those rejected candidates are retained; the native lock byte now lies beyond read-ahead. A Unix fixture initially attempted an ordinary .NET shared-lock read while its own exclusive lock remained active; it now verifies bytes after actual quota closure. An earlier Windows IPC-only crash control now waits for actual capacity recovery after process-exit notification rather than assuming immediate kernel-lock retirement.

Final r393 core suites pass 574/576 with two platform skips on Mac and Ubuntu, and 554/594 with 40 skips on Windows; all 36 Windows native cases pass. Final r394 rendering suites pass 79/79 on Mac/Ubuntu and 78 with one Unix-only skip on Windows. Native indexed r397 workflows pass again on all three, preserving 509 generated paths and exiting with empty scratch. Read-only r398 checks find the valid file-capacity token matching each workflow's recorded private profile. No public feature/resource/package gate or final independent review is closed by this checkpoint.
