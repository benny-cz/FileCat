# Active-analysis profile capacity

This implements an internal cross-process scratch-capacity owner for plan §27.12. It does not enable public indexed acquisition or qualify the complete resource, package or persistence gates. Product commands, operations and the privileged helper remain off.

`AnalysisProfileQuota.Open` accepts a nonempty UUID from trusted application-owned private profile state. Imported `SessionIdentity.HostProfile` values must never choose this namespace. A supplied `AnalysisStorageOptions.CreateProfileQuota` factory runs on admitted storage work. The workspace retains the quota independently of that factory/owner, and derived arenas, datasets and readers retain it through their shared private directory. Capacity returns after the actual scratch file closes; an original owner closing cannot release a still-readable dataset's reservation.

Each owner rounds its current byte reservation up to 256 MiB capacity units. Thirty-two units impose an 8 GiB ceiling across cooperating ordinary processes using the same private profile and OS coordination domain. This is reserved capacity, not a claim that 8 GiB of payload has been written. Conservative rounding can refuse smaller concurrent sessions before their exact bytes total 8 GiB. The existing 4 GiB session limit, process budget and free-space reserve also apply. Failed capacity growth rolls back its new units and its parent byte reservation before any payload write.

Windows uses explicitly current-user-only, cross-session named mutexes. A bounded dedicated owner thread acquires and releases each mutex, preserving Windows thread ownership. An abandoned token protects no mutable state and is reusable. Held tokens count against the native-handle admission. A planted object of another type is preserved and produces an operational refusal without exposing the private namespace digest in the error.

Linux and Darwin use a kernel-only owner-private System V semaphore set with capacity, protocol marker, registration count and a short nonblocking registration/removal lock. `SEM_UNDO` accounts for both held capacity and registrations until actual process exit. No runtime directory, `TMPDIR`, `XDG_RUNTIME_DIR`, source path, PID file or file lock selects the namespace. Native calls verify the ordinary UID, creator, 0600 permissions and exact record shape. Atomic GETALL snapshots validate the protocol. Unknown, nonprivate, malformed, inconsistent or uninitialized existing records are unavailable and remain unchanged. The implementation never resets an existing set with SETVAL/SETALL. Last ordinary close retires an idle initialized set while holding its registration lock; process death restores its capacity, and a later owner can reuse and retire the idle protocol record.

Namespace hashes contain no source names. Unix's finite key can conservatively collide, combining capacity or refusing a foreign protocol; it must never provide extra capacity. This is coordination among cooperating processes within the same native IPC domain, not protection against an arbitrary process with the same user's ability to modify owned IPC objects. Container/IPC namespace separation, Windows logon/terminal-session variants and packaged/sandboxed applications require explicit profile-to-domain agreement before production spill is enabled. A crash before an initializer publishes its protocol can leave an unavailable record; no unproven repair or filesystem fallback is used.

At most eight quota owner threads exist in one process. Requests are serialized through a one-item command queue, and final closure joins the actual worker. Unix kernel operations use NOWAIT, bounded lock attempts and bounded interruption retry. Missing native primitives or operational failures refuse the affected work. Production bounded-memory fallback, trusted profile connection and all end-to-end native resource limits remain required before the public acquisition switch.

## Regression evidence

The original managed-mutex Unix candidate failed on Ubuntu when an owned child changed its private runtime environment: it acquired a second ceiling. The retained r271 negative receipt records that failure. The kernel-only candidate passes the same test and cross-process normal/crash/new-Unix-session controls. Two final cases also confirm full capacity after the last child alone exits normally or crashes. Foreign-record controls independently plant uninitialized, unknown-protocol, wrong-shape, nonprivate and inconsistent-idle Unix records, checking that their values and last-operation PID remain unchanged. Dataset controls retain real hierarchy readers after factory/owner closure and refuse a full profile before the first scratch payload write.

Final r283 analysis/command regressions pass on the actual Mac (556 total, 554 passed, 2 platform skips), Ubuntu VM (556/554/2), and ordinary Windows VM account (574 total, 538 passed, 36 platform skips). All 32 Windows native filesystem/private-storage controls pass. Native hard-link and 6,002-path source fixtures opt into the quota and retain existing source/canary/cleanup assertions. The r282 solution build has zero warnings/errors. Fresh post-checks show no remaining owned FileCat or test process. These are native functional tests, not desktop-input, 1M/10M whole-pipeline, memory/handle/thread envelope, diagnostics ZIP or complete package qualification. The final independent review remains pending until the complete implementation/testing loop finishes.
