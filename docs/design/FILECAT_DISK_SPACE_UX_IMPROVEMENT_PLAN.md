# Disk Space Analysis UX and UI improvement plan

## Recommendation

Prioritize room for the results and put plain-language scope, measurements, and outcomes next to the controls they explain. The project owner interpreted the main information as intended in all five walkthrough screens. The case for this work is the effort required to find and read that information, especially in a short window. Use the current accounting, captured-source boundaries, and action eligibility as the basis for the presentation. [Analysis plan](FILECAT_DISK_SPACE_ANALYSIS_PLAN.md) · [Walkthrough](../validation/disk-space/UX_COMPREHENSION_STUDY.md).

## 1. Give the results more room

1. Keep the current scope, metric, coverage or freshness state, and active scan controls in view. Put second-order information such as component coverage, boundary and issue counts, storage mode, and diagnostic detail under a keyboard-accessible **Coverage details** control. Show exceptional states in the summary when they materially change the result. For example, use “Partial results · some folders were not read” when the captured evidence establishes that gap. Retain a visible incompatible-basis explanation and distinguish scan exclusions from display filters.
2. Keep the view switcher and the controls needed to navigate, filter, and inspect the current result together. Put secondary result commands such as open/import, export, history, recipes, and resource limits in a clearly labeled **Analysis actions** menu. Keep Save, Compare, the current scan controls, and the setup view's Start and Open actions directly reachable. Reuse the existing handlers, availability, disabled reasons, and themed keyboard and pointer help. Restore focus to the menu trigger on dismissal.
3. Start with the chart color legend collapsed. Keep its current color dimension visible in the legend trigger and retain the open state across metric, focus, and theme updates in that view. At wide layouts, give reclaimed height to the chart, table, and inspector. At compact widths, build on the table-first view and give it a directly reachable **Inspect selection** action. Keep the list viewport finite and virtualized.

Apply the same command grouping, summary order, and legend behavior to the memory and indexed result views. Keep their existing navigation and data ownership paths. [Memory view](../../src/FileCat.App/Views/DiskSpaceWindow.cs) · [Indexed view](../../src/FileCat.App/Views/DiskSpaceWindow.Indexed.cs) · [Color legend](../../src/FileCat.App/Controls/DiskSpace/AnalysisColorLegend.cs).

**Acceptance.** With the r1795 fixture at the same dimensions, the chart and inspector receive more visible space than the baseline. At 380 × 430 DIP, the scope, coverage, and first result row are readable on load at the existing large-text setting. The user can reach filtering, inspection, scan control when present, and cleanup review with the keyboard at compact widths and at 200% text scaling. Secondary commands and their reasons are reachable using their named trigger. Changing presentation preserves the captured scope, selected row, marks, and basket, and keeps the chart and table synchronized.

## 2. Make the inspector explain the selected amount

1. Use the active metric's visible name and format its value consistently with the chart. In the shared hard-link case, show the charge first and name the other measure **File size across matching paths**. In the r1795 example the two rows would read **On disk — reported · 1.0 MiB counted once here** and **File size across 2 matching paths · 2.0 MiB** using the current locale. Follow immediately with the current common-parent and remaining-link explanation. Derive the wording from the actual metric, scope, and known coverage. Show explicit unknown and partial states for incomplete charges and reference totals.
2. For a selected folder whose contents could not be read, put that outcome above size and path. Explain that **0 paths observed** is an observation count and the contents and size remain unknown. Use narrower wording for partly read, excluded, unverified, and stale entries according to the recorded evidence. Move the long captured path and low-level evidence below the interpretation, with the existing path and details actions available.
3. Apply the same order in the inline inspector, compact inspector, and indexed bucket details. Use localized values for reading and retain exact values, raw-name evidence, and all existing privacy and safe-display behavior in details and copy. Keep measurements and their state available through the keyboard and accessibility tree.

Build from the current typed measurement formatting and shared-link explanation. Render the summary from data the view already has for the selected capture. [View model](../../src/FileCat.App/ViewModels/DiskSpaceViewModel.cs) · [Memory inspector](../../src/FileCat.App/Views/DiskSpaceWindow.cs) · [Indexed inspector](../../src/FileCat.App/Views/DiskSpaceWindow.Indexed.cs).

**Acceptance.** Treemap and Sunburst show equivalent interpretation for the same selection. The fixture shows 1,048,576 reported bytes counted once, 2,097,152 logical bytes across the two references, and two paths in the inspector and exact details. An unreadable directory with a neutral name presents an unknown size beside zero observed paths. A genuinely empty complete folder, an excluded folder, and a filtered subset display distinct states. Verify these cases in memory and indexed views under dot- and comma-decimal cultures, with matching visible and accessible wording.

## 3. Put capacity scope and cleanup outcomes first

### Volume capacity

Use **Current analysis** and **Containing filesystem** as the dialog section headings. At opening, capture the published metric, scope, coverage, and amount together so the number agrees with the visible chart or table. Use the recorded sample time for each filesystem figure. Show the possible shared-volume-capacity caveat next to the relevant volume figures. Keep reported free space and space available to the current user separately labeled. Place sample time and volume ID beneath the primary figures. For several locations, retain the per-location samples and clear scope labels. Use the existing whole-volume difference eligibility and signed display. [Capacity view](../../src/FileCat.App/Views/DiskSpaceWindow.VolumeCapacity.cs).

**Acceptance.** Both figures and their scopes can be read entirely inside the dialog at wide and compact layouts. A filtered folder view still identifies the displayed subset. Shared-capacity volumes remain individually described with the qualifier visible beside their measurements. The signed difference and volume context appear only under their existing supported scope, provenance, and source conditions. Return and Escape close the dialog and restore focus to the invoking control.

### Cleanup review

Put the selected action, its availability reason, and expected space effect together before the entry list. For unavailable recycling, show that FileCat cannot verify safe recycling and restoration for the selected entry. In the same group, explain that files moved to Trash on the same volume can still occupy space and that expected free-space gain is unknown. Keep captured size and recorded allocation together as measurements. Put method IDs and per-entry evidence under details. Let short entry lists use less vertical space while retaining bounded paging and the explicit focused-entry or basket scope. [Cleanup dialog](../../src/FileCat.App/Views/AnalysisCleanupReviewDialog.cs).

**Acceptance.** At compact size and large text, the current action, its availability, and the preserving default are readable. For unavailable recycling, the refusal is shown and the submit control is disabled. `Cancel / Keep files` keeps initial focus and handles Enter on open and Escape. Existing checks continue to enforce availability, explicit inclusion, and the reviewed source binding. Declining or closing the review retains the files. Exercise unavailable recycle, stale or recorded data, and the qualified reviewed-copy route.

## Validation and delivery

1. Implement the results layout first, then the inspector and the two dialogs. Reuse the existing renderer and native harness coverage. Add targeted assertions for the new layout and summaries where current checks cannot catch a regression. The existing chart-label, narrow inspector, volume capacity, and cleanup review checks cover measurement and safe-action behavior. Keep the current chart performance target of p95 below 33 ms for the tested workloads. [Renderer tests](../../tests/FileCat.Rendering.Tests) · [Native harness](../../tests/FileCat.NativeAcceptance/DiskSpaceHarness).
2. Run one grouped native batch per available platform using the same reviewed source, the Windows and Ubuntu VMs, and the Mac. Defer a machine while another tester is active. Cover normal and compact windows, large text, resize and maximize/restore, keyboard focus and tooltip access, and representative light, dark, and high-contrast themes. Use the existing all-theme regression and native accessibility workflows, with the relevant on-screen and screen-reader feedback verified. Preserve the disposable fixtures and close the processes launched for each batch. Compare captures with the r1793 and r1795 layouts. [Package and accessibility evidence](../validation/disk-space/NATIVE_PACKAGES_QUALIFICATION.md).
3. Regenerate the five comprehension captures with the revised layout and a neutral name for the unreadable folder. Ask readers to find the selected charge, explain the unknown contents, identify the scope and possible sharing of capacity, and state why recycling is unavailable and what remains possible. Include first-use tasks to find **Coverage details**, **Inspect selection**, and a moved secondary action without coaching. When independent readers are available, record their wording, the first control or label they relied on, and any point where they needed help. Keep the independent study pending until responses are collected. [Study protocol](../validation/disk-space/UX_COMPREHENSION_STUDY.md).
