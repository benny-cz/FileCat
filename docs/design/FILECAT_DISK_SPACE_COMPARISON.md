# Inventory comparison foundation

`AnalysisComparison` is a bounded, data-only comparison engine under development for plan §16. A development comparison tab now supports declarative queries, status cohorts, ranking, two-sided inspection and explicit structural root mapping. Comparison charts, mutable metric selection, saved comparison format and the indexed large-data path remain unfinished and unqualified. This document closes no release or security gate.

The caller retains the input snapshot/inventory leases through work and through any view that needs them. The result owns a separate process-wide work/result admission for one 32-MiB memory fallback. Its producer preflight caps estimated input work at 12 MiB and expanded raw/display paths at 8 MiB; exceeding either limit fails the whole comparison, without publishing a partial result or zero baseline. Disposing a result releases its admission; a failed or canceled build releases it too. The future indexed implementation and resource qualification remain mandatory.

The engine validates both typed snapshots and derives exact aggregate totals using the existing metric rules. File size and Files use path entities. Unique file size and On disk use one entity per observed identity group, retaining all aliases and respecting unavailable measurements. Directory-self allocation has separate entities. Display paths escape control characters, raw invalid Unix names and unpaired UTF16; matching keys retain tagged raw components and independently encoded root identifiers. Host path normalization is never a match proof.

Automatic root pairing requires the same captured canonical locator, scheme, entry/name rules and source identity. It also requires either the same recorded acquisition session/epoch/host-profile/binding reference, or the same canonical known host/profile plus a matching verified captured source/root-object identity and canonical connection UUID. A matching volume serial and path alone do not establish continuity. Missing/legacy host context, changed root object, a missing/unqualified binding, another private profile or a reopened native connection requires explicit structural root mapping. An explicit one-to-one active-root mapping allows structural comparison, including different volumes; it grants no identity continuity. Policies, observed component/inclusion bases, raw-name representation sets, coverage, freshness and host/profile/source assurance qualify the interpretation. A changed representation is limited instead of turning re-encoded names into additions/removals. A complete scope with no file observations supplies a known zero file-allocation baseline only within the same declared basis; directory component contracts must still match. Incompatible values are displayed side by side with an unknown difference. Partial coverage cannot turn a missing path into an addition/removal; typed stale scope/root evidence propagates to children. A later previous observation receives an order warning.

The private profile/host context is typed recorded correlation data; it never authenticates an imported inventory or recreates a live binding. Native backends retain per-binding random connection UUIDs. Qualification of continuity across fresh native rebinds remains pending, so separate scans require reviewed structural mapping rather than guessing from a device serial, hostname or matching directory spelling.

Path intersections match accounting entities only when the relationship is unambiguous. An identity-only move requires matching version evidence and compatible observed metadata, including creation times where present. Reused IDs, ambiguous alias splits/merges and contradictory metadata do not become confident renames. Equal amounts plus changed aliases/common-parent accounting are attribution movement, with no assertion of storage growth or unchanged contents. Changed observed IDs at the same path are replacements, requiring a different future live candidate.

Signed differences retain a sign and UInt128 magnitude, so subtracting extreme measurements cannot wrap through Int128. Zero baselines have no percentage; default ranking uses absolute difference before relative percentages. A net difference is available only with comparable complete coverage, compatible known totals and no missing/unverified amounts. Even then, reported allocation is not physical consumption or reclaimable-space proof.

All outputs are inert observations. Privacy taint joins both inputs, including privileged/imported flags. The result contains no backend, navigation command, approval token, helper request or executable path. None of its identity/version labels establishes ComparedContent, a live target, or permission to mutate a current file. Current file actions require the plan's independent explicit source binding and fresh review.

## Development comparison view

Compare captures the displayed revision before its review, freezes that interaction, names the full-inventory scope and captured metric, then reads the previous private inventory on admitted workers. The current display filter/folder does not reduce either input. The CPU comparison runs off the UI thread. A new offline tab owns both input leases and the result, so closing the original view cannot retarget or invalidate its observations. Canceled/failed work publishes no partial comparison. A comparison tab is temporary work and requires a preserving Keep open / Discard comparison choice.

The tab shows previous/current known amounts, unavailable and identity-unverified qualifiers, exact signed differences, observation intervals and compatibility reasons. Its virtualized rows support status cohorts, absolute/relative/current/path ranking, and separate removed/unknown entries. Detail overlays retain both path sets, modified times, metadata assurance and recorded allocation component/basis descriptions. Neither a removed row nor a current observation provides a live action target. The initial tab uses the captured metric; additional charts and metric changes remain required by the plan.

The Compare review offers an explicit structural-mapping choice. If no automatic root pair exists, mapping review is required. The retained inputs cannot be retargeted by later source-view changes. Each active Current root offers compatible Previous roots with matching entry/name rules; all selectors start unmapped. At least one unique pair is required, duplicate Previous assignments are rejected, and partial maps explain their unknown relationships and unqualified combined difference. Cancel is the default. Enter on a focused native dropdown may open that dropdown; it does not approve a comparison. Structural results retain the explicit structural label even when the chosen canonical paths happen to be equal. Preparation disposal and source-view closure cannot release the independent leases held by actual comparison work.

## Comparison queries

Apply comparison query uses the same bounded, non-executable grammar as exploration. It adds exact signed `delta` comparisons and change statuses, including `unknown` (also Previously unknown), `previously-unknown`, `replaced`, `metadata-changed` and `unchanged` (No observed metadata change). Signed thresholds and values retain UInt128 magnitude; no Int128 narrowing is performed. This does not turn unknown baselines into zero or establish unchanged contents.

The side selector chooses Current with Previous fallback for removed rows, Current only, Previous only, or either recorded side. The complete expression is evaluated independently for each alias on that side; a True alias retains the whole accounting row once, including its other aliases and full measured amount. Explicitly absent sides are Unknown; an absent side contributes False to an either-side search over recorded observations. Paths are root-relative source names, and unrepresentable names/ancestors remain Unknown for text predicates. Dates use the chosen side's captured timezone. Choose a single side for root IDs or labels that differ; invalid or ambiguous root predicates are refused. Above-table totals always describe full inventories, never the filtered cohort.

Query work runs off the UI thread with cancellation and retained input/result leases. The process admits one query worker with an 8-MiB index producer cap and a 2-MiB individual path scratch cap. This is separate from the existing 32-MiB engine work/result fallback; these are development producer bounds, not resource qualification. Filtered results retain the original comparison admission until their rows are released. Closing the source comparison cannot make an outstanding query release actual ownership early. Errors preserve the last applied result with “Filter not applied.” Unknown predicates have a visible count and an explicit uncertain cohort; changing query text alone does not change rows. Clear removes the query, while status/sort controls remain display choices. No query opens a recorded locator or creates current action authority.

Comparison controls release their row/template references on disposal. Disposed engine results clear their owned row array before releasing admission and reject further Rows access. Windows display paths use source separators even when inspected on another platform. Text sizes inherit the window's setting, with headings retaining only a minimum size.

Comparison metadata fingerprints compare timestamp UTC instants and their recorded precision, not the textual offset. The strict inventory writer normalizes dates to UTC; a local-offset native observation and its saved round trip therefore remain the same observation. This preserves actual creation/change-time differences and does not strengthen content assurance. A native Windows exploratory run exposed the false positive; eight all-metric/structural codec controls reproduce it before the fix. Native before/after scan fixtures also compare an unchanged saved revision before changing generated sources.

Enter on a focused comparison row is handled in the tunneling route before the list control consumes it. A pointer-to-keyboard regression establishes real row focus before opening the two-sided inspector; all three guest runtimes exercise that route. Keyboard behavior and full accessibility qualification still require the remaining native matrix.
