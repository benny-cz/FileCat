# Inventory comparison foundation

`AnalysisComparison` is a bounded, data-only comparison engine under development for plan §16. The comparison window, growth filters/charts, saved comparison format and indexed large-data path are not connected or qualified. This document closes no release or security gate.

The caller retains the input snapshot/inventory leases through work and through any view that needs them. The result owns a separate process-wide work/result admission for one 32-MiB memory fallback. Its producer preflight caps estimated input work at 12 MiB and expanded raw/display paths at 8 MiB; exceeding either limit fails the whole comparison, without publishing a partial result or zero baseline. Disposing a result releases its admission; a failed or canceled build releases it too. The future indexed implementation and resource qualification remain mandatory.

The engine validates both typed snapshots and derives exact aggregate totals using the existing metric rules. File size and Files use path entities. Unique file size and On disk use one entity per observed identity group, retaining all aliases and respecting unavailable measurements. Directory-self allocation has separate entities. Display paths escape control characters, raw invalid Unix names and unpaired UTF16; matching keys retain tagged raw components and independently encoded root identifiers. Host path normalization is never a match proof.

Automatic root pairing requires the same captured canonical locator, scheme, entry/name rules and source identity. An explicit one-to-one active-root mapping allows structural comparison, including different volumes; it grants no identity continuity. Policies, observed component/inclusion bases, raw-name representation sets, coverage, freshness and host/profile/source assurance qualify the interpretation. A changed representation is limited instead of turning re-encoded names into additions/removals. A complete scope with no file observations supplies a known zero file-allocation baseline only within the same declared basis; directory component contracts must still match. Incompatible values are displayed side by side with an unknown difference. Partial coverage cannot turn a missing path into an addition/removal; typed stale scope/root evidence propagates to children. A later previous observation receives an order warning.

Path intersections match accounting entities only when the relationship is unambiguous. An identity-only move requires matching version evidence and compatible observed metadata, including creation times where present. Reused IDs, ambiguous alias splits/merges and contradictory metadata do not become confident renames. Equal amounts plus changed aliases/common-parent accounting are attribution movement, with no assertion of storage growth or unchanged contents. Changed observed IDs at the same path are replacements, requiring a different future live candidate.

Signed differences retain a sign and UInt128 magnitude, so subtracting extreme measurements cannot wrap through Int128. Zero baselines have no percentage; default ranking uses absolute difference before relative percentages. A net difference is available only with comparable complete coverage, compatible known totals and no missing/unverified amounts. Even then, reported allocation is not physical consumption or reclaimable-space proof.

All outputs are inert observations. Privacy taint joins both inputs, including privileged/imported flags. The result contains no backend, navigation command, approval token, helper request or executable path. None of its identity/version labels establishes ComparedContent, a live target, or permission to mutate a current file. Current file actions require the plan's independent explicit source binding and fresh review.
