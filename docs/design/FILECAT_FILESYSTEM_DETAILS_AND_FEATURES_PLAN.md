## 1. Recommendation and decisions

**Build a shared, summary-first File-system details experience, with platform-specific evidence underneath. Correct Windows reparse presentation first. Expose existing metadata before adding more mutation commands.**

FileCat already detects far more than the normal UI communicates: Windows reparse formats, Cloud Files, WOF, streams, EAs, hard links, allocation and NTFS internals; Linux inode flags, xattrs, extent sharing and ext4 details; macOS forks, BSD flags and APFS sharing hints. Much of this is buried in the full record report. The largest gap is an accurate front layer, together with several completeness and source-binding corrections.

| Decision | Contract |
|---|---|
| One inspection entry | Evolve existing `file.fileRecord` into **File-system details…**, preserving Ctrl+Alt+Enter and the command ID. Default to a short summary; **Read full record** explicitly loads the adapted deeper metadata report with §7.4 omissions. No competing Storage details command or permanent sidebar. |
| Preserve other purposes | Windows Alt+Enter remains native Properties. Unix Properties continues through its current FileCat fallback. Ctrl+Shift+I remains cached focused-row inspection. Alt+Shift+Enter remains the existing supplementary-data tab. Compression uses its separate reviewed selection/job workflow. |
| Common structure, exact meanings | Share Item, Target, Storage, Sharing, Access and Location sections where applicable. Every observation retains subject, mechanism, scope, source, availability and completeness. Do not turn an unsupported feature into Off. |
| Information before operations | F1–F3 deliver read-only classification and summaries. F5 adds qualified names/counts and explicit values, and F6 adds optional columns. NTFS compression and EFS proceed under their own release gates. |
| Focused object | Details describes the captured focused item, even when other items are marked. It never scans a marked selection or subtree implicitly. |
| Display is not authority | Presentation taxonomy does not change traversal, copy, deletion, elevation or mutation admission. `EntryFlags.Link` currently serves conservative operational policies; do not redefine it globally. |
| No expensive browsing side effects | Use enumeration facts for ordinary labels. No per-entry open added to directory enumeration, painting, hover or accessibility. Optional columns use qualified demand queries; full extents, stream values and raw records remain explicit. |
| No generic filesystem toggles | Btrfs/ZFS policy, macOS compressed representation, EFS, fscrypt and FileVault have different scopes and effects. No universal Compress/Encrypt/Sparse/Immutable checkbox. |

The initial release can honestly label an unclassified Windows object **Reparse point**. Accurate uncertainty is preferable to claiming it is a link. Exact row subtypes arrive with a qualified tag-bearing enumeration adapter, not a hidden scan of every item.

### 2.2 Existing behavior that must not be accidentally expanded

`EntryFlags.Link` affects TreeCompare recursion, sync interpretation, folder-size eligibility, recursive file-list export, streamed transfers, SFTP uploads and edit-source admission. Search independently skips raw reparse directories. Copy/deletion also use separate `FileSystemItemInfo.IsLink` and held native tag policies. Consequently **correcting a label does not authorize changing any of those decisions**. Each future behavioral change needs its own fixture and disposition.

Existing full-record readers are deliberately broad. Windows can read USN/history, extents, security, stream previews and privileged MFT/log/index data. Unix appends hidden-data values and security information, and can read extents/raw devices with sufficient rights. Calling the full reader and hiding most of its text does not create a lightweight or metadata-only summary.

### 3.1 Filesystem-specific choices

**NTFS/ReFS/FAT/exFAT:** the details UI is not NTFS-only. Reparse points also exist on ReFS; query capabilities instead of applying an NTFS name test to all inspection. Show FAT/exFAT's supported basic information and mark absent capabilities accurately. NTFS mutation remains local NTFS only. Do not call ReFS integrity streams an NTFS feature.

**ext4:** useful additions are discoverability of inode flags, file-encryption indications, allocation, xattrs and casefold status. Qualified Linux x64 full reports can show [version 2 fscrypt filesystem keyring status](../validation/filesystem-details/2026-11-18-linux-fscrypt-policy.md#filesystem-keyring-status-for-version-2-policies). Raw `c`, `s` and `u` bits are not proof of compression, secure deletion or undelete protection: mainline ext2/3/4 do not implement those historical behaviors. Keep the raw bit/letter in technical details, label it **Recorded flag; behavior not implemented by this filesystem**, and do not repeat the current `LsattrText` promises. This applies to summary and the reused full report. Unknown filesystems get **Behavior not qualified**, not an ext4 or Btrfs interpretation. Name behavior can be per directory.

**Btrfs:** a read-only policy probe is useful later, labelled **Compression policy: zstd; existing data not assessed**. A file can contain differently encoded extents. Changing policy affects later writes; recompressing existing data is another operation. Defragmentation/recompression can break extent sharing and increase storage use. Defer that mutation until a separate scope, space, interruption and recovery design exists.

**XFS:** prioritize ordinary allocation, xattrs, flags and optional sharing evidence. Reflinks belong to a qualified copy-engine optimization, not a hard-link or Attributes control. `FICLONE` shares file data; it does not by itself prove full security/metadata preservation.

**ZFS:** later read-only dataset detail can explain compression policy, encryption/key availability and dataset accounting. Keep it under **Location → Dataset**. Compression affects new writes; encryption is selected at dataset creation, with key-root/inheritance scope. Do not introduce `zfs set`, key operations, snapshots or dataset creation here. Until a qualified adapter exists, mount identification is useful but dataset protection stays Not inspected.

**APFS/HFS+/HFSX:** reuse current macOS live queries for forks, BSD flags, compression representation and supported sharing hints. A may-share flag is not proof that a particular other file owns the same blocks. APFS-specific attributes do not apply automatically to HFS variants. Query actual naming capabilities; macOS is not uniformly case-insensitive. Record the supported ABI version and native fixture results with the adapter; existing source code alone is not runtime proof.

### 3.2 Encryption is not one portable state

The UI separates **file protection**, **directory policy**, **dataset protection**, and **volume/device protection**. EFS is not fscrypt, and neither is FileVault. Fscrypt policy establishment applies to empty directories; converting existing files requires migration rather than in-place encryption. Its confidentiality boundary does not cover all metadata.

The Linux x64 ext4 full report identifies native fscrypt v1 and v2 policies on the held directory or regular file. The summary keeps the separately observed inode flag. Policy absence is scoped to the inspected object. [Ext4 fscrypt qualification](../validation/filesystem-details/2026-11-18-linux-fscrypt-policy.md).

FileVault is volume protection; hardware encryption on some Macs and FileVault credential protection are distinct observations. An absent per-file encrypted flag cannot produce **Encryption: Off** for the entire storage stack.

Example summary: **File encryption: not reported. Volume encryption: not inspected.** For an unsupported query say **File encryption status unavailable here**, not Not reported. Do not apply EFS export warnings indiscriminately to every file stored on an encrypted volume. Future output policy must use the actual protection scope and route; this task adds no cross-platform key manager.

| Refresh | Read the displayed tier; when no snapshot exists, use the selected tier. Retain the old view marked **Previous observation** during acquisition. Successful Summary refresh discards the old full result; successful Full refresh replaces both members of the pair. |

Do not replace it with an error-only report, advance its observation time or change tier. Initial failure has no retained snapshot. |
| Tier changes during acquisition | Select an available cached tier immediately and invalidate pending publication. An uncached requested tier replaces the single coalesced pending request. Late completion cannot switch the view. |

Copy/Save captures the displayed successful tier's immutable revision, including observation time and any retained-old qualification. Loading/error placeholders are never successful snapshots. Cached switches still cancel a pending output before publication under §7.4. Publishing new data does not steal search/scroll/spoken-line focus or reset a deliberate tier choice. ## 5. Native semantics and observation contract

### 5.1 Small typed facts, not a new filesystem framework

Keep **`IPlatform.FileRecords` as the sole composition seam**. Add typed `ReadSummary` and policy-bound `ReadFull` operations to `IFileRecords`; implement them in `WindowsFileRecords`, `UnixFileRecords` and `NoFileRecords`. Retain existing `Read(string, CancellationToken)` for unrelated legacy callers/tests. Move `file.fileRecord` and the Unix Properties fallback to the new methods; neither may silently fall back to unrestricted `Read`. No sibling service, generic factory or filesystem framework is needed.

`ReadSummary` returns one immutable `FileDetailsSnapshot`. `ReadFull` returns one immutable `FileDetailsReport`: its newly acquired basic snapshot from the **same reader context**, structured technical sections, content classification, contributor provenance and observation revision. F3 selects `MetadataOnly`; F5 adds only qualified explicit-value sections. These synchronous native methods are invoked by the owned scheduler adapter; they never spawn hidden work or complete before their native ownership retires. Non-filesystem references are rejected before local acquisition. Replace `IFileRecords`' current absolute “no times/no journal entries change” comment with §5.2's precise no-requested-payload/no-requested-mutation contract; metadata access can still involve provider/OS activity.

Use the typed basic snapshot for summary, optional fields and report rendering; never reverse-parse `InspectionReport` strings. Proposed fact shapes below define the contract; the named service methods/results above are the chosen integration path:

```csharp
enum FactState { Known, NotInspected, NotApplicable, Unsupported,
                 Denied, Missing, Changed, Partial, Failed }
enum FactScope { Entry, MainData, NamedStream, AllForks, DirectoryPolicy,
                 Namespace, Dataset, Volume, ExtentSample }
record ObservedFact<T>(FactState State, T? Value, FactScope Scope,
                      string Source, string? Reason);
// FileDetailsSnapshot: captured subject, observation time, identity evidence,
// typed object/storage/link/platform facts, completeness, safe navigation target.
// ReadSummary does bounded metadata work. ReadFull remains explicit.
```

Capability is per field/action/provider, not one SupportsNtfs Boolean. Keep unknown numeric values/tags available in detail. Preserve the raw/native source meaning separately from formatted common labels. An observation time is not an atomic snapshot. Query ordering and current identity must remain explicit; report detected changes rather than assembling contradictory object/target facts.

For Linux use returned statx field and attribute masks; a clear unsupported bit is Unknown/Unsupported, not No. `stx_blocks` is in 512-byte units. macOS requires both the returned getattrlist bit and a fully present, correctly packed field before accepting a scalar. Check the leading length, actual buffer length, slot bounds and overflow; distinguish required size from bytes present. The current `MacAttributes.Query` accessors substitute zero on a short slot, which must not become a Known zero merely because its returned bit is set. Invalid/truncated output is Failed/Partial with only independently validated fields retained. The present 1,024-byte buffer exceeds its fixed request; this is a parser robustness repair, not a claim of observed native truncation. Keep validity/capability bits distinct from unsupported fields. Do not use `TotalSize ?? 0`, comparer fallback or missing nullable fields as a real zero/false in the new snapshot.

### 5.2 Metadata access and provider activity

The summary requests no file payload, hashes, thumbnails, stream/xattr/EA values, target existence checks, directory descent, FIEMAP synchronization, raw volume reads or full security history. Special objects receive safe metadata queries only. A path-level type precheck is insufficient: regular-file stat → replacement by FIFO/device → ordinary open can already access the wrong object before a postcheck. Linux can pin with `O_PATH` and query supported metadata on that descriptor; it cannot assume that descriptor supports ioctl/fgetxattr. Any extra probe needing another descriptor must establish a qualified same-object acquisition, or remain unavailable in this tier. `O_NONBLOCK` and final `O_NOFOLLOW` alone do not solve replacement by a non-symlink special object. Apply the equivalent capability/identity requirement to other platforms rather than guessing a universal open recipe.

The macOS summary has its own explicit attribute request mask; do not reuse the full `MacAttributes.Query` mask. Request only the basic identity/type/time/flags and qualified size/allocation fields used by the summary. Exclude `ATTR_DIR_ENTRYCOUNT` and other optional directory statistics: the repository's full request includes this extra work, whose cost has not been qualified for summary use. No summary or ordinary column asks for it. A later explicit count is an immediate native entry count, not a recursive total or stable census.

No-follow does not mean no network, automount, FUSE/filter callback or cloud activity. State the defensible guarantee: **FileCat requests metadata, not content**. Do not promise that all providers cause zero network traffic or OS metadata changes. Recognized recall-on-open/dataless objects use cached facts unless an independently qualified metadata-only path is available; unsupported queries get a precise reason. Never retry a refused metadata query by opening file contents. Test known Cloud Files/File Provider/dataless cases; unknown vendors remain a declared limitation.

Windows attribute provenance matters: enumeration's `0x40000` recall-on-open meaning overlaps queried EA semantics. Do not feed all raw masks into `CloudFiles.StateOf` without source context. Pin/unpin is intent, not measured residency. A listing sparse indication can mean a stream has been sparse; it does not establish current holes in main data.

### 5.3 Bounds and ownership

For the details window's summary and explicit full requests: one in-flight request per window plus one coalesced pending refresh; at most **8 admitted queued/running/retiring requests per process** and a proposed details-specific admission limit of **4 per device**, subordinate to scheduler capacity. `DeviceIoScheduler` currently defaults to two normal workers and six maximum per device; do not change its global policy to fit this limit. Both tiers share these admission limits, so repeatedly canceling a deeper read cannot bypass them. A canceled native call retains its slot/handles until return; closing a window stops publication and further queries, not resource ownership underneath the call. Never wait on the UI thread or accumulate a worker per refresh. Reserve global and device admission together outside device workers; if either is unavailable, keep only the coalesced pending request and hold no partial reservation. Dispatch through `DeviceIoScheduler.RunOwned` with request/window and `StoppingToken` cancellation.

The adapter owns one idempotently disposable permit lease **outside** the delegate, covering enqueue and awaiting `RunOwned` in `try/finally`. Release it on enqueue failure, scheduler rejection and never-started cancellation, as well as after an entered delegate actually returns. The delegate disposes its native handles before completion; results contain immutable observations, not live handles. `RunOwned` supplies the running-owner completion boundary. Never release from an ordinary cancellation callback or rely solely on a delegate `finally` that may never run. A watchdog replacement does not finish the old owner. This lifetime applies to F2/F3/F5/F6. Never synchronously wait for same-device child work from an occupied worker. Keyboard Refresh/F5/Control-R uses the same controller as the button; disabled button state alone is insufficient. Shutdown discards pending requests and prevents any next native query or publication.

Initial bounds: **4 owned object/search handles per summary request**, **256 KiB retained summary metadata**, **16 KiB reparse payload**, **1,024 extra-data entries / 1 MiB names metadata**, **1,024 hard-link names / 1 MiB name data**, and at most **two bounded resize/retry cycles** for changing inventories. Reject oversized records safely, retain explicit Partial/limit reasons and stop no-progress loops. Long names must produce a truthful limit/error, not an empty inventory. These are acquisition bounds, not post-formatting truncation rules. For every retained new summary/full section, check cancellation before the first native call and after each returned call before starting another; validate byte/count/cursor progress before a continuation. An in-flight native call remains owned until return. F3 omits the **entire legacy supplementary section before `HiddenDataSection.Of`/`IHiddenData.List`**, plus unadapted hard-link-name, retrieval-pointer/sparse-range/FIEMAP collections and all raw-volume acquisition sections. Their old first-40-row/8-MiB-text caps do not bound upstream work. State each omission in the full report. F5 restores the bounded metadata collectors under §7.3; it does not require restoring raw-volume readers. Raw privileged acquisition remains unavailable from this new route until a separately qualified explicit section has a working-memory reservation, cancellation/binding and payload-output contract. Preserve legacy APIs for their existing other callers, but never route around an omission through them.

Optional-column caches have a separate **8 MiB / 4,096-observation** budget for new typed detail values, whichever fills first; reuse existing scheduling/publication infrastructure. Cache misses cause truthful pending/eviction states, not unbounded analysis or a false complete sort. Detailed reports retain their own explicit bounds; cap newly assembled summary-plus-full text at **8 MiB**, with an omitted-detail notice. Parsing remains bounded before formatting, so a text cap is not the only memory defense. The existing raw-log reader permits a 512-MiB result and an additional run-sized copy; the F3 omission happens before those allocations. Do not claim that an 8-MiB text cap bounds process working set. Every retained full section needs a reviewed acquisition bound before enablement; unqualified sections remain explicitly omitted.

**F5/F6 query ownership is explicit:** new inventory and native optional-column producers join the same **8-process / 4-device queued/running/retiring observation allowance** through the shared adapter; the one-in-flight/latest-pending rule remains per details window. Acquire once per producer operation, not recursively per field or native call. Reserve outside device workers before queueing; listing/metadata code that already owns a worker calls a synchronous already-admitted producer rather than queueing and waiting on itself. Preserve the scheduler's existing total capacity. Inventory cancellation or tab retirement retains the real running owner; F6 demand/Analyze uses `RunOwned` completion for this producer family. Requests identify the original filesystem/provider/device, never a synthetic results device. Ordinary unrelated metadata producers remain unchanged. If a consumer cannot supply that ownership, it reports unavailable rather than bypassing admission. The retained cache budget is separate from this in-flight quota.

### 5.5 Recorded restrictions are not an effective-access decision

Share raw mode/UID/GID, ACL entries, BSD/inode flags and observed capability/security labels with their source and applicability. The summary does not add value reads to obtain ACL/security xattrs. Keep warnings about sensitive recorded settings, with this limitation, and update the existing exact-text tests. **Existing Find inventory consumer is part of F5.** Replace `SearchEngine.CarriesHiddenData`'s combined `IHiddenData.List` call with the same bounded typed inventory. The first Windows predicate is explicitly **Carries alternate data streams besides its download mark**; its help says EAs are excluded. It performs zero EA-value queries. A saved older broad “streams or attributes” predicate requires the user to replace it with this scope or clear it before running; do not silently migrate its meaning. Partial/denied/unsupported/changed/failed candidates are unexamined and counted in the result's incomplete-coverage notice with bounded diagnostics. Recognize download marks by platform + typed category + exact native-name rules, not the current global name-only set. Recursive EA-value search is deferred.

Explicitly admitted EAs have their own category snapshot and source binding. Do not expand new creation/rename/bulk-removal support. Existing exports and deletes must retain their confirmations and acquire current object/name authority. ### 7.2 Managed metadata is not an ordinary attachment

Identify known storage/security/synchronization metadata before exposing generic deletion shortcuts. Examples: macOS `com.apple.decmpfs` and compression-bearing forks, Linux security/system attributes, and recognized provider control metadata. Mark their role and route applicable changes through the proper existing permissions/provider tool; **do not offer deleting a compression attribute as Remove compression**. Unknown metadata must not be called harmless, and known managed metadata must not silently lose its role through export/import. The initial safeguard is a conservative refusal for recognized managed-storage/security controls, with a specific reason. Preserve Windows EA raw flags: **FILE_NEED_EA** is positive evidence that the attribute is required to interpret the file, even when its vendor/name is unfamiliar. Mark it **Required metadata** and refuse generic deletion. Preserve unknown native flag bits diagnostically; do not manufacture harmlessness. A qualified WOF backing stream such as WofCompressedData is storage-managed payload, not an ordinary optional attachment. Apply the role guard after current typed-item resolution in every focused/marked/delete invocation, not only by disabling a menu. Revalidate the role before the actual deletion; no same-name/category fallback. Ordinary user data and existing download-mark removal retain their scoped review. This is not a promise that every vendor's reserved metadata can be recognized.

Copy preservation is also route-specific. Existing macOS handle-based copy covers forks/xattrs/ACLs, whereas the inspected Linux normal-copy path calls POSIX ACL copying without a general equivalent xattr-copy call. Do not claim all extended metadata is preserved cross-platform. The inspector describes the source; changing transfer preservation is separately scoped and tested.

### 7.4 Reports can contain payload bytes

The lightweight summary contains metadata only. The full record can include decoded stream/xattr excerpts; report export is therefore an additional concrete output route, not automatically harmless metadata. `ReportWindow.SaveAsync` writes `_text` through `File.WriteAllTextAsync`; `HiddenDataSection.Of` can populate it from stream values. Add **E-OUT15** to the EFS plan for reports with EFS-derived excerpts, using the same actual-source provenance and destination-loss policy. Metadata-only reports do not acquire an EFS warning merely because they name an encrypted file.

**F3 ships a metadata-only report route.** Carry an explicit MetadataOnly/ContainsPayload/Unknown classification and origin evidence; do not infer it from text. Omit value excerpts and mixed raw acquisitions **before reading them**, recording **Data excerpts omitted; this route is not qualified**. This includes `HiddenDataSection` values, raw MFT resident bytes/slack, resident-content log previews and raw ext4 inode bytes that may contain inline data. Calling the broad reader and dropping a rendered section afterward is insufficient. If an acquisition cannot separate qualified metadata from payload, omit that acquisition. Keep the remaining technical metadata and ordinary summary export usable. There is no optional full-payload branch in F3. F5 may restore independently qualified explicit-value sections with the complete origin/output contract; its completion is not needed for F3's safe omitted result. This is not a claim that the original full reader was metadata-only.

Retain origin on a derived report after source handles close; a later source-path change cannot erase it. Save/export approval covers destination replacement as well as source protection. Cancellation after an approved write can leave partial output; do not promise zero bytes after output has begun. Raw privileged records and attribute values remain explicit deeper work and must not run just because FileCat happens to be elevated. The summary never invokes them.

The same report contract covers **Copy all**, selected/visible source copy and displayed-text copy: `ReportWindow.CopyAsync/CopyTextAsync` publish to the OS clipboard. Rendering controls as symbols does not remove payload origin. For a payload report with qualified **EfsDerived** origin, require route-specific approval to publish unencrypted content, or refuse; the clipboard may be retained by the OS/other applications and does not preserve EFS. **Unknown protection or unresolved contributor binding refuses file and clipboard publication until qualified**, even if a consent callback returns Yes. Unknown content classification must be classified or omitted/refused, never treated as MetadataOnly. This is the existing E-OUT rule, with no report-only exception. Publish an immutable report revision containing text, content classification, origin union, observation identity and revision together. Every Save/Copy variant captures that exact revision before a picker or consent await. For this details route, refresh, tier switch or close **cancels a pending output before its first publication/write**; recheck the revision after awaits. Never approve report A then write mutable `_text` from B. Preserve the existing Copy generation checks and add the equivalent Save owner/cancellation guard. Once authorized output begins, report actual partial output/cancellation honestly. Initially use the report's conservative contributor union rather than inventing per-character provenance. Metadata-only summary copy remains ordinary. Cancellation after clipboard publication cannot revoke copies already observed elsewhere. This closes the new details/report route; it does not claim a completed application-wide clipboard audit.

## 8. Columns, filtering, and provider boundaries

No new default columns. Use existing Kind/Details where present, and optionally add **Kind** to a newly chosen Links layout. Do not rewrite saved profiles or shift Alt+digit assignments. Keep the current Link target field ID, but use typed target semantics so a WOF description or app identity cannot appear as a navigable filesystem path.

Read-only follow-up columns: **Allocated**, **Hard links** (regular files), and **Reparse type** on Windows. Each optional column has a field description, scope and unsupported/pending/error text; folder allocation is never recursive. Shared Kind display does not need a new sortable metadata field merely to label an item.

`MetadataService` currently caches by path/mtime/size, rejects every Offline row before producer dispatch, and uses name-only applicability. Storage facts can change without mtime/size. Introduce narrowly typed eligibility and observation revision/expiry for these producers, with listing-generation invalidation, post-job invalidation and bounded refresh. Do not globally remove the Offline guard: only individually qualified metadata-only producers may run there. Keep pointer/accessibility routes cache-only. Sorting uses an immutable captured set of produced keys; no provider I/O in comparison. Unknown sorts last in both directions. For `hidden`, only an exact complete count of its declared category/API-view scope supplies a numeric sort key. Lower bounds such as **2+**, uninspected categories and stale/partial/error states use an unknown key, even when useful partial text is shown. If complete ordering cannot be retained within the byte budget, show partial coverage or refuse completion; do not label a viewport-only sort complete. Reuse Analyze folder only after adding these field-specific invariants. Avoid implementing a new sorting framework in this plan.

Find first adds Windows raw **Reparse point**, **Sparse attribute**, and **Offline attribute** predicates with precise descriptions and no new content reads. Offline tests that specific native bit; it does not mean all cloud files, recall state or synchronization status. A later recall predicate requires explicit enumeration/query provenance to disambiguate the overlapping EA bit. Exact tag filters can follow only when the search enumeration carries tags or a separately explicit bounded query does so. Unreadable subtype is Unknown, not a negative match silently omitted. Keep existing reparse recursion exclusions unchanged. `SearchEngine.MemberMatches` must inspect both `AttributesSet` and `AttributesClear`: any active native filesystem mask other than Directory is unsupported for an archive member, in both archive search and search-within-results. Such members are not positive matches for either polarity; count their excluded scope as unexamined and disclose incomplete coverage. Name/size/time/Directory-only archive searches remain unchanged. Archive compression/encryption is a different scope and supplies no negative filesystem fact. Query admission rejects unsupported predicates for a wholly unsupported root; mixed searches keep the supported native scope with visible per-provider unavailable accounting, never silent broadening.

Cross-platform Compressed/Encrypted criteria must state their source. Existing `FileAttributes` predicates do not imply Btrfs-policy, fscrypt, APFS-volume or ZFS-dataset coverage. Disable/rename unsupported predicates rather than advertise a filesystem-wide search that returns false negatives. A shared no-I/O capability validator runs at query admission for fresh, restored and refinement queries, before enumeration. Check active **set and clear** masks; disabled controls alone do not neutralize saved masks. Refuse an unsupported criterion with its exact name/source and an explicit **Remove this criterion** path. The Advanced dialog retains the unsupported selection visibly and allows its removal while preventing new unsupported selections. Never silently drop it, broaden a saved search, or evaluate unavailable evidence as false. Shared later filters such as **Symbolic link** or **Immutable flag reported** need provider-defined observations and missing-data accounting, not reused Windows bit positions.

Local mounted filesystems may support detail even where mutation is unavailable. SMB/mapped shares may expose partial read-only facts, labelled server-reported; keep opaque server reparse payloads opaque unless a specific protocol is qualified. SFTP/archive/MTP/Registry objects retain existing provider details/cached inspection; no local stat/PInvoke on their display paths and no assertion that archive compression/encryption is filesystem protection. A future remote details adapter must use actual protocol capabilities, not silently download content.
