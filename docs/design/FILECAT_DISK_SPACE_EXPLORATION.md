# Disk space exploration checkpoint

This records the bounded table-order and breadcrumb development implementation. It does not qualify W2, register the product command, enable operations or establish the final resource/display/accessibility matrix.

`AnalysisTableOrder` sorts references to immutable accounting rows. Exact UInt128 comparisons avoid floating-point rounding. Missing or policy-excluded numeric values follow known amounts in both directions; partial amounts retain their known subtotal. Name ties use ordinal spelling and stable record keys. Sorting the table does not alter the accounting tree, chart area, captured scope, focus, marks or basket.

The merge worker checks cancellation at least every 4,096 copied references. Before allocating its two arrays it reserves a conservative 24 bytes per row plus headers from a shared 32 MiB ordering pool. The returned owner retains that reservation until its published or pending rows are released. Admission failure retains the preceding rows and explains refusal. Scope, history and rows now commit together only after admission; navigation cannot label old rows as a new scope on refusal. This separate reference-array budget is not whole-process or indexed 1M/10M qualification.

The view owns the published ordering and any pending interaction revision independently. Forced rebuild requests cancel the preceding worker and restart after actual completion. Scope workers retain their own snapshot lease through cancellation and tab closure. Stale scope/order results cannot publish; prior published owners are released after synchronous view updates, including when an observer throws. Deferred interaction results revalidate scope and ordering before adoption.

Breadcrumbs derive only from the captured accounting hierarchy. The root, current location and nearby ancestry remain visible; deeper ancestors use an explicit menu. The trail is bounded, including deeply nested synthetic Other scopes. A navigation callback rechecks that its target remains in the current trail. It does no filesystem access and grants no action authority. Back/Forward preserve the same independent focus/mark/basket identities. Each history direction retains at most 128 recent locations without changing scan policy or saved inventory identity.

An in-flight navigation holds a CPU interaction freeze while keeping its own snapshot lease. Incoming scan/filter projections remain pending. If ordering changes, the worker releases its former ordering and computes the requested scope again before committing it. After commit, a pending projection is revalidated against the committed scope. Refusal, cancellation or closure cannot consume history or publish a partial navigation. Three controls exercise actual blocked work, injected admission refusal for drill/Back/Forward, concurrent filter/order changes and bounded recent history.

The table resolves Enter before ListBox consumes it, so folder/group activation and file details follow the analyzer keymap. Space on a table row toggles its mark through that keymap. A focused mark checkbox keeps its own press/release cycle, avoiding a second toggle on keyup. Text editing and dialog guards remain in the existing resolver.

Four presentation controls cover exact extreme integers, missing/zero/excluded values, cancellation/refusal/disposal, pointer focus with Enter/Space, sorting and navigation with preserved references, and folded ancestry. The final r46 suite has 42 passing cases on Windows VM, Mac and Ubuntu. Initial failing Enter and checkbox cases are retained as reproduction evidence. Native input receipts identify their exact binaries and distinguish pointer, keyboard and accessibility routes.

Still required: persisted table ordering, grouping/color dimensions, complete columns/details/tooltips, captured sort-order range selection, broader native keyboard/screen-reader/theme/DPI/display coverage, complete lifecycle/registration and indexed scale/resource qualification. Named saved display state currently restores its existing metric/chart/query/root/real-scope fields; table ordering remains temporary. Children subdivide the remaining surface in their existing measured ratios; accounting, exports and table values do not change. ## Captured table ranges

Ctrl/Command-click toggles a real row mark, including an already focused row, without changing the review basket. Shift-click and Shift with arrows, Home/End and Page keys mark the inclusive range in the currently published table order. A retained bounded mark baseline allows subsequent Shift gestures to shrink that range while keeping unrelated marks; Ctrl/Command plus Shift adds to the current marks. An ordinary focus/mark gesture starts a new anchor. A missing or out-of-scope anchor starts at the target rather than including hidden rows. Synthetic rows are omitted from implicit ranges with an explicit status explanation; Mark current members remains the deliberate bounded expansion action. Folder rows contribute their own observation references rather than silently expanding descendants.

Only the current immutable row sequence is enumerated. Marks commit after the entire candidate passes the 100,000-path bound; refusal preserves focus, marks and basket. Equivalent publications rebind the range to its new admitted order owner only when acquisition identity and the entire ordered key/ID sequence match. The range does not retain a reference array after its order reservation is released. ## Private indexed record foundation

EntryStore compatibility/memory review: the existing 48-byte flat listing records, mutable Update behavior and synchronous spilled Get/mapped-read contracts do not represent hierarchical allocation observations, object aliases, storage components or immutable analysis epochs. The new primitive adopts bounded pages and complete-before-publication behavior; it does not reuse the listing file format, map disk data into UI indexers, or extend EntryData with analysis authority. Typed analysis record codecs and reader/projection integration remain required.

AnalysisScratchArena owns a no-follow private directory and an unpublishable temporary file. Linux uses O_TMPFILE|O_EXCL for scratch, independently of publishable inventory staging; Darwin unlinks a verified empty private file before payload I/O; Windows sets delete-on-close in exclusive create. The existing saved-inventory publication/durability path remains separate. Direct offset I/O has no buffered stream that can flush a failed tail on an old read. Runtime-only HMAC keys authenticate bounded record headers/payloads/offsets and are never inventory data or source authority. Native privacy/ancestry verification and fixed allocation/read bounds precede disk access. A failed append stops new writes, keeps the prior published end usable and retains the full claimed extent until native/reader ownership ends. Cleanup closes exact owned files; a user-created neighbor remains untouched even after abrupt helper death.

AnalysisScratchVector packs up to 512 records / 256 KiB per block and keeps only a capped 65,536-block directory in memory. Completed 1024-entry directory pages are immutable and shared; a checkpoint copies only the incomplete tail. Each of at most eight reader leases holds one bounded authenticated block cache. Dense IDs resolve by directory search without one managed node/string/dictionary entry per observation. Publication is explicit: accepted-but-buffered records and failed block tails stay outside the committed count. Old readers keep their count and data after the writer closes and cannot read later observations. These internal synchronous components belong on admitted workers; their production I/O/projection connection is still unfinished.

## Typed indexed paths

The private codec stores a root ordinal and one reversible native name per path. UTF-8, invalid Unix bytes and UTF-16 code units (including unpaired surrogates) retain their exact evidence. It preserves nullable metadata flags, object/observed-identity references, all observed times and precision, and explicit metadata/policy state. Strict field bounds precede allocation. Wrong IDs, tags, raw-name extents, UTF-8, dates, truncated/trailing records and a false absent-raw-name flag are rejected. A base path record refuses nonempty issue references rather than dropping them; issue/object/fact/alias data requires separate indexes. No AnalysisEntry.Ancestry, runtime binding ID, traversal ticket or operation approval is encoded.

AnalysisIndexedPaths keeps the bounded root header and a dense path vector. It resolves a pending parent from its writer buffer or authenticated committed block without taking a reader lease. External readers still see only their captured prefix. Append requires the next ID, one active root record per binding, an earlier readable directory parent in the same root, and the depth bound. This is partial structural validation; sibling uniqueness and complete object/fact/issue relationships are not implemented by this path component. Arbitrary imported IDs still need an explicit bounded mapping; they are never silently renumbered here.

Published path headers retain acquisition/session, epoch, host-profile and timezone fields plus origin/privacy classification in runtime ownership. A captured revision cannot change acquisition fields, move backward, predate its committed observations, or refer to different records/timestamps under the same revision ID. Imported privacy joins preserve privileged and unverified bits. These headers and read-only records grant no source authority. Existing native backend ancestry remains process-owned and must be retained/requalified by a separate traversal integration; decoded rows cannot replace it.

Lineage reads reconstruct at most the declared depth and locator byte bound. A leaf remains readable when its whole path is too large; lineage fails explicitly instead of returning a truncated locator. Old readers retain count/data after writer closure and reject future IDs. The active production AnalysisStore and its managed snapshots remain unchanged; typed readers, exact source frontier/identity indexes, sibling/object/fact/issue validation, aggregation/scope/top-K/table/import/export and I/O/UI integration are still required.

A failed multi-table flush leaves the preceding entire publication readable rather than publishing a partial graph. Strict bounded object, storage-fact and issue codecs preserve exact UInt128 measurements, known zero and missing states, observation times and precision, owner/component/basis/include references and issue node/root state. A workspace shares its verified native directory across separately owned arenas. Data and temporary sorting runs reserve both a session budget and the parent process-wide budget before writes. ## Typed related-record graph

The internal graph writer now shares one raw publication for dense path/object/fact/issue tables. It retains the bounded session/epoch/profile/timezone, roots, policy and phase/coverage/freshness/origin/privacy header in runtime ownership. It preserves supplied base values and refuses supplied aliases/issue-code lists that are not represented by these APIs. Append validates earlier readable directory parents, roots, depths and observation times. No backend ancestry or action capability is restored from records.

Sealing freezes observation input, then builds exact full-key indexes for children, object IDs, object aliases, fact owners, fact IDs and issue owners. Streaming validation checks duplicate sibling/ID keys, object-reference existence and identity/state consistency, directory/fact ownership, observation intervals, bounded component inclusion graphs and node/root issue references. Object-reference checks use ordered merges instead of a dictionary for all objects. Per-owner component validation retains at most 256 bounded facts. A failed index build releases temporary outputs, preserves the caller's raw prefix and can retry only the same frozen header. A failed raw multi-table publication remains failed and cannot become a successful indexed revision.

Graph readers keep all related data/index lifetimes after writer, revision owner and workspace close. The whole-graph consumer ceiling is eight, independent of the number of component views, including reader retention after owner closure. Indexed aliases and related values are paged by exact ranges; base records do not materialize full alias or issue lists.

Sparse sorting now accepts explicit consumed-row byte costs. A skipped directory is a counted work step, so a directory-only alias source cannot run millions of hidden MoveNext iterations. A one-worker regression queues interactive work during skipped 64 KiB rows and verifies service after at most four such rows. Cancellation and invalid sparse inputs use the same admitted cleanup path.
